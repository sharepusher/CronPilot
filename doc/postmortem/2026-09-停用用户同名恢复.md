# 2026-09 停用用户同名覆盖启用（OPT-P0-22）复盘

**日期**：2026-09-09　**关联设计**：
[停用用户同名恢复设计.html](../design/停用用户同名恢复设计.html)（rev.3）　
**相关**：
[auth\_version Session 缺键 Fail-Open](2026-09-auth-version-session-failopen.html)

**一句话**：同名再申请被错误实现为「删除停用用户 + 新建」，破坏 `user_id` 连续性与历史日志；同时停用未可靠撤销 Web Session。OPT-P0-22 改为原行覆盖启用 + `auth_version` fail-closed，且申请人零同名提示。

## 1) Bug 定位

- `approve_registration()` / `create_user()` 历史路径：发现同名 `is_active=0` 时删除旧行再插入，导致 `user_id` 变化、组/审计引用孤儿风险。
- 审批 UI 文案「曾被停用 / 将被替换」暗示删建，且未说明日志继承。
- 停用仅清 Token，Session 内角色快照可继续使用（Session 撤销见独立复盘 B2）。

## 2) 根因

1. `rbac_users.username` UNIQUE 与「停用名可再申请」冲突时，工程上选了删行释放约束，而未保留身份主键。
2. 产品误把「同名再申请」等同「原使用人回来」，文案与删建实现互相强化。
3. Web 鉴权信任 Session 快照，停用未递增认证版本。

## 3) 测试漏洞

- 旧测试断言「旧用户被删除」为成功条件，锁死了错误策略。
- 缺少：ID 不变、组全量替换、失败回滚、申请人响应零提示、审计 `detail` 无凭据、Session 缺键失效。

## 4) 修复（B1–B5）

| 批次 | 内容 |
| --- | --- |
| B1 | `tests/test_user_reactivation.py` 锁定删行重建不可接受 |
| B2 | `auth_version` 缺键 fail-closed + 一次性 bump |
| B3 | `_overwrite_disabled_user_inplace`；标记列；审计 `detail`；§4.5 凭据分支 |
| B4 | §4.2 文案；「同名停用」标签；审批/管理员确认弹窗；`cp:form-confirm-reactivation` |
| B5 | §3.1.7 / 路线图 / RELEASE / 本复盘 / 门禁 |

## 5) 防护测试

```
python -m unittest tests.test_user_reactivation -v
# 覆盖：ID 稳定、组不继承、回滚、stale target、audit detail、文案门禁、Session 缺键
python -m unittest tests.test_redesign_sidebar -v
python scripts/smoke_routes.py --check
```

## 6) 同类排查

- `rg "db.session.delete" app/rbac/`：无删除 `RbacUser` 实体的生产路径（组关系 delete 除外）。
- `rg "曾被停用|将被替换|停用后不可恢复启用" app/templates/redesign/`：应为空。
- 直接启用路径仍拒绝：`set_user_active` / `update_user`。

## 7) 预防方案（可验证）

| # | 措施 | 落地位置 | 验证 |
| --- | --- | --- | --- |
| P1 | 单元门禁禁止生产路径 `db.session.delete(…user…)` | `tests/test_user_reactivation.py::test_service_never_deletes_disabled_user_row` | `python -m unittest tests.test_user_reactivation.TestDisabledUserOverwriteIdentity.test_service_never_deletes_disabled_user_row -v` |
| P2 | 审批/管理文案契约静态断言（申请人禁词 + 审批人必含覆盖/继承） | `TestApplicantSurfaceNoReactivationHints` · `TestApproverAdminCopyB4` | `python -m unittest tests.test_user_reactivation.TestApproverAdminCopyB4 -v` |
| P3 | 设计安全契约：Session/鉴权伪代码实施验收须对照；抢跑半成品以设计全文重审 | `AGENTS.md` · `.cursor/rules/cronpilot-project.mdc` | 见 B2 复盘；回归 `TestDisabledSessionRevocation` |

**结论**：同名停用以「覆盖启用 + 日志继承」为产品语义；工程上永不删行；Session 以 `auth_version` fail-closed。B1–B5 已闭合。

## 附录：B5 回归 — 侧边栏 HTTP 用例缺 auth\_version

| 要素 | 内容 |
| --- | --- |
| Bug 定位 | `tests/test_redesign_sidebar.py::_login_client` 注入 Session 未写 `auth_version`；B2 fail-closed 后 Viewer/Operator 反向路径变成 302 登录而非 403 |
| 根因 | HTTP 集成 Fixture 在引入缺键失效后未同步；仍假设「有 is\_login 即可鉴权」 |
| 测试漏洞 | 侧边栏用例未覆盖「缺键 → 踢登录」与「有键 → 走权限 403」的区分 |
| 修复 | `_login_client` 写入 `sess['auth_version'] = int(user.auth_version or 0)` |
| 防护 | `python -m unittest tests.test_redesign_sidebar -v` 须全绿 |
| 同类排查 | 凡 `session_transaction` + `is_login` 的 HTTP 用例均应带 `auth_version`（与 DB 对齐） |
| 预防 | 会话测试矩阵（缺键 / 不匹配 / bump）已在 AGENTS.md；新增登录态 HTTP Fixture 必须写入 auth\_version |
