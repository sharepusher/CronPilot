下次执行相对时间误显示 · 复盘

日期：2026-09-16 · 状态：已修复并验证

设计全文： 下次执行相对时间误显示修复设计-2026-09

问题： 只填「小时」、分钟留空的任务，调度器按 APScheduler 在第 0 分触发； 展示层把空分钟当成 *，「下次执行」被压成 in <1 min。
修复： 共享 next_fire_datetime / effective_crontab_5 / cron_fire_interval_seconds， 经 build_scheduler_kwargs + CronTrigger 与注册路径同源。

1. Bug 定位

dashboard_service.compute_next_runs / compute_overdue_map、main/views.py 详情 next、format_cron_expression 对空字段使用 or '*'，与 build_scheduler_kwargs 省略空字段（APScheduler 默认 minute=0）不一致。

2. 根因

注册路径与预测/展示路径对「空 cron 字段」语义分裂：省略→0 vs 空→*。相对时间格式化本身正确，错误来自错误的 next 时间点。行为层原因是缺少与调度器共享的「有效 Trigger」单一事实源。

3. 测试漏洞

既有 test_cron_schedule_display / overdue 用例未覆盖「只填 hour、minute 空」；无 next_run ↔ CronTrigger.get_next_fire_time 对照。

4. 修复

在 cron_schedule_display.py 新增同源 helper；Dashboard next/overdue、详情 next、format_cron_expression 全部改走 helper。未改注册语义与触发频率。

5. 防护测试

  • tests/test_dashboard_next_run.py：空 minute + hour=*/2 表达式以 0 */2 开头；next 不为 in <1 min；与 Trigger 同分钟；间隔 7200s；3h 前执行不误标逾期。
  • tests/test_cron_schedule_display.py::test_hour_only_shows_minute_zero_not_star

验证：.venv-py311/bin/python -m unittest tests.test_dashboard_next_run tests.test_cron_schedule_display tests.test_overdue_detection -v

6. 同类排查

已改：next_run、overdue、详情 next、format_cron_expression。humanize 本已按 0。API 原始空字符串字段不改。全 * 配置仍经 _schedule_configured 跳过。

7. 预防方案

下次触发 / 有效表达式 / 逾期间隔禁止再手写 minute or '*' 拼 crontab；必须经 app/services/cron_schedule_display.py 的 next_fire_datetime / effective_crontab_5 / cron_fire_interval_seconds。门禁由 tests/test_dashboard_next_run.py 锁定；第三方可复现命令见 §5。
