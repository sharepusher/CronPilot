# P2 触发 URL 签名与记录不一致复盘

**日期**：2026-09-11

## 1. Bug 定位

`app/crons.py` 以字符串拼接 GET 参数，并通过 `split('?')` 取签名输入。含 `#fragment` 的 URL 会被错误记录，也会使 fragment 混入最后一个签名参数。

## 2. 根因

签名、实际发送与持久化 URL 各自使用不同的字符串处理逻辑，没有把 URL 的 query 与 fragment 作为独立语义处理。

## 3. 测试漏洞

原测试只校验签名脱敏，不覆盖 fragment、query+fragment、空值及重复 key，无法比较 Requests 实际预处理 URL。

## 4. 修复

新增 URL 解析 helper：`urlsplit`/`parse_qsl` 生成签名参数；GET 使用 `requests.Request(...).prepare().url` 生成记录值；统一用 fragment-safe 脱敏 helper 写入成功与异常路径。POST 与 DNS pinning 不变。

## 5. 防护测试

`.venv-py311/bin/python -m unittest tests.test_lifecycle_logging tests.test_cronpilot_sign -v`：23 项通过，覆盖 fragment 排除、PreparedRequest URL、空值、重复 key、脱敏和原有签名稳定性。

## 6. 同类排查

POST 同样复用新的签名参数解析，消除了其 fragment 签名差异；未引入多值 query 新协议，保留既有 dict 的后者覆盖语义。

## 7. 预防方案

新增 `TestTriggerRequestUrlConstruction`，以 Requests PreparedRequest 作为 GET URL 的可执行基准；后续变更 URL 或签名逻辑必须扩展该测试，不得再以字符串拼接重建请求 URL。
