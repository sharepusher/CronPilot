任务生命周期与无删除

暂停 ≠ 下线；取消任务/日志人工删除；下线为不可逆终点，同类需求须新建

状态：已确认 · 随 v0.3.0 实施

关联：RBAC v4 · 架构设计 · 交付状态

一、问题与根因

项内容
问题任务/执行流水提供「删除」，易丢失审计与历史；「停止」与「结束」语义混淆
根因早期 CRUD 把删除当生命周期终点；模型已有 status=-1 结束态，但 Web 以物理删除为主
目标配置与流水可追溯；暂停可恢复；下线不可逆；同类需求新建任务

二、状态机（权威）

动作含义cron_infos.status可逆？
运行调度执行中1—
暂停临时停调度，配置保留0是（可再「运行」）
下线生命周期终点-1否（不可再启/再改；同类需求新建）
创建 → 运行 ⇄ 暂停
         ↘       ↙
          下线（终点）
不做：管理端/API 人工删除任务；管理端人工删除执行日志/流水；对已下线任务再启动或编辑「复活」。
保留：按 job_log_counts 的系统自动裁剪（容量策略，非用户删除功能）；one-shot 自然结束后写 status=-1。

三、方案要点

3.1 Web

  • 退役 /cron_del、/cron_batch_del、/job_log_delete、/job_batch_delete（返回 410）
  • 新增 /cron_retire?id=：写 status=-1 + remove_job；不删 cron_infos / job_log
  • 列表：运行中/已暂停显示「下线」；已下线仅展示状态，无启停/编辑/下线
  • 已下线禁止 update_status、cron_edit

3.2 API

  • /api/cron/status 仍仅 0|1（暂停/运行）
  • 新增 /api/cron/retire（按 task_name）
  • /api/cron upsert：若同名任务已 status=-1 → 拒绝，提示须新建（新 task_name）

3.3 RBAC

ROLE_PERMISSIONS = {
    'viewer':   {'cron:read', 'log:read'},
    'operator': {'cron:read', 'cron:write', 'log:read'},
    'admin':    {'cron:read', 'cron:write', 'cron:retire',
                 'log:read', 'user:manage', 'audit:read'},
}

cron:write = 添加/编辑/启停；cron:retire = 下线（仅 admin）。废弃 cron:delete、log:delete。

步骤内容

五、验收

  1. UI 无任务删除、无日志删除
  2. 旧删除 URL → 410
  3. 暂停 ⇄ 运行；下线后不可运行/编辑；列表显示已下线
  4. 下线后流水仍可查；同类需求走添加（新 task_name）
  5. rbac_enable=1：operator 可暂停不可下线；admin 可下线
  6. 自动日志裁剪仍可按配置工作
