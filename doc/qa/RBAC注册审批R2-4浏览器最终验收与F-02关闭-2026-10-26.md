# RBAC 注册审批 R2-4 浏览器最终验收与 F-02 关闭

版本：rev.1 · 日期：2026-10-26 · 状态：**验收通过，F-02 已关闭** · 设计：[R2-4 rev.2](../design/RBAC注册审批R2-4浏览器最终验收与F-02关闭方案-2026-10.html) · 父方案：[Scope 精确化 rev.20](../design/RBAC注册审批列表Scope精确化优化方案-2026-10.html)

**结论：**真实浏览器、真实 Cookie 与常驻开发服务下，五类角色矩阵、筛选分页、标题/侧边栏 badge 及旧 Session 降权全部符合数据库当前 Scope。R2-0–R2-4 完成定义成立，父 Review 的 F-02、F-04、F-05、F-06 已关闭。

## 1. 验收对象与方法

使用 `scripts/verify_registration_scope_browser.py` 幂等准备 `r2_r4_` 专用账号和申请，以本机 Chrome 逐角色完成登录和 DOM 精确断言；脚本随机生成密码且不输出，始终在 `finally` 清理用户、UserGroup、申请及申请—组关联。截图只包含虚构用户名和业务组，不含密码、Token 或真实邮箱。

## 4. 自动化脚本误报复盘

1. **Bug 定位：**首轮证据脚本把组 10 页面误判为包含组 1 申请。
2. **根因：**脚本在整页 HTML 上做子串搜索，`viewer_g1` 会命中 `viewer_g1_g10`。
3. **测试漏洞：**验证器没有强制读取表格用户名列并比较完整单元格。
4. **修复：**改为定位主数据行第二列，标准化文本后进行集合精确相等断言。
5. **防护测试：**组 1、组 10、多组同时含前缀相交用户名，任一子串误判都会导致矩阵失败。
6. **同类排查：**total、标题 badge、导航 badge 使用独立 DOM 节点精确文本；登录 Cookie 解码核对用户名与组集合。
7. **预防方案：**可重复脚本固定在 `scripts/verify_registration_scope_browser.py`，禁止以整页字符串包含作为授权集合证据；第三方可运行上述命令复现。

## 5. F-02 关闭判定

| 完成定义 | 证据 | 判定 |
| --- | --- | --- |
| 组号精确匹配与 admin 子集 | 组 1/10/多组矩阵及关联表 Repository 回归 | 通过 |
| 数据库当前 actor 与旧 Session 收敛 | 同 Cookie 全局→组 1 后立即只见组 1 | 通过 |
| 列表、total、分页、badge 同源 | 五角色矩阵、状态/搜索/第二页及 R2-3 HTTP 回归 | 通过 |
| 证据可持续与 fixture 零残留 | 脚本、PNG、JSON、SHA-256；清理计数 0/0/0 | 通过 |

**边界：**本批没有修改生产业务代码或 API 返回结构。MySQL 性能与双后端查询计划已在 R2-2E2/E3 独立验收，本批不重复制造容量结论；用户编辑 no-op/单事务仍属于独立 U0–U3 方案。
