### 2.1 行为层要点

- **身份**：同名停用用户改为原 `user_id` 覆盖启用；旧 Web Session 若无 `auth_version` 必须重登。这是正确的安全收紧，也是全量测试变红的直接原因。
- **调度安全**：DNS 解析失败默认拒绝触发；内网不稳可设 `url_ssrf_dns_fail_open=1`（该键已进入 `configs()`，不再是死键）。
- **可观测**：`cron.start` / `cron.http_sending` 等过程日志；`actual_url` 脱敏 `cronpilot_sign`；历史文案 `回调URL安全校验未通过` 仍由 `BLOCKED_URL_PREFIXES` 识别。
- **数据**：新任务/日志走 50-bit ID，旧小 ID 共存；下线任务不再进入异常提醒面板。
- **`one_shot`**：字段与文案已预留，`register_cron_job` 仍写入 `schedule`，不是功能缺失误报。

## 6. 兼容与运维注意

- 升级后**未写 auth\_version 的旧 Cookie 一律失效**，用户需重新登录。这是 OPT-P0-22 的预期，不是回归。
- 新任务/日志 ID 从约 12 位十进制起；API 调用方若写死「小整数 ID」需核对。
- 外网 DNS 抖动可能导致触发被拒；确认后再开 `url_ssrf_dns_fail_open`。
- 启动时须跑 `ensure_business_tables`，补 `job_log` 四列与 `auth_version` 等。

## 8. 建议顺序

1. 按已有设计扫完全仓 `session_transaction()` / `is_login` 夹具（`test_rbac_phase` 优先），保留缺键否定用例。
2. 再跑 `unittest discover`，目标失败数回到个位数（仅 SECRET\_KEY 环境与明确豁免）。
3. 用户确认 P2 设计后，提交 URL/签名规范化，并处理 `.query` 门禁误报。
4. `cronpilot.sh restart --daemon` 后用种子账号走登录 → 任务中心 → 立即执行 → 详情页，补本轮缺失的常驻进程验收。
