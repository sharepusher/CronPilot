复盘：标签管理增强 OPT-P1-11（2026-08）

本文档汇总 OPT-P1-11（任务创建页改进：单组归属 + 标签系统）整个开发周期中发现的所有问题及复盘。

Bug 1: RELEASE_NOTES 内容与实际设计不一致

#要素内容
1Bug 定位RELEASE_NOTES.md OPT-P1-11 部分描述了"多组可见性"、group_ids 列表 API、"标签合并"功能、"复选框多选"、"453 tests"——均与实际已更改的设计不符。
2根因设计漂移：设计从"多组可见性"改为"单组归属"后，RELEASE_NOTES 未同步更新。修改了代码和设计文档但遗漏了发布文档。
3测试漏洞无 CI 检查 RELEASE_NOTES 与代码/设计文档的一致性。
4修复全面重写 OPT-P1-11 章节：单组归属、group_id 单值 API、移除合并功能、单选下拉框、正确测试数（428）。
5防护测试python scripts/html_docs_to_markdown.py --check 验证文档同步。
6同类排查同步检查了其他 OPT 条目的 RELEASE_NOTES 描述，无类似漂移。
7预防方案新增规范（cronpilot-project.mdc）：设计变更后必须即时同步 RELEASE_NOTES；commit 前 git diff -- RELEASE_NOTES.md 检查。

Bug 2: rename_tag 错误消息引用已删除的"合并"功能

#要素内容
1Bug 定位app/services/tag_service.py — rename_tag 错误消息含"请使用合并功能"，但合并功能已被移除。
2根因删除 merge_tags 功能时，不完整影响分析——只删除了函数本体和路由，未搜索全仓库引用（包括错误消息和 docstring）。
3测试漏洞无测试覆盖错误消息内容的语义正确性。
4修复错误消息改为"同组内已存在同名标签「{}」"；docstring 移除"合并"描述。
5防护测试grep -rn '合并' app/services/tag_service.py（应无匹配）。
6同类排查全仓库 grep '合并.*标签\|merge.*tag'，确认无其他残留。
7预防方案新增规范（cronpilot-project.mdc）：删除功能时必须全仓库搜索（中文名 + 英文名 + 函数名），清除所有引用。

Bug 3: 标签输入空格触发后文本残留

#要素内容
1Bug 定位app/static/js/tag-input.js — 按空格键触发标签创建后，输入框内原文本未清除，导致视觉重复。
2根因浏览器对 keydown 事件中可打印字符的 e.preventDefault() 不完全生效——浏览器在事件循环下一 tick 仍可能将字符插入 input，覆盖已调用的 $input.val('')。
3测试漏洞CDP 键盘模拟直接操作 DOM 值，不经过浏览器完整 input 事件管道，无法复现真实用户键盘的异步字符插入。
4修复① 添加 e.key === ' ' 为触发键；② addTag(val) 后添加 setTimeout(function() { $input.val(''); }, 0) 延迟清除。
5防护测试CDP 验证基本逻辑正确 + 用户手动验证键盘交互。
6同类排查检查所有 keydown handler 中的可打印字符拦截，确认无类似模式。
7预防方案新增规范（cronpilot-backend.mdc）：① JS keydown 可打印字符拦截必须附 setTimeout(0) 清除；② CDP 验证局限性声明。

Bug 4: name="tags" hidden input 重名导致后端收到空字符串

#要素内容
1Bug 定位cron_add.html / cron_edit.html — 可见 input 和 hidden input 都使用 name="tags"，导致 FormData 序列化时可见 input 的空值覆盖了 hidden input 的实际值。
2根因inline chip 重构时，将可见 input 的 name 属性从 tags_input 误写为 tags，与负责同步值的 hidden input 同名。
3测试漏洞无 DOM 层级测试检查 name 属性唯一性。
4修复可见 input 移除 name 属性（它不需要被提交，仅用于输入交互）。
5防护测试浏览器 E2E：提交带标签的任务 → 后端正确接收标签列表。
6同类排查检查所有 tag-input 实例确认无同名冲突。
7预防方案新增规范（cronpilot-backend.mdc）：JS 动态 hidden input 命名冲突防护——禁止可见 input 和 hidden input 使用同一 name。

Bug 5: AJAX 响应字段名不匹配导致删除确认 Modal 不弹出

#要素内容
1Bug 定位app/templates/tag_manage.html JS 删除流程中使用 r.code / r.msg，而后端 web_api_return() 返回 r.errcode / r.errmsg。条件永远为 false，Modal 不弹出。
2根因编写新 JS AJAX 代码时未先确认项目统一的 API 响应格式（datas/utils/json.py），凭其他项目经验使用了不一致的字段名。
3测试漏洞无前端 AJAX 响应字段名的自动化检查。Ajax form guard 仅检查 DOM 结构。
4修复r.code → r.errcode，r.msg → r.errmsg。
5防护测试浏览器 E2E：点击删除 → CDP 验证 Modal display:block + 内容含任务数据。
6同类排查grep -rn 'r\.code\b\|r\.msg\b' app/templates/ 无其他匹配。
7预防方案新增规范（cronpilot-backend.mdc）：AJAX 响应字段名规范——强制使用 r.errcode / r.errmsg。AGENTS.md 同步。

Bug 6: CronInfos.is_active AttributeError 导致关联任务查询 500

#要素内容
1Bug 定位app/services/tag_service.py:270 — CronInfos.is_active 属性不存在。
2根因凭记忆假设 CronInfos 有 is_active 字段（rbac_users 表使用此名），未查阅 datas/model/cron_infos.py 确认实际字段名为 status。
3测试漏洞get_tag_tasks 为新函数，未编写单元测试即部署。"Import 可达性验证"规范未覆盖属性访问。
4修复CronInfos.is_active → CronInfos.status，JS 端 t.active → t.status。
5防护测试浏览器 E2E 验证 Modal 展示任务 ID + 名称 + 状态。
6同类排查delete_tag 中仅用 CronInfos.id 和 CronInfos.task_name，已验证正确。
7预防方案使用 ORM 模型属性前，必须 grep 字段名 datas/model/*.py 确认字段存在。扩展 Import 可达性规范覆盖属性访问。

Bug 7: INSERT OR IGNORE SQLite 专用语法未兼容 MySQL

#要素内容
1Bug 定位scripts/ensure_business_tables.py — _migrate_group_id_to_task_groups() 使用 INSERT OR IGNORE INTO。
2根因只在 SQLite 开发环境测试，忽略 MySQL 生产环境。INSERT OR IGNORE 是 SQLite 专用，MySQL 使用 INSERT IGNORE INTO。
3测试漏洞单元测试用 sqlite:///:memory:，无法暴露跨数据库语法差异。
4修复添加 business_db_backend() 判断，分别生成对应语法。
5防护测试迁移脚本为幂等操作，代码中已显式处理双后端。
6同类排查grep 'INSERT OR IGNORE\|INSERT IGNORE' scripts/ 确认无其他未处理实例。
7预防方案新增规范（cronpilot-project.mdc）：迁移脚本原生 SQL 必须同时写 SQLite 和 MySQL 两个分支。

Bug 8: API Breaking Change（group_ids → group_id）未标注

#要素内容
1Bug 定位app/api/views.py — cron_query/cron_detail 返回从 group_ids 列表改为 group_id 单值，RELEASE_NOTES 未标注。
2根因将多组模型纠正为单组时，心理上未将其视为 Breaking Change；缺少 API 契约测试。
3测试漏洞单元测试已更新断言但缺少 API schema 验证测试。
4修复RELEASE_NOTES 中明确标注 Breaking Change 及迁移指南。
5防护测试建议后续添加 API 响应 schema 断言测试。
6同类排查grep 'group_ids' 全仓库确认已全部替换。
7预防方案新增规范：API 返回结构变更必须在 RELEASE_NOTES 标注 Breaking Change。

Bug 9: 组名兜底使用空字符串而非语义值

#要素内容
1Bug 定位app/templates/_cron_list_rows.html — group_name_by_id.get(gid, '') 兜底为空字符串。
2根因沿用了 Python dict.get 的默认模式，未考虑前端显示时空字符串不可见、不可操作。
3测试漏洞无模板渲染断言测试覆盖兜底值。
4修复兜底值改为 '—'（em dash）。
5防护测试浏览器验证页面显示。
6同类排查检查所有模板 .get( 调用，修正同类空字符串兜底。
7预防方案新增规范：模板中 dict.get 兜底值必须使用语义值（如 '—'），禁止空字符串。

元复盘：Agent 反复遗漏自主复盘

#要素内容
1Bug 定位Agent 多次在修复问题后直接进入 AskQuestion 提示下一步，跳过复盘。
2根因① 将复盘视为"修复的附加步骤"而非"原子组成部分"；② AskQuestion 用户规则创造了"急于到达下一步"的锚点；③ 复盘触发条件被窄化为"用户报告的代码 bug"。
3测试漏洞无自动化机制检查回复中是否包含复盘。
4修复强化规范：AskQuestion 前置门禁——调用 AskQuestion 前必须自检是否需要复盘。
5防护测试规范中的"交付前自检"清单 4 步。
6同类排查回顾对话历史，至少 4 次被用户推回补充复盘。
7预防方案新增规范（cronpilot-project.mdc）：① AskQuestion 前置门禁；② 复盘质量门禁 4 项检查；③ 复盘文档化强制条款。
