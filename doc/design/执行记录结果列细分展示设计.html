执行记录结果列细分展示设计

状态：已确认 · 2026-08-27 · Redesign Execution Logs

1. 问题

执行记录（_exec_logs_rows.html）结果列将 fail（HTTP 4xx/5xx/关键词命中）和 error（请求前异常/连接异常）合并显示为同一个「失败」， 但筛选按钮区分了「仅失败」和「仅异常」，导致用户点击「仅异常」后看到的记录依然标注「失败」，语义混乱。

2. 根因

模板中 {% elif log.status in ('fail', 'error') %} 将两种不同状态合并处理，未利用 fail_reason 字段细分。

3. 方案

拆分 fail 和 error 状态，并利用 fail_reason 字段提供细分标签：

statusfail_reason实际数量显示文案颜色
success—17成功绿 --cp-success
failhttp_4xx908失败 · 4xx红 --cp-danger
failhttp_5xx0失败 · 5xx红
failkeyword254失败 · 关键词红
errorinternal17,897异常橙 --cp-warn
errorconnection183异常 · 连接橙
errorblocked_url0异常 · URL拦截橙
timeouttimeout3超时紫 --cp-state-timeout

4. 范围

文件变更
app/templates/redesign/_exec_logs_rows.htmlCOL 6 结果列拆分：fail/error 独立分支 + fail_reason 子标签
app/static/css/redesign-pages.css新增 .el-log-error 样式（橙色 --cp-warn），区别于 .el-log-fail（红色）

不做：v1 模板（无颜色编码结果列，仅文本展示）；后端状态值不变。

5. 分批

单批完成（CSS + 模板，约 20 行改动）。

6. 验收

  1. bash scripts/cronpilot.sh restart --daemon
  2. 登录后访问执行记录 → 切换「仅异常」筛选 → 结果列显示「异常」/「异常 · 连接」而非「失败」
  3. 切换「仅失败」→ 结果列显示「失败 · 4xx」/「失败 · 关键词」
  4. python scripts/smoke_routes.py --check 通过

7. 风险

  • fail_reason 可能为空（旧数据）→ 回退到仅显示主标签（「失败」/「异常」）
