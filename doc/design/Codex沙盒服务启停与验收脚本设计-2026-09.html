Codex 沙盒服务启停与验收脚本设计（2026-09）

状态：已实现（服务启动受当前沙箱端口策略阻断）　日期：2026-09-14

1. 问题

现有 scripts/stop_local.sh 通过 lsof + kill + kill -9 管理端口；Codex 沙盒可能禁止查看/终止非当前进程，导致旧 PID 清不掉。verify_install_flow.sh 无条件执行 pip install --upgrade 'pip<25'，无外网时失败。

2. 根因

脚本把“可管理所有端口进程”和“可访问 PyPI”当成前置条件，未区分脚本自有进程、外部占用进程和离线验收。

3. 方案

  1. 新增 scripts/cronpilot_codex.sh，命令固定为 start、stop、status、check。
  2. PID 文件固定为 datas/cronpilot-codex.pid；仅当 PID 文件存在且 /proc/<pid>/cmdline 可证明命令包含项目路径与虚拟环境 Python 时才发送 TERM。
  3. 端口探测使用 curl --max-time 2；端口有响应但 PID 不匹配时退出码 3，输出“外部进程占用”，绝不 kill。
  4. check 默认离线：断言 .venv-py311/bin/python、Flask/PyMySQL 可导入、/rbac/login 返回 200；--online 才执行 pip pin 检查。
  5. 扩展 verify_all.sh --codex，只执行单测、check 和自身进程的 start→HTTP→stop，不调用 verify_golden_path.sh 的强制清理。

4. 范围

新增脚本、tests/test_codex_runtime.py、verify_all.sh 参数分支及本设计文档；不修改生产启动、默认端口、业务鉴权和现有联网安装语义。

5. 分批

第一批实现 PID 自证与退出码；第二批实现离线依赖检查和测试；第三批接入验收入口、更新文档与 Release Notes。

6. 验收

  • start 成功：写入 PID，HTTP 健康检查 200，退出码 0；沙盒禁止 bind 时返回码 4 并标记 SKIP。
  • stop 自有 PID：进程退出并删除 PID 文件，退出码 0。
  • 外部占用端口：退出码 3，日志包含 PID/端口和人工处理命令，外部进程仍存活。
  • check 离线无 DNS 请求；联网 --online 保持 pip<25 校验。

7. 风险

沙盒禁止读取 /proc 时，脚本只能把 PID 视为不可验证并拒绝终止；这会牺牲自动清理换取不误杀。离线检查不能证明 PyPI 可安装，输出必须标记 offline。

实现与验证记录

已新增 scripts/cronpilot_codex.sh、tests/test_codex_runtime.py，并接入 verify_all.sh --codex。离线依赖检查、Shell 语法测试和 Codex 验收入口通过；当前沙箱启动 Flask 时返回 Operation not permitted，入口将该环境限制标记为 SKIP，HTTP 启停链路须在 Cursor/宿主终端复验。
