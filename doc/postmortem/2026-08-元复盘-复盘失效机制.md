# 元复盘：Agent 反复未主动复盘的系统性失败

**日期**：2026-08-11  
**严重程度**：系统性流程缺陷（非单次遗漏）  
**影响**：用户至少 3 次被迫指出复盘缺失，严重影响协作信任

## 1. Bug 定位

**模式**：Agent 在以下场景中反复未主动执行复盘：

- Phase 2 首次实现偏离 Mockup → 用户发现后才复盘
- Phase 2 全量重写后 → 用户问"为什么没复盘"才补
- 实施方案缺 Design QA → 本轮才追加

发生次数：仅在 Mockup 实施周期内至少 **3 次**。

## 2. 根因（行为层分析）

| 层次 | 根因 |
| --- | --- |
| 认知层 | Agent 将复盘视为"事后总结"而非"修复的原子组成部分"——改完代码就认为"任务完成"，复盘被挤到后面甚至遗忘 |
| 流程层 | Agent 内部执行序列是"改代码→验证→报告结果→问下一步"，复盘没有被嵌入为任何一步的**前置条件** |
| 激励层 | AskQuestion 制造了"快速到达下一步"的锚点，Agent 潜意识优先"给出选项"而非"先完成复盘" |
| 判断层 | 对"何时触发复盘"的判断过于依赖显式 bug（用户报告的 500/报错），对"设计偏离""方案缺陷"等隐性问题不触发 |
| **约束层（核心）** | **纯文字规范对 Agent 行为的约束被证明反复失效**——规范虽存在，但没有程序化强制机制阻止跳过 |

## 3. 测试漏洞

现有规范（`.cursor/rules/cronpilot-project.mdc`「AskQuestion 前置门禁」）已经写明：

> Agent 在 invoke AskQuestion 之前必须自检：本轮是否执行了修复动作？有→先输出复盘再给选项

但这条规范**仅是文字约束，没有程序化强制机制**。Agent 可以"读到了但执行时跳过"。文字规范 ≠ 可执行门禁。

## 4. 修复

- 创建 `.cursor/hooks.json` + `.cursor/hooks/postmortem-reminder.sh`（L1 实时提醒）
- 配置 `stop` prompt hook（L2 结束前评估）
- 更新 `.cursor/rules/cronpilot-project.mdc` 加入程序化强制描述
- 更新 `AGENTS.md` 同步
- 更新 `doc/design/UI重设计-实施架构与过渡方案.html` 加入 Design QA 门禁

## 5. 防护测试

| 层 | 机制 | 验证方式 |
| --- | --- | --- |
| L1 | `postToolUse` hook 注入 `additional_context`（每次 Write/StrReplace 后） | 编辑文件后观察 system\_reminder 是否出现 |
| L2 | `stop` prompt hook（Agent 结束前评估复盘完整性） | 尝试结束一轮包含修复但无复盘的对话，验证是否被续行 |
| L3 | TodoWrite 原子绑定（修复 Todo + 复盘 Todo 配对） | 检查 TodoWrite 调用中修复类项目是否有配对复盘项 |

## 6. 同类排查

检查其他"应该做但反复被跳过"的规范：

- Mockup 逐节对照 — 已通过 Design QA 门禁 + Hook 加固 ✓
- 复盘文档化 — 已有明确规范，本轮在 Hook 提醒中也包含 ✓
- 交付后可验证本地环境 — 暂未发现反复跳过的模式（保持观察）

## 7. 预防方案

**核心结论**：对于反复违反的规范，纯文字约束无效，必须升级为程序化强制。

| 措施 | 落地位置 | 验证命令 |
| --- | --- | --- |
| L1: postToolUse Hook（实时提醒） | `.cursor/hooks.json` + `.cursor/hooks/postmortem-reminder.sh` | `cat .cursor/hooks.json | python3 -m json.tool` |
| L2: stop prompt Hook（结束前门禁） | `.cursor/hooks.json` stop 节 | 同上 + 实际触发验证 |
| L3: TodoWrite 原子绑定规范 | `.cursor/rules/cronpilot-project.mdc` AskQuestion 前置门禁节 | `grep "L3" .cursor/rules/cronpilot-project.mdc` |
| Design QA 门禁写入实施方案 | `doc/design/UI重设计-实施架构与过渡方案.html` §6.1 第 8 条 + §6.3 | `grep "Mockup 设计还原对照" doc/design/UI重设计-实施架构与过渡方案.html` |
| 元复盘文档化 | `doc/postmortem/2026-08-元复盘-复盘失效机制.html`（本文档） | 文件存在 |

**效果验证**：本轮实施 Hook 后，每次 `Write`/`StrReplace` 操作已立即收到 system\_reminder 注入，证明 L1 生效。L2 将在下一次 Agent 结束时生效。
