## 2. 一致性与安全场景

- 切读后的 verify-only 启动对账、缺失/多余/孤儿关联拒启和零 DML 测试通过。
- 单条有效审批、批量全成功、批量部分失败、存储漂移失败、重复审批幂等均通过。
- 用户、用户组、申请状态在成功和失败路径保持一致；失败路径无错误副作用。
- 全局管理员、受限业务管理员、Viewer/Operator 的 Scope 正反路径及筛选、分页、badge 一致性通过。

## 3. 浏览器与真实运行态

## 4. 未关闭事项

- 如正式发布矩阵包含 MySQL 5.7，需在后续阶段补跑真实后端验证。
- 冒烟工具需独立设计修复调度器在测试应用配置覆盖前连接开发 SQLite 的隔离缺口；本轮使用环境开关隔离完成验收。
- 100k 为非阻断压力诊断，不影响当前 E3 结论。

## 5. E3 复盘

1. **定位：**需要证明关联表切读、审批一致性和 Scope 查询在全链路中没有旁路回退。
2. **根因风险：**单测可能遗漏启动迁移、批量审批、浏览器权限和真实路由链路。
3. **测试漏洞：**若只运行性能测试，无法发现审批状态、用户组和反向权限问题。
4. **修复：**按冻结矩阵执行专项、全量、路由、黄金路径和浏览器角色验证。
5. **防护测试：**固定 82 项 Scope/关联回归、99 项注册生命周期回归和 935 项全量回归。
6. **同类排查：**检查列表、count、badge、审批、启动对账和角色入口，未发现旁路 LIKE 或 Session 放行。
7. **预防：**将 E3 门禁命令与角色矩阵写入 QA 文档，后续 E4 必须引用本报告而不是仅引用单测结果。
