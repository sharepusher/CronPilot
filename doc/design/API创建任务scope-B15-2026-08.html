B-15 API 创建任务 Scope 赋值

状态：设计待确认
关联：API 安全与质量全面评估 §3.3 B-15
日期：2026-08-28

1. 问题

Web UI 创建/编辑任务时，_apply_scope_from_form() 强制执行 scope 规则：

  • 非 bypass 用户（operator）：必须选择自己所属业务组，scope 固定为 GROUP
  • bypass 用户（admin/seed）：可选 GLOBAL 或指定 GROUP

API 路径（POST /api/cron 和 /api/cron/add）无等效 scope 逻辑：

  • CronUpsertIn schema 无 scope_type / group_id 字段
  • upsert_cron_by_task_name() → create_cron() 默认 scope_type='GLOBAL'
  • 后果：拥有 operator token 的用户可通过 API 创建 GLOBAL 任务（Web 端不允许）

2. 根因

API 创建任务功能最初设计为「管理脚本使用全局 token」场景，未考虑用户 token（S-5/S-6 后新增）的 scope 语义。 当用户 token 开始支持 API 调用后，scope 赋值逻辑未从 Web 端移植到 API 端。

3. 方案

方案 A：API 强制 scope 赋值（推荐）

在 upsert_cron_by_task_name() 或调用方（crons() / crons_legacy()）中，根据 request._api_scope 自动赋值 scope：

Token 类型scope 行为
全局 token（role='admin'）接受可选 scope_type / group_id 参数；默认 GLOBAL
用户 token（role='user'，bypass） 同全局 token：接受可选参数，默认 GLOBAL
用户 token（role='user'，非 bypass）
  • 必须提供 group_id（或单组用户自动推断）
  • group_id 必须在 scope.group_ids 中
  • scope_type 强制为 GROUP（忽略用户传入的 GLOBAL）

方案 B：API 禁止非 bypass 创建（简单但限制大）

非 bypass 用户 token 不允许创建任务（仅允许更新已有的、scope 内的任务）。过于限制，不推荐。

推荐方案 A

与 Web 端行为对等，API 用户体验完整。

4. 范围

文件变更
app/api/views.pycrons() / crons_legacy() 新增 scope 赋值逻辑
app/api/schemas.pyCronUpsertIn 新增可选 scope_type、group_id 字段
tests/test_api_scope_s6.py新增 scope 赋值相关测试

不做：不修改 create_cron() / update_cron() 的 scope 处理逻辑（它们已正确接受 normalized dict）；不修改 Web 端。

5. 分批

  1. Batch 1：在 crons() / crons_legacy() 中新增 _apply_api_scope() 函数，根据 request._api_scope 向 form_data / datas 注入 scope 字段
  2. Batch 2：CronUpsertIn schema 新增 scope_type、group_id 可选字段

两批可合并为单次交付。

6. 验收

  1. 全局 token 创建任务：默认 GLOBAL ✓
  2. 全局 token 指定 group_id：创建 GROUP 任务 ✓
  3. operator token（单组）创建任务：自动推断 group_id，scope_type=GROUP ✓
  4. operator token（单组）传入不属于自己的 group_id：返回 403 ✓
  5. operator token 传入 scope_type=GLOBAL：强制为 GROUP ✓
  6. bash scripts/cronpilot.sh test 全量通过
  7. python scripts/smoke_routes.py --check 通过

7. 风险

  • 向后兼容：全局 token 行为不变（默认 GLOBAL）。用户 token（非 bypass）创建任务现在需要 group_id（或自动推断），这是期望的安全收紧
  • API Breaking Change：使用用户 token 创建任务的自动化脚本可能需要添加 group_id 参数

8. 实现细节

8.1 _apply_api_scope() 函数

def _apply_api_scope(datas):
    """根据 API scope 向 datas 注入 scope_type / group_id。
    
    全局/bypass token：接受可选 scope_type/group_id，默认 GLOBAL。
    非 bypass 用户 token：强制 GROUP + 校验 group_id。
    返回 error_msg 或 None。
    """
    scope = getattr(request, '_api_scope', None) or {'role': 'admin'}
    if scope.get('role') == 'admin':
        # 全局 token：接受用户传入或默认 GLOBAL
        if 'scope_type' not in datas:
            datas['scope_type'] = 'GLOBAL'
        return None
    
    from app.rbac.policy import user_bypasses_scope
    user_role = scope.get('user_role', '')
    username = scope.get('username', '')
    group_ids = scope.get('group_ids', [])
    
    if user_bypasses_scope(user_role, username=username, group_ids=group_ids):
        if 'scope_type' not in datas:
            datas['scope_type'] = 'GLOBAL'
        return None
    
    # 非 bypass：强制 GROUP
    raw_gid = datas.get('group_id', '')
    if not raw_gid:
        if len(group_ids) == 1:
            raw_gid = str(group_ids[0])
        else:
            return '请指定 group_id（当前用户属于多个业务组）'
    
    try:
        gid = int(raw_gid)
    except (TypeError, ValueError):
        return 'group_id 无效'
    
    if gid not in set(int(x) for x in group_ids):
        return '只能在本人所属业务组内创建任务'
    
    datas['scope_type'] = 'GROUP'
    datas['group_id'] = gid
    return None
