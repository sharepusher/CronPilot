# CronPilot V1（Legacy UI）下线方案

**日期**：2026-08-26  |  **编号**：OPT-P1-16 Phase Final  |  **状态**：设计评审中

## 1. 问题陈述

CronPilot 当前运行 **双轨 UI 系统**：V1（Legacy Simpleboot + Bootstrap 3）和 V2（Redesign 自研架构）。
双轨通过 Cookie `cp_ui_version` 或配置项 `CRONPILOT_FORCE_NEW_UI=1` 切换。

### 1.1 双轨代价量化

V1 模板文件

36 个

V1 模板行数

4,249

V1 专属 JS

1,918 行

V1 专属 CSS

~1,070 行

Views 中分支代码

35 处

可删除静态资源

10 文件

### 1.2 维护痛点

- **双倍测试成本**：每个功能需验证 V1 和 V2 两条路径
- **代码膨胀**：views.py 中 35 处 `getattr(g, 'ui_version', 'v1') == 'v2'` 三元表达式
- **依赖锁定**：V1 依赖 Bootstrap 3 + Simpleboot + artDialog + ajaxForm + wind.js 等不再维护的库
- **安全负债**：V1 模板中硬编码颜色、inline style 不受 CI 门禁监管（CI 仅覆盖 `redesign/` 目录）
- **认知负荷**：新贡献者需理解两套模板系统的关系

## 3. 下线方案

### 3.1 策略选择

| 方案 | 描述 | 推荐 |
| --- | --- | --- |
| **A. 硬切** | 直接删除 V1，`FORCE_NEW_UI=1` 为默认 | ✓ 推荐 |
| B. 过渡期 | 保留 V1 代码 1 个版本周期，通过 deprecation warning 引导 | 适用于外部用户多的项目 |
| C. 渐进式 | 按页面逐个下线 V1（先 Dashboard → 最后 Login） | 复杂度高，不推荐 |

**推荐方案 A** 的理由：CronPilot 为内部工具型项目，用户群可控；V2 已稳定运行；无第三方 API 兼容性顾虑。

### 3.2 分批执行计划

| 批次 | 内容 | 影响 | 可回滚 |
| --- | --- | --- | --- |
| **Batch 1** Default V2 | 1. `ui_mode.py`：默认值 `v1` → `v2` 2. `app/__init__.py`：移除 `CRONPILOT_FORCE_NEW_UI` 判断 3. 更新 README/部署文档，说明 V2 为唯一 UI | 所有用户默认看到 V2；V1 代码仍保留可通过 Cookie 切回 | ✓ 设置 Cookie `cp_ui_version=v1` 即可回退 |
| **Batch 2** 删除分支逻辑 | 1. views.py：消除 35 处 `ui_version` 三元分支，直接使用 V2 模板路径 2. 删除 `app/ui_mode.py` 中的 `ui_version` 相关代码 3. 删除 `app/__init__.py` 中的 `_set_ui_version()` 4. 删除 `_VALID_UI_VERSIONS` 常量 | Views 层精简约 100 行；不可再通过 Cookie 切回 V1 | ✗ 不可回滚（需 git revert） |
| **Batch 3** 删除 V1 模板 | 1. 删除 `app/templates/*.html`（除 `index.html`）— 17 文件 2. 删除 `app/templates/rbac/*.html` — 18 文件 3. 删除 `app/templates/admin_base.html` 4. 共 36 个模板文件，约 4,249 行 | 模板目录清爽，仅保留 `redesign/` | ✗ git revert |
| **Batch 4** 删除 V1 静态资源 | 1. 删除 `app/static/js/common.js` (1,082 行) 2. 删除 `app/static/js/wind.js` (836 行) 3. 删除 `app/static/js/ajaxForm.js` 4. 删除 `app/static/js/bootstrap.min.js` 5. 删除 `app/static/js/md5.js` 6. 删除 `app/static/js/requests.js` 7. 删除 `app/static/js/signs.js` 8. 删除 `app/static/js/tag-input.js` 9. 删除 `app/static/css/bootstrap.min.css` 10. 删除 `app/static/css/console-mode.css` (1,066 行) 11. 删除 `app/static/js/simpleboot/` 目录 12. 删除 `app/static/js/artDialog/` 目录 | 减少约 3,000+ 行 JS + 若干第三方库 | ✗ git revert |
| **Batch 5** 清理残余引用 | 1. 全局搜索残余 `admin_base`、`simpleboot`、`artDialog` 引用 2. 更新 `tests/test_ajax_form_guard.py`（如有 V1 模板相关用例） 3. 更新 CI 门禁范围（`check_ui_contract.py` 可移除 V1 排除规则） 4. 清理 `console-theme.css` 中仅 V1 使用的变量（如 `--cp-topbar-*`） 5. 模板目录重组：`redesign/` → `templates/`（可选，见 3.4） | 最终清洁状态 | ✗ git revert |

### 3.3 影响量化（预期收益）

删除文件数

~50

删除代码行

~9,000+

views.py 净减行数

~100

消除三元分支

35 处

### 3.4 模板目录重组（可选，Batch 5 之后）

**可选决策**：下线 V1 后，`app/templates/redesign/` 中的文件成为唯一模板。
是否将它们移到 `app/templates/` 根目录？

| 方案 | 优点 | 缺点 |
| --- | --- | --- |
| 保持 `redesign/` 子目录 | 零改动；git history 连续 | 路径略长；"redesign" 名称过时 |
| 移到根 `templates/` | 路径简洁；语义清晰 | 需改 35+ 处 `render_template` 路径；git blame 断裂 |
| 重命名为 `templates/views/` | 语义中性 | 同上 + 额外重命名工作 |

**建议**：保持 `redesign/` 子目录。名称可在下一个 major version 时统一重命名（通过 git mv + 全局替换），当前改动的 ROI 过低。

## 4. 风险评估

| 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- |
| V2 存在未发现的功能缺失 | 低 | 中 | Batch 1 先默认 V2 但保留回退能力 |
| 外部集成依赖 V1 特定 DOM 结构 | 极低 | 低 | 无外部浏览器自动化集成 |
| 删除后发现测试依赖 V1 模板 | 低 | 低 | Batch 2 前全量运行测试 |
| 用户习惯 V1 界面不适应 | 低 | 低 | Batch 1 阶段提供回退 Cookie 说明 |

## 5. 验收标准

| 批次 | 验收条件 |
| --- | --- |
| Batch 1 | 无 Cookie 时默认加载 V2；`cronpilot.sh test` 全绿；浏览器登录→操作→登出正常 |
| Batch 2 | views.py 无 `ui_version` 引用；测试全绿；设置 `cp_ui_version=v1` Cookie 不再生效 |
| Batch 3 | `ls app/templates/*.html` 仅剩 `index.html`（如有）；`app/templates/rbac/` 目录已删除；测试全绿 |
| Batch 4 | `ls app/static/js/` 仅包含 redesign 模块 + jquery；测试全绿；浏览器无 404 |
| Batch 5 | `grep -r "admin_base\|simpleboot\|artDialog\|wind\.js" app/` 返回空；CI 全绿 |

## 6. 不做清单

- **不删除 `jquery.js`** — V2 仍依赖 jQuery（`common-redesign.js`）
- **不删除 `console-theme.css`** — V2 的 Design Token 来源
- **不重命名 `redesign/` 目录**（见 3.4 分析）
- **不改变 URL 路由** — 所有用户可见 URL 不变
- **不影响 API 层** — `app/api/views.py` 无 UI 版本分支

## 7. 时间线建议

| 阶段 | 建议时间点 | 说明 |
| --- | --- | --- |
| Batch 1（默认 V2） | 立即可执行 | 风险最低，可回滚 |
| Batch 2-5（完全下线） | Batch 1 稳定运行 1-2 周后 | 确认无功能缺失再执行不可逆操作 |
| 或一次性全做 | 立即 | 如果对 V2 功能完备性有信心 |
