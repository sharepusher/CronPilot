# 文档同步说明（Linux 安装 / venv / Docker）

部分历史文档（`README.md`、`doc/index.md`、`非Docker部署指南.*` 等）曾属 **root** 属主，需在本机执行一次合并。

## 为何会出现「pending 里 README 比根目录旧」？

| 环节 | 问题 |
|------|------|
| `sync_all_docs.py` | 无法写 root 属主文件时，把**当时脚本生成的全文**落到 `doc/_pending_sync/<原路径>` |
| 主文档继续演进 | 根目录 `README.md` 等在 Git 中正常更新，**pending 副本不会自动同步** |
| 旧版 `apply_pending_docs.sh` | 曾 `find` 整个目录并无差别 `cp` 回仓库，**会用陈旧副本覆盖新版** |
| 误提交 | 若将 pending 下的 `README.md` 纳入 Git，会长期保留过期快照 |

**现行防护（2026-06 起）：**

1. `pending_apply.manifest`：仅登记因 PermissionError 产生的待合并路径。
2. `apply_pending_docs.sh`：只处理 manifest；若**主文件比副本新**则跳过并删除陈旧副本。
3. 目录说明使用 **`doc/_pending_sync/INDEX.md`**（勿用 `README.md` 作目录说明——该路径留给根 `README.md` 的 pending 副本）。
4. `.gitignore` 忽略 `doc/_pending_sync/*` 临时副本，仅跟踪 `INDEX.md` 与 `已合并补丁记录.md`（见仓库 `.gitignore`）。
5. 删除 `doc/_pending_sync/` 下任何文件前，须在 [已合并补丁记录.md](_pending_sync/已合并补丁记录.md) 写明**完整路径**与**删除原因**。

## 一键同步

```bash
cd /path/to/CronPilot
python3 scripts/sync_all_docs.py
sudo bash scripts/apply_pending_docs.sh   # 仅当存在 pending_apply.manifest 时
```

## 仍可能出现在 `doc/_pending_sync/` 的文件

`sync_all_docs.py` 在无法写入 root 属主文件时，会把**完整副本**写入此目录，并登记到 **`pending_apply.manifest`**。合并：

```bash
sudo bash scripts/apply_pending_docs.sh
```

- 仅 manifest 中的路径会被覆盖到主文档；主文件较新时自动跳过。
- 合并后已应用的副本与 manifest 条目会删除；**不会**删除 `INDEX.md` 与 `已合并补丁记录.md`。
- **勿**手动把根目录 `README.md` 复制到本目录长期存放。

再运行：

```bash
bash scripts/check_pending_sync.sh
python3 scripts/html_docs_to_markdown.py --check
```
