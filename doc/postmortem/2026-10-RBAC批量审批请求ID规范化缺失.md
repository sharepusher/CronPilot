# RBAC 批量审批请求 ID 规范化缺失复盘

日期：2026-10-27 · 状态：已修复并验证 · 关联：[修复设计 v1.1](../design/RBAC批量审批请求ID规范化修复方案-2026-10.html)

## 1. Bug 定位

`app/rbac/views.py` 的 `registration_batch_approve()` 与 `registration_batch_reject()` 将 CSV 内每个数字 token 直接加入列表。`ids=12,12` 会对同一申请调用两次：首项成功，第二项因已处理失败，造成错误的 partial-failure 汇总；`ids=12,abc` 则静默忽略 `abc`。

## 2. 根因

输入解析同时承担了容错清洗和业务授权前置校验，却没有建立“完整、唯一的请求集合”这一边界条件。服务层的幂等性仅阻止第二次状态写入，无法校正批量层已偏离调用方意图的摘要。

## 3. 测试漏洞

既有批量测试只覆盖不同 ID 的全成功、部分失败和全失败，默认调用方传入唯一有效 ID；没有覆盖重复、空 token 或混合非法 token，更没有断言参数失败发生在任何业务服务调用之前。

## 4. 修复

新增共享 `_parse_batch_request_ids()`：仅接受经 trim 后的 ASCII 正十进制 ID，拒绝空 token、非数字、零和重复值。两个批量入口均在进入逐项审批循环前调用它；任一不合规则返回既有 JSON 错误信封且不写入申请记录。

## 5. 防护测试

在 `tests/test_rbac_global_scope_assignment.py` 新增三条 HTTP 测试：批准重复 ID 零写入、批准混合非法 token 零写入、拒绝重复 ID 零写入。三条均断言 `errcode=1` 与申请仍为 `pending`。

## 6. 同类排查

通过/拒绝两条批量路由均已改为调用同一解析函数；单项审批只接受单个 `id`，不消费 CSV，本问题不适用。页面前端由复选框生成唯一 ID，未修改其逻辑。

## 7. 预防方案

将“批量 ID 必须在首个写入前完成完整性与唯一性校验”固化为共享函数，避免两条入口再次分叉；第三方可运行 `.venv-py311/bin/python -m unittest tests.test_rbac_global_scope_assignment.TestRegistrationApprovalScopeClosure.test_batch_approve_duplicate_ids_are_rejected_before_any_write tests.test_rbac_global_scope_assignment.TestRegistrationApprovalScopeClosure.test_batch_approve_invalid_token_is_rejected_before_any_write tests.test_rbac_global_scope_assignment.TestRegistrationApprovalScopeClosure.test_batch_reject_duplicate_ids_are_rejected_before_any_write -v` 验证该约束。

## 验证结果

- 新增三条专项 HTTP 测试：通过。
- `.venv-py311/bin/ruff check app/ tests/test_rbac_global_scope_assignment.py`：通过。
- `.venv-py311/bin/python scripts/smoke_routes.py --check`：86 / 86 通过。
