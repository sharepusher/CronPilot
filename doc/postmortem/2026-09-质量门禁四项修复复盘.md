# 复盘：质量门禁四项修复（2026-09-04）

范围：测试稳定性 + 验收脚本 + 文档完整性 + CSS 静态门禁准确性

## 1) Bug 定位

- `tests/test_rbac_scope.py`：`TestScopeIntegration` 单跑时登录链路触发 `rbac_registration_requests` 查询，报表不存在。
- `scripts/smoke_http.sh`：`docs_rfc` 校验固定访问 `/docs/依赖升级RFC.html` 返回 404。
- `scripts/check_css_token_reachability.py`：注释中的 `animation:` 文本被误识别为真实样式，报 undefined keyframe。
- `doc/postmortem/index.html`：缺同名 `doc/postmortem/index.md`，触发 completeness 失败。

## 2) 根因

- 测试初始化只覆盖了部分模型导入，导致对登录路径的依赖表未建全，出现顺序依赖。
- 文档目录迁移到 `doc/deps/` 后，脚本中的硬编码 URL 没有同步更新。
- reachability 检测直接按行正则扫描，未先剥离 CSS 注释。
- postmortem 索引页被当成“特例”遗漏了 MD 配对，流程未做索引页专项检查。

## 3) 测试漏洞

- 此前主要看全量 `cronpilot.sh test` 结果，未强制执行“关键套件单独运行”。
- golden path 失败曾被误判为环境问题，缺少对失败断言本身的真伪复核。
- CSS reachability 缺少“注释干扰”的反例样本。
- postmortem completeness 之前未纳入每轮回归必跑清单。

## 4) 修复

- `tests/test_rbac_scope.py`：补导入 `RbacRegistrationRequest`，确保 `create_all()` 建表完整。
- `scripts/smoke_http.sh`：`docs_rfc` URL 改为 `/docs/deps/依赖升级RFC.html`。
- `scripts/check_css_token_reachability.py`：新增注释剥离函数，保留行号后再做 token/keyframe 解析。
- 新增 `doc/postmortem/index.md`，补齐 HTML/MD 对照。

## 5) 防护测试

- `.venv-py311/bin/python -m unittest tests.test_rbac_scope.TestScopeIntegration -v` 通过。
- `bash scripts/verify_golden_path.sh` 通过（含 `PASS docs_rfc (200)`）。
- `.venv-py311/bin/python scripts/check_css_token_reachability.py --check` 通过。
- `.venv-py311/bin/python scripts/check_postmortem_completeness.py --check` 通过。

## 6) 同类排查

- 复跑全量门禁清单（lint/UI/文档/版本/OPT/smoke/unit/golden），本轮均通过。
- 验证 `doc/design` 新文档已在 `doc/index.html` 与 `doc/index.md` 注册，避免新增文档漏登记。
- 确认 `smoke\_routes.py` 的文档路由冒烟通过，无额外 404 回归。

## 7) 预防方案

- 在评估类任务中固化“先单跑关键套件，再跑全量”流程：`tests.test_rbac_scope.TestScopeIntegration` 必须单跑（落地位置：本复盘 + 设计文档验收清单）。
- 将 `check_postmortem_completeness.py --check` 纳入本地标准回归序列，与 `check_doc_completeness.py --check` 同级执行（落地位置：本复盘 + 本轮设计文档第 6 节验收命令）。
- 对静态解析脚本新增注释剥离基线规则（落地位置：`scripts/check_css_token_reachability.py`），防止同类误报反复出现。
