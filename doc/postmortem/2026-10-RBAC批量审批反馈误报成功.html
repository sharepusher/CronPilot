RBAC 批量审批反馈误报成功修复复盘

日期：2026-10-16（2026-10-19 B3 收口） · 对应设计：B0–B3 方案 · 状态：已完成

一句话：后端已逐项识别失败，但批量路由在汇总时固定返回 errcode=0 与跳转 URL，使部分/全失败在协议层被伪装为成功。

1. Bug 定位

registration_batch_approve() 和 registration_batch_reject() 收集 ok_count/fail_msgs 后无条件调用 web_api_return(code=0, url=...)。B0 在旧实现上用 6 条红线稳定复现：4 条证明失败仍 code=0，2 条证明成功响应缺结构化摘要。

2. 根因

行为层根因是“人类可读文案”代替了“机器可判定结果”：实现者把失败数写进 errmsg 便认为已反馈，却没有同步修改成功码、导航权与结构化数据。通过/拒绝两条路由复制了同一汇总模式，因而问题成对出现。

3. 测试漏洞

原测试重点是数据库授权不越界，未同时断言 errcode、url、结果摘要和逐项 DB 状态之间的不变量；也没有覆盖原始异常脱敏与日志关联号。

4. 修复

新增共享结果组装函数，统一 all_success / partial_failure / all_failure 三态；仅全成功返回 code=0 和 URL。失败项返回 ID 和受控文案。系统异常在服务层或路由边界生成 trace_id，原文与 traceback 仅写服务端日志。

5. 防护测试

TestRegistrationApprovalScopeClosure 覆盖通过/拒绝的三态和数量不变量；新增异常测试确认响应不含敏感原文且同一 trace_id 存在于日志。TestApproveRejectRegistration 直接注入 commit 异常，证明服务层的关联链真实可查。

6. 同类排查

本轮同时修复批量通过和批量拒绝，并保留单条路由契约。全仓异常原文输出由既有“异常信息脱敏”门禁持续覆盖；B2 将独立处理前端对三态摘要的消费。

7. 预防方案

可落地措施 1：在 tests/test_rbac_global_scope_assignment.py 固定 total = success_count + failure_count、failure_count = len(failures) 和“任一失败无 URL”契约。

可落地措施 2：在 tests/test_registration.py 固定“原始异常只在日志，同 trace_id 可查”，防止后续只加通用文案却丢失运维可观测性。

验证：.venv-py311/bin/python -m unittest tests.test_rbac_global_scope_assignment.TestRegistrationApprovalScopeClosure tests.test_registration.TestApproveRejectRegistration -v

8. 最新验收证据

2026-10-16：定向 22/22，相关回归 123/123，Import smoke 9/9，路由冒烟 86/86；Ruff、文档完整性、链接、HTML/Markdown 同步通过。本地服务登录页 HTTP 200，无写入的不存在 ID 冒烟返回 all_failure 且无跳转 URL。

9. B2 实施中的 jQuery 兼容性修复

B2 首次浏览器验收发现批量请求进入网络失败分支。定位到项目固定使用 jQuery 1.8，而新实现写成 $.ajax({method: 'POST'})；jQuery 1.8 忽略该新版配置后默认发出 GET，路由因仅允许 POST 返回 405。修复为兼容语法 type: 'POST'，并在 tests/test_registration.py 增加“必须 type，禁止 method”渲染契约。根因是实施时按现代 jQuery API 习惯编写，未先读取本仓库 jQuery 实际版本；预防措施的落地位置是上述静态契约测试与真实浏览器 POST 验收。

10. B3 最终验收

2026-10-19：注册、授权边界、会话撤销、CSRF、四角色侧边栏与表单守卫扩展回归 163/163 通过，路由冒烟 86/86，verify_all.sh --local-only 为 4 通过、0 失败；沙箱禁止端口绑定导致黄金路径按脚本规则跳过，但运行服务的真实登录 GET=200、POST=302，审批页=200。浏览器以受限 Biz Admin 验证全部成功、部分成功、全部失败和系统异常：导航权、结果条、逐项原因、32 位 trace_id、焦点恢复与数据库状态均符合设计，控制台 0 错误；临时用户、申请、审计记录和故障注入 trigger 清理后均为 0 残留。该证据关闭父 Review F-01；审批列表 Scope 精确性 F-02 仍是独立问题。
