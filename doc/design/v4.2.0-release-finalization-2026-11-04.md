## 2. 根因与状态解释

当前处于发布准备期：业务修复和专项验证已完成，但版本文案归档及最终候选检查尚未收口。4.1.1/published 是上一发行状态，不能只改为 4.2.0/published 就视为发布完成。用户决定手动提交及操作 Release；自动发布 job 的仓库上下文问题暂不处理，不作为此次手动发布阻断。

## 3. 方案

1. 整理 Unreleased：按最终实现去重，核对 API Breaking Change、升级迁移、旧编辑页刷新、缓存及调度一致性边界，形成专业英文 4.2.0 说明；历史测试计数保留其运行上下文，不拼成虚假的最新全量结果。
2. 同步根 Release Notes、doc/RELEASE\_NOTES.html 及生成 Markdown、README、路线图和版本总览。候选阶段明确“待发布”，不把未来版本放入已发布事实；不更改历史发布日。发布日期由实际手动发布时确定。
3. 版本归档提交后，以确切候选 commit 跑全量 discovery、文档/术语/图片/版本/Ruff 门禁和关键路由；记录通过、失败、跳过及环境限制。仅在新变更或失败要求时补跑已经完成的双后端与浏览器专项。
4. 以实际候选 commit 构建自定义发布包两次，校验可重复性、哈希和构建报告；执行独立资产检查、仓库外解压安装、启动、登录和黄金路径。隔离 DB/端口及调度器，不操作开发库中的真实任务，也不自动启动 Docker daemon。
5. 验收全通过后将结构化清单置为 4.2.0/ready，保留准确的未解决风险；冻结最终提交并复核发布包来源。清单或文案变化使候选 commit 改变时，按影响重新构建并校验，避免产物指向旧提交。
6. 交付手动发布所需的 tar.gz、sha256、build.json、英文 Release notes 及确切 commit。用户自行创建标签、上传发布附件并确认发布；Agent 不推送、不创建标签或 Release。发布完成后再记录实际日期和 published 状态。

## 4. 范围

版本归档文档、结构化清单和验证证据；不新增产品行为、不修改业务代码或自动发布工作流。不默认修复验收发现的新产品问题，新发现须定位后按设计流程处理。当前已有标签触发发布工作流的配置保持；手动推送标签可能触发它，失败不改变手动发布操作的可用性。

## 5. 分批

1. F0：文案和版本入口审查，形成待发布候选改动。
2. F1：用户提交候选后，冻结 SHA 并执行全量门禁；失败则停止进入 ready。
3. F2：以确切 SHA 做隔离安装及确定性打包演练。
4. F3：记录验收、冻结最终 SHA 与对应产物，交用户手动发布；发布事实事后更新。

## 6. 验收

版本及文档一致性、术语、图片治理、迁移映射、Ruff、全量单测与关键路由通过；跳过项明确说明。RELEASE\_NOTES 中新增 API Header 已标注；业务与兼容性描述与当前代码一致。包内不含凭据、数据库、虚拟环境、QA 截图；两次构建相同；校验报告 source\_commit 与冻结 SHA 一致；新建环境启动、POST 登录、核心页面和隔离黄金路径通过。正式发布前状态只能为待发布或 ready，不假报 published。

## 7. 风险及控制

- 版本文档声称已发布：候选和发布事实分开标记，实际日期以后续操作为准。
- 验证对象漂移：所有验收记录输入 SHA，代码或打包内容变更后重新评估受影响验证，不沿用旧产物。
- 大量历史说明误合并：逐条按最终实现梳理，延期事项保留真实边界，人工发布方式不取消业务门禁。
- 验证影响真实调度：专用库、暂停调度、独立端口；不重启共享数据容器。
- 自动发布触发失败：按用户决定记录为暂不处理；本方案不借此更改仓库自动化策略。

## 交付阻滞复盘（7 项）

1. **定位：**先前给用户的发布命令把 set -euo pipefail 放在交互式顶层；脏工作区的 test 返回 1 后退出终端，会话保存又报 HISTTIMEFORMAT 未定义。本地 Git 提交另被两份 root 所有的 reflog 阻止。
2. **根因：**将脚本执行环境直接套到交互式 Shell，并在交付发布命令前未代办候选收尾；提交前仅验证 diff，没有检查日志可写性。严格选项影响调用者，底层权限使所有正确的提交命令仍失败。
3. **测试漏洞：**原检查只做 bash -n，验证了语法，没有验证失败时父 Shell 的存活与选项；工作区验收未包含一次真实提交结果。
4. **修复：**检查和归档由 Agent 完成并提交；发布命令严格模式全部放进子 Shell。Git 两份日志通过同目录原子替换恢复当前用户所有权，逐字节比对并保留原内容；不删除 reflog、不改历史提交。
5. **防护验证：**`bash -c 'before=$-; (set -euo pipefail; false); test "$-" = "$before"; printf "PARENT_SHELL_ALIVE_OPTIONS_UNCHANGED\n"'` 退出 0 并输出 PARENT\_SHELL\_ALIVE\_OPTIONS\_UNCHANGED。Git 提交 73854ac 成功；两份 reflog 替换前后内容一致且 owner=501。
6. **同类排查：**本轮发布评估文档的所有完整严格模式命令改为子 Shell；使用精确附件清单，不使用目录通配上传。ready 与 published、当前工作区与已提交打包来源分别核验。
7. **预防方案：**在本设计此节及发布评估文档的命令交付步骤新增“bash -n + 父 Shell 失败隔离探针 + 真实 Git 提交后清洁状态检查”三个可重现验收项；探针命令见上，语法检查对评估文档 pre 块执行 bash -n，最终执行 git status --porcelain 和 build.json.source\_commit 对齐 HEAD。该措施直接覆盖原先遗漏的调用环境和提交结果。

本轮未改业务代码，不新增截图；未重跑真实 MySQL、Docker 或 Python 3.8–3.10。复盘引用已同步到本版本 Release Notes。
