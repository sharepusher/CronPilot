# 侧边栏菜单文案优化 — 操作记录与审计重命名

**日期**：2026-08-27   **状态**：待确认

---

## 1. 问题

系统管理区域的两个日志类菜单 **「操作记录」** 与 **「审计」** 命名过于笼统，用户难以仅凭侧边栏文案区分二者内容：

- 「操作记录」— 字面上可包含任何操作，未体现其覆盖范围仅限*任务配置变更*（创建/编辑/启停/下线）
- 「审计」— 太抽象，不清楚审计的对象是安全事件（登录/权限拒绝）还是业务变更

## 2. 根因

两个功能在 v1 时期独立开发，命名各自选择了通用词汇（「操作」「审计」），缺少从全局导航角度的差异化设计。随着 Redesign 将二者放入同一「系统管理」分组，模糊性被放大。

## 3. 方案

| 位置 | 旧文案 | 新文案 | 说明 |
| --- | --- | --- | --- |
| 侧边栏菜单 | 操作记录 | **变更记录** | 突出"任务配置变更"语义 |
| 侧边栏菜单 | 审计 | **访问审计** | 突出"登录/权限/访问"安全维度 |
| 操作记录页标题 | 操作记录 | **变更记录** | 与菜单对齐 |
| 审计页标题 | 审计日志 | **访问审计** | 与菜单对齐 |
| 页面副标题 | （保持不变） | （保持不变） | 副标题已足够详细，无需改动 |
| 页面交叉引用 | "RBAC 审计" | **"访问审计"** | 变更记录页中指向审计页的链接文案 |
| 空态提示 | "暂无操作记录" | **"暂无变更记录"** | \_oplog\_rows.html / operation\_log\_list.html |
| 空态提示 | "暂无审计记录" | **"暂无访问审计记录"** | \_audit\_logs\_rows.html / rbac/audit\_logs.html |
| 角色提示 | "看操作记录…RBAC审计" | **"看变更记录…访问审计"** | user\_form.html / users\_add.html |

**不改动**：

- 路由 URL（`/operation_log_list`、`/audit_logs`）— 内部标识，不影响用户认知
- 权限字符串（`operation:read`、`audit:read`）— 后端逻辑标识
- Python 函数名 / 数据库字段 — 无用户可见影响
- 页面副标题 — 已有详细解释，无需重复改动

## 4. 范围

### 4.1 Redesign (v2) 模板

| 文件 | 改动点 |
| --- | --- |
| `app/templates/redesign/_sidebar.html` | 菜单项文案 + title 属性（2 处） |
| `app/templates/redesign/audit_logs.html` | block title + h1 标题 |
| `app/templates/redesign/operation_log.html` | block title + h1 标题 + 交叉引用链接文案 |
| `app/templates/redesign/_oplog_rows.html` | 空态 "暂无操作记录" → "暂无变更记录" |
| `app/templates/redesign/_audit_logs_rows.html` | 空态 "暂无审计记录" → "暂无访问审计记录" |
| `app/templates/redesign/user_form.html` | 角色提示文案 |

### 4.2 v1 模板（保持一致）

| 文件 | 改动点 |
| --- | --- |
| `app/templates/rbac/_sidebar_console.html` | "操作记录" → "变更记录"，"审计" → "访问审计" |
| `app/templates/rbac/_nav.html` | 同上 |
| `app/templates/rbac/audit_logs.html` | 交叉引用 "操作记录" → "变更记录" + 空态提示 |
| `app/templates/operation_log_list.html` | 交叉引用 + 空态提示 |
| `app/templates/rbac/users_add.html` | 角色提示文案 |

### 4.3 Python 注释（保持一致）

| 文件 | 改动点 |
| --- | --- |
| `app/rbac/policy.py` | 角色注释中 "操作记录" → "变更记录"，"RBAC 审计" → "访问审计" |

## 5. 分批

本次改动为纯文案替换，无逻辑/样式变更，不涉及数据库。**一批完成**，所有文件同步修改，避免中间状态文案不一致。

## 6. 验收

1. `bash scripts/cronpilot.sh restart --daemon` — 重启服务
2. 浏览器访问侧边栏 → 确认菜单文案为「变更记录」「访问审计」
3. 访问变更记录页（`/operation_log_list`）→ 页面标题为「变更记录」，交叉引用指向「访问审计」
4. 访问访问审计页（`/rbac/audit_logs`）→ 页面标题为「访问审计」
5. v1 页面导航同步验证（`?v=1` 或直接访问 v1 路径）
6. `python -m unittest tests.test_redesign_sidebar -v` — 侧边栏权限回归
7. `python scripts/smoke_routes.py --check` — 路由冒烟
8. `grep -rn "操作记录\|RBAC 审计\|RBAC审计" app/templates/ app/rbac/policy.py` — 确认无残留旧文案（仅允许在纯历史语境注释中出现）

## 7. 风险

- **低**：纯文案替换，无逻辑变更，无数据库影响
- **回归面**：侧边栏权限测试中可能硬编码了旧文案字符串 → 实现时需检查测试代码是否需同步更新
- **用户习惯**：已有用户可能短暂不适应新名称，副标题保持不变可降低过渡成本
