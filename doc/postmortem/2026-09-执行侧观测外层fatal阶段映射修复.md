# 执行侧观测外层 fatal 阶段映射 · 复盘

日期：2026-09-18 · 状态：**已修复并验证（F6）**

关联评估：[执行侧观测近期提交专业 Review 评估](../design/执行侧观测近期提交专业Review评估-2026-09-18.html)

**问题：**`cron_do()` 外层 fatal except 只写 `fail_reason`，依赖默认值把已经创建运行记录、甚至请求调用后的异常标成 `pre_request`/`not_started`，造成排障阶段误导。

**结果：**新增边界感知的 fatal 映射：尚未创建运行记录为 `pre_request/not_started`，已创建记录但未开始调用为 `persistence/prepared`，请求调用已开始则复用传输异常分类。

## 1. Bug 定位

问题位于 `app/crons.py` 外层 `except Exception` 的 `_save_job_log()` 调用；原调用没有传入 `failure_stage`、`transport_state`、`response_received`。

## 2. 根因

`_save_job_log()` 的默认策略适合普通前置失败，但外层 fatal 捕获跨越了任务创建、参数准备、HTTP 调用和持久化多个边界。异常处理器没有携带“是否已有运行记录”和“是否已开始请求调用”的上下文，因而所有路径共享同一组默认值。

## 3. 测试漏洞

既有测试覆盖了异常原因，却没有直接测试 outer fatal 的三种边界，也没有断言写入的 `failure_stage` 与 `transport_state`。因此默认值错误长期未暴露。

## 4. 修复

- `app/services/job_log_outcome.py` 新增 `fatal_failure_info()`，根据运行边界返回非对称阶段映射。
- `app/crons.py` 在 `cron_do()` 入口初始化 `_request_call_started`，outer fatal 保存时传入完整失败契约。
- 请求已开始的 fatal 复用现有 `exception_failure_info()`；已创建记录但未开始调用的异常标记为持久化阶段，避免声称请求已发送。

## 5. 防护测试

- `tests/test_job_log_outcome.py::test_outer_fatal_stage_depends_on_execution_boundary`：覆盖 pre-request、persistence、transport 三条路径。
- `.venv-py311/bin/python -m unittest tests.test_job_log_outcome tests.test_run_inspector_presenter tests.test_execution_observability_contract tests.test_execution_tracer -q`（40 条通过）
- `.venv-py311/bin/ruff check app/` 与 `.venv-py311/bin/python scripts/smoke_routes.py --check`（86/86）

## 6. 同类排查

已检索 `_save_job_log()` 的所有调用点：正常 URL 拦截/缺失路径仍使用前置默认语义；HTTP 异常路径使用显式传输状态；outer fatal 现在使用边界感知映射。未改变任务业务结果、通知或权限语义。

## 7. 预防方案

所有跨越多个执行阶段的 catch-all 异常处理器必须显式传入阶段和传输状态，禁止依赖 `_save_job_log()` 默认值表达复杂上下文。新增异常边界时必须补充“记录是否已创建/请求是否已开始/是否收到响应”三维否定用例；门禁位置为 `tests/test_job_log_outcome.py`。
