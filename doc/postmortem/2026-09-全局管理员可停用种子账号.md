# 2026-09 全局管理员可停用种子账号复盘

日期：2026-09-09 · 关联：OPT-P2-15 补丁 · 产品确认：维持旧设计（全局 admin 可编辑种子），但**不可停用**种子

## 1) Bug 定位

`app/rbac/views.py` 的 `_check_management_scope()` 在 `_actor_bypasses_scope()` 为真时直接放行；全局业务管理员（空 `group_ids`）因此可调用 `/rbac/users/set_active` 成功停用种子 `username=admin`。证据：探测 POST 返回 `errcode=0 / 已停用用户「admin」`。

## 2) 根因

种子保护写在「非 bypass」分支里，把「Scope 绕过」错误等同于「可对种子做全部管理动作」。OPT-P2-15 原文允许全局 admin 编辑种子，但未把「停用种子」单独列为永久禁止；服务层 `set_user_active` / `update_user` 也没有按用户名硬拦截。

## 3) 测试漏洞

已有用例覆盖「按组管理员不可操作种子」「不可停用自己」「不可停用最后一名 admin」，但**没有**「全局 bypass admin 停用种子」反向用例，导致缺口长期绿测。

## 4) 修复

- 服务层：`set_user_active` / `update_user(is_active=0)` 对 `is_seed_admin_username` 一律拒绝，文案「系统管理员账号不可停用」。
- 视图层：`users_set_active` 在 scope 检查前拦截种子停用。
- UI：用户列表对种子隐藏停用按钮；编辑页状态改为只读「启用（系统管理员不可停用）」。
- 设计：更新 `doc/design/管理员admin-Scope差异化设计.html` 停用矩阵行。

## 5) 防护测试

`tests/test_rbac_phase.py::TestRbacUsersManage.test_cannot_disable_seed_admin_via_set_active_or_edit`：全局 admin 对种子的 set\_active / edit(is\_active=0) 均失败；列表无停用按钮；编辑页只读文案存在；库中种子仍 `is_active=1`。

## 6) 同类排查

- API 无用户启停端点（无同源洞）。
- 按组管理员路径本已由 `_check_management_scope` 拦截，仍受益于服务层硬拦。
- 重置密码 / 重置 Token / 编辑资料：按产品确认仍允许全局 admin（本轮不改）。

## 7) 预防方案

**措施**：在 `.cursor/rules/rbac.mdc` 增加硬规则——种子 `admin` 不可被任何主体停用；服务层必须在 `set_user_active` / `update_user` 双路径拦截；新增回归测试名固定。

**验证**：

```
python -m unittest tests.test_rbac_phase.TestRbacUsersManage.test_cannot_disable_seed_admin_via_set_active_or_edit -v
grep -n "系统管理员账号不可停用" app/rbac/services.py app/rbac/views.py
```
