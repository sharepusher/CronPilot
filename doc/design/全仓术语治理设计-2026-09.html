全仓术语治理设计（callback/回调→触发语义）

状态：已完成；Batch A/B 为问答过程同步，Batch C/D 已执行并验证 · 日期：2026-09-07

1. 问题

当前仓库中存在“callback / 回调”与“触发请求”混用。CronPilot 的执行模型是平台主动向业务 URL 发起 HTTP 请求，属于“触发请求”语义。混用会带来三类问题：

  • 对外文档与用户文案误导：让读者误以为平台存在被动回调协议。
  • 代码命名与日志不一致：同一行为被不同词汇描述，增加维护成本。
  • 规则门禁缺失：后续提交容易再次引入旧术语。

2. 根因

  • 历史术语惯性：早期文档和实现沿用“回调”说法。
  • 跨层无统一词表：代码、文档、规则各自演进，缺少统一治理机制。
  • CI 缺少术语门禁：只能靠人工 review 发现，稳定性差。

3. 方案

采用“分批治理 + 规则固化”方案。治理对象是 CronPilot 的业务执行语义，不是禁止所有技术语境中的 callback。统一目标词汇如下：

旧术语统一术语说明
业务语境中的 callbacktrigger request指调度器主动向业务 URL 发起请求
业务语境中的回调触发请求 / 触发统一用户可见、日志和业务代码表述
回调 URL触发 URL仅针对任务目标地址的用户可见字段

关键原则：不修改业务行为，仅调整命名与文案；第三方 vendor/dist 代码不改。异步库 API 中的 callback、历史文档中的技术引用和原始事实不做机械替换。

4. 范围

4.1 范围内

  • 代码命名：函数名、变量名、注释、日志文案、指标 help。
  • 用户文案：模板文案、错误提示、接口描述文本。
  • 活跃文档：当前版本的架构、设计、手册、README 和发布说明；历史复盘与归档文档仅在业务语义明显误导时修订。
  • 规则/门禁：`AGENTS.md`、`.cursor/rules/*.mdc`、新增术语检查脚本与 CI 命令。

4.2 明确不做

  • 不改第三方文件：`app/static/js/jquery.js`、`app/static/dist/*`、虚拟环境目录。
  • 不做与术语无关的重构、格式化和逻辑优化。
  • 不新增功能，不改变 HTTP/API 行为契约；validate_callback_url 是内部函数命名，当前仓库无业务 callback 依赖，允许直接改为 validate_trigger_url。
  • 不改异步库或第三方技术 API 中合法的 callback 语义。

7. 风险与回滚

  • 风险 1：误替换技术语义（例如 JS/Python 回调函数语境）导致表达变差。
    缓解：门禁按业务语境匹配，并维护明确的技术语境 allowlist。
  • 风险 2：大范围替换引入非目标 diff。
    缓解：仅改目标目录，逐批 `git diff` 审核。
  • 风险 3：文档与代码术语短时不一致。
    缓解：按批次顺序执行并在同轮完成同步检查。
