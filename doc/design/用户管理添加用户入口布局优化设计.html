用户管理「添加用户」入口布局优化设计

状态：已确认并实施　日期：2026-09-09　归属：OPT-P1-16 Redesign 用户管理子项　变更类型：低风险 UI 信息架构调整

结论：将「+ 添加用户」从页面标题栏最右端移入用户列表工具区，并置于搜索框之前。标题区只保留“用户管理 + 成员数”；主操作、搜索和筛选在同一任务上下文内从左到右排列。该方案与现有“业务组”“标签管理”页面的左侧工具栏模式一致，不改变权限、URL、表单或后端行为。

1. 问题

当前 users.html 把标题、成员数和「+ 添加用户」共同放入 .page-head；共享样式使用 justify-content: space-between，因此按钮被推到内容区最右上角。用户的主要视线和操作集中在左侧的搜索、状态筛选与表格，新增入口与其作用对象之间出现过大的视觉距离。

专业维度当前表现影响
空间邻近性新增入口属于列表操作，却远离列表工具区用户需要在标题与表格之间横向扫视
操作分组主操作独占标题栏，搜索/筛选位于下一层同一对象的操作被拆成两个视觉组
全站一致性业务组、标签管理的创建入口均在左侧工具栏管理页之间形成不必要的肌肉记忆差异
窄屏稳定性标题与按钮争夺同一横行空间按钮易贴边或与标题产生不自然换行

2. 根因

  1. 复用了通用标题栏“两端对齐”能力，却没有区分页面级动作和列表级动作。
  2. 页面后续增加搜索、状态 Chip 和提示语后，没有重新收敛操作层级。
  3. 缺少管理类列表页面的统一约定：标题负责识别，工具栏承载创建/搜索/筛选。

3. 方案

3.1 推荐布局

  1. 标题区：仅保留“用户管理”和“共 N 名成员”，不放操作按钮。
  2. 第一操作行：左起依次为「+ 添加用户」、搜索输入框、「搜索」、「清除」（有搜索词时）。新增按钮与搜索之间保留明确间距或轻量分隔。
  3. 第二筛选行：保留“全部 / 启用 / 停用”状态 Chip，不混入创建按钮，避免主操作与筛选状态竞争。
  4. 说明行：继续位于表格前，保持策略提示与数据列表邻近。

信息层级：页面身份（标题） → 对列表执行动作（新增/搜索） → 缩小结果集（状态筛选） → 阅读与行级操作（表格）。这是比“标题两端塞动作”更稳定的管理后台结构。

3.2 交互与响应式契约

场景设计要求
桌面宽屏新增按钮紧邻搜索区左侧；工具区整体左对齐，不再跨越整页宽度。
中等宽度工具区允许自然换行；按钮保持完整文字和最小点击尺寸。
手机/窄屏新增按钮独占第一行或保持首位，搜索表单在下一行占满可用宽度；不得产生水平滚动。
键盘Tab 顺序为：添加用户 → 搜索框 → 搜索 → 清除 → 状态筛选，符合视觉顺序。
权限仅沿用当前服务端可见性/路由权限；本设计不新增前端权限判断。

3.3 方案对比

候选方案评估结论
A. 标题右侧（现状）常见但与当前页面操作密度和用户反馈不匹配不采用
B. 标题文字后紧跟按钮距离缩短，但标题与动作仍混层；窄屏标题行不稳定备选
C. 列表工具区左首位邻近作用对象，与业务组/标签页面一致，响应式自然推荐
D. 表格右上角悬浮/吸顶高频新增时有价值，但当前业务不需要持续占屏，复杂度偏高不采用

5. 范围

5.1 包含

  • app/templates/redesign/users.html：移动现有链接的 DOM 位置，不复制第二个入口。
  • app/static/css/redesign-pages.css：仅在 .cp-page-users 范围内补充工具栏布局和窄屏规则。
  • 用户管理页面的桌面、窄屏、键盘顺序与权限可见性回归。

5.2 不包含

  • 不修改 users_add 路由、URL、权限、CSRF、表单字段或提交流程。
  • 不改造搜索/筛选 AJAX 逻辑，不把状态 Chip 合并进表单。
  • 不修改其他页面的通用 .page-head，避免产生全站回归。
  • 不与“停用用户同名恢复”的业务交互混为一项；两者仅共享添加用户入口页面。

6. 分批

  1. B1 · 结构：移动唯一的添加用户链接到 .um-toolbar 首位，保持 href 与按钮类不变。
  2. B2 · 页面专属样式：在 redesign-pages.css 的 Users 区块增加桌面间距、换行和窄屏规则。
  3. B3 · 验证：静态契约、权限回归、浏览器桌面/窄屏截图与点击跳转验证。

7. 验收标准

  1. 页面标题行右侧不再出现「添加用户」，按钮位于搜索框之前。
  2. 页面中「添加用户」入口恰好一个，链接仍指向现有添加用户路由。
  3. 1440px 桌面视口下，按钮、搜索和状态筛选形成连续的左侧视觉动线。
  4. 768px 与 390px 视口下无水平滚动、遮挡或文字截断；搜索输入可用。
  5. 键盘焦点顺序与视觉顺序一致，按钮保留可见焦点态。
  6. Seed Admin / Biz Admin 的入口可见性保持现状；Operator / Viewer 不获得新增权限。
  7. python scripts/check_ui_contract.py --check、python scripts/audit_hardcoded_colors.py --check、python -m unittest tests.test_redesign_sidebar -v 通过。
  8. 浏览器完成“进入用户管理 → 点击添加用户 → 到达添加用户页”的正向验证，并验证无权限角色反向路径。

8. 风险与回滚

风险等级控制
按钮移入表单导致误提交低链接必须位于搜索 form 外部；实施后检查 DOM 和点击路径。
AJAX 选择器受结构变化影响低保留 .um-search 与内部字段不变；仅移动相邻链接。
窄屏换行拥挤低页面专属媒体查询 + 390px 浏览器验收。
与同名恢复确认交互并行开发冲突中布局改动只触及入口位置；合并时读回完整工具栏和表单边界。

回滚：将同一个链接移回 .page-head 并删除 Users 页面专属布局规则即可；不涉及数据、接口和迁移。
