# P1 测试夹具认证契约漂移复盘

**日期**：2026-09-11　**范围**：OPT-P0-22 Web Session fail-closed 回归

## 1. Bug 定位

`tests/test_cron_run_now.py` 的 RBAC 列表页 Session 缺少真实用户、`user_id`、`auth_version`；`tests/test_job_log_detail_integration.py` 在 `create_all()` 后才动态导入注册申请模型。结果为 3 个失败、2 个错误。

## 2. 根因

认证版本成为 Session 契约后，手工 fixture 仍沿用旧的“用户名+角色即登录”模型；最小应用测试也未把登录路径会查询的模型纳入建表注册。

## 3. 测试漏洞

已有缺键 fail-closed 专项测试覆盖安全拒绝，却没有让 Dashboard 和运行详情 fixture 以新 Session schema 通过 before-request gate；集成测试没有覆盖登录预检查所需完整模型集合。

## 4. 修复

列表页测试创建启用的 admin/viewer，并将提交后的原始 ID、版本、角色、用户名写入 Session，避免离开应用上下文后访问失效 ORM 实例；运行详情测试在 `create_all()` 前导入 `RbacRegistrationRequest`。未修改生产鉴权。

## 5. 防护测试

`.venv-py311/bin/python -m unittest tests.test_job_log_detail_integration tests.test_cron_run_now tests.test_user_reactivation.TestDisabledSessionRevocation tests.test_user_reactivation.TestAuthVersionOneTimeBump -v`：21 项通过，涵盖正常路径、缺键拒绝、错配撤销与一次性 bump。

## 6. 同类排查

本轮范围内所有 RBAC 列表页手工 Session 已收束到共享 `_login()` helper；首个不注册 rbac Blueprint 的接口测试不经过该 gate，保持原夹具。未修改 P2 URL/签名逻辑。

## 7. 预防方案

在 `doc/design/测试Session补齐auth-version修复设计.html` 固化真实用户+匹配版本的 fixture 契约和验收命令；后续新增 Web 测试的手工 Session 必须复用同类 helper 或显式声明缺键否定语义。通过上述 21 项命令可由第三方复验。
