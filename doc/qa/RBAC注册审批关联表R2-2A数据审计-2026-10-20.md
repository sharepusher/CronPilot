# RBAC 注册审批关联表 R2-2A 数据审计

日期：2026-10-20 · 状态：完成 · 性质：只读，无模型/Schema/业务数据变更

## 1. 目的

在建表和回填前验证现有 `rbac_registration_requests.group_ids` 的实际数据形态，确认设计分类能够覆盖全部存量。

## 2. 审计结果

| 分类 | 申请数 | 预计关联行 |
| --- | --- | --- |
| 有效具体组 | 11 | 15 |
| 合法 admin + `__ALL__` | 5 | 0 |
| 可规范化空白/重复 | 0 | 0 |
| 空/非法/混合全局/悬空组 | 0 | 0 |
| 父表总计 | 16 | 15 |

具体分布：`1`×7、`1,2`×1、`1,2,3`×1、`3,4`×1、`9`×1、`__ALL__`×5。资源组 1–10 均存在；全部 `__ALL__` 记录角色均为 admin。

## 3. 守恒与零写入证据

- 16 = 11 个具体组申请 + 5 个全局申请 + 0 个非法申请。
- 预计关联行 15 = 9 个组 1 关系 + 2 个组 2 + 2 个组 3 + 1 个组 4 + 1 个组 9。
- 审计命令仅包含 `.schema` 和 `SELECT`；独立连接返回 `total_changes=0`。
- 尚不存在 `rbac_registration_request_groups` 表；未执行建表、回填或状态修改。

## 4. R2-2B 输入结论

现有本地数据全部落在设计已覆盖的合法分类中，可以按“具体组全量回填、`__ALL__` 零关联”的规则进入 Schema 与回填设计。真实 MySQL 存量库仍必须在 R2-2B 独立执行同一只读审计，不能用本地 SQLite 结论代替。
