# RBAC 注册审批拒绝 Scope 授权方案专业评估

日期：2026-10-27 · 评估对象：[独立方案 rev.1](../design/RBAC注册审批拒绝Scope授权闭环方案-2026-10.html) · 结论：**专业通过，可在用户确认后实施**

**总体判断：**方案准确区分了“批准的赋权边界”与“拒绝的审阅边界”，将对象授权下沉到服务层，且没有因处理异常数据而给 scoped admin 增加治理能力。架构、事务、安全和兼容性均无阻断问题。

## 评估维度

| 维度 | 结论 | 依据 |
| --- | --- | --- |
| 专业性 | 通过 | 显式 actor、DB-current、行锁、服务边界、审计与最小信息反馈符合对象级授权常规。 |
| 准确性 | 通过 | 与当前代码事实一致：批准已校验 Scope，拒绝未校验；Repository 已定义 viewer/operator 交集与 admin 子集的列表语义。 |
| 合理性 | 通过 | 不直接复用批准校验，避免把“是否能授予”误用为“是否能审阅终止”；同时将异常申请限定给 bypass actor。 |
| 安全性 | 通过 | 越权请求不写入、授权查询错误 fail-closed、范围外响应不泄露对象详情、批量逐项复用同一防线。 |
| 可测试性 | 通过 | 矩阵覆盖单条/批量、正常/全局/漂移、正向/反向、状态/reviewer/comment 不变量及浏览器 CSRF 路径。 |
| 兼容性 | 通过 | 不改变批准、列表 SQL、RBAC 角色或公开 API；管理端仍使用既有 partial-failure 响应语义。 |

## 关键校验

- 全局管理员可清理异常申请是必要治理能力，不是 fail-open：条件被限制为数据库 bypass actor。
- scoped admin 的 viewer/operator 交集规则与列表一致；admin 的完整子集规则防止越权处理管理员申请。
- 服务签名显式传 actor，消除后台调用、测试调用和路由调用对隐式 Session 的耦合。
- 批量不会因一个越权 ID 回滚已合法处理的项，但也不会产生成功跳转或错误写入。

## 实施前唯一确认项

需由用户确认冻结的产品规则：scoped admin 对 viewer/operator 申请按精确交集拥有拒绝权，对 admin 申请要求完整非空子集；异常/漂移申请仅可由 seed/global admin 拒绝。确认后即可实施，不需要额外技术决策。
