# RBAC 注册审批列表 R2-2 专业评估

日期：2026-10-20 · 评估对象：Scope 精确化方案 rev.5 的 R2-2 · 结论：**A-（方向准确，须完成 DEC 后方可实施）**

**评估边界：**本评估依据当前模型、Repository、View、分页组件及 R2 红线测试；不授权实现。R2-1 已完成，R2-2 只处理资源 Scope 精确谓词及列表/count/page 同源。

## 1. 结论摘要

R2-2 要解决的不是普通字符串检索，而是一个读取授权谓词：viewer/operator 采用“精确交集”，admin 采用“非空完整子集”，`__ALL__` 仅允许数据库当前 global actor 查看，非法值对 scoped actor fail-closed。该业务语义准确，且必须在分页前进入权威查询，否则行、total、pages 与 badge 必然可能不一致。

**当前不足：**方案正确识别了必须先做双后端 DEC，但尚未选定可执行数据结构/查询算法、MySQL 最低版本、性能数据集和历史脏数据处置。因此不能把 rev.5 的 R2-2 直接解释为“改一下 LIKE 就能实施”。

## 2. 代码事实与问题准确性

| 事实 | 专业判断 |
| --- | --- |
| `group_ids` 是最长 255 的非空 CSV 字符串。 | 它不是关系型集合；子串 LIKE 无法表达 token 相等或集合包含。 |
| Repository 使用 `LIKE '%gid%'` 构造交集。 | 组 1 会误命中组 10，RL-01 的问题判断准确。 |
| admin 完整子集在 View 中对已分页 items 做 Python 过滤。 | 过滤发生在 count/limit/offset 之后，导致空洞页、total/pages 偏大，RL-04/RL-10 判断准确。 |
| pending badge 另建相似 LIKE 查询。 | 授权谓词复制后容易漂移；要求列表/count 同源是必要的。 |
| 注册入口通常写入规范整数 CSV 或 `__ALL__`。 | 新数据较规范，但历史数据、手工写入和迁移遗留不能据此默认合法；读取侧仍须 fail-closed。 |

## 3. 业务谓词准确性

### 3.1 viewer/operator：精确交集

只要申请组与 actor 当前组存在至少一个相同 token 即可见。这与审批时“可授予自身范围内的普通角色”一致，RL-03 的正向基线可以防止误改成完整子集。

### 3.2 admin：非空完整子集

admin 申请可能授予后续管理能力，因此申请中的每个组都必须属于 actor 当前组；只命中一个组不够。此规则与写入侧 `validate_user_scope_assignment()` 的子集策略一致，读写边界逻辑统一，专业上合理。

### 3.3 全局与非法数据

`__ALL__` 代表独立的全局授权状态，不能当普通 token；仅 global actor 可见。空串、非整数、混合 `__ALL__`、重复或非规范 token 对 scoped actor 应 fail-closed，同时记录数据质量指标，避免“解析失败即放行”。

## 4. 三种实现方向评估

| 方向 | 优点 | 主要风险 | 结论 |
| --- | --- | --- | --- |
| 方言化 CSV 精确表达式 | 无 schema 迁移；viewer/operator 精确交集可用分隔符包裹或方言函数实现。 | admin 完整子集需要拆分每个 token；SQLite 与 MySQL 可用函数、递归 CTE/JSON 能力及索引行为不同。前置通配 LIKE 通常不可利用普通索引。 | 仅当真实双后端证明正确且性能达标时可接受；不能凭 SQLAlchemy 编译成功视为语义等价。 |
| 查询全量候选后 Python 过滤再内存分页 | 实现简单，集合语义直观。 | 数据量增长后不可控；数据库分页失效；badge/count 需全量加载；并发下快照一致性差。 | **不推荐**，也不满足当前“查询级同源”目标。 |
| 申请—业务组关联表 | 交集可用 EXISTS，admin 子集可用 NOT EXISTS 越界组；SQLite/MySQL 关系语义稳定，可建立索引，并自然复用到 count/page。 | 需要双写/回填/校验/回滚；必须保留 `__ALL__` 独立语义并处理历史非法 CSV。 | **长期最专业、最可审计；若 CSV DEC 无法证明 admin 子集，则应升级采用。** |

## 5. DEC 必须补齐的内容

1. 明确选定方案及 MySQL 最低支持版本，不能只写“SQLite/MySQL 兼容”。
2. 给出统一的权威 scoped statement/predicate，列表分页和 pending count 只能叠加状态、用户名条件。
3. 冻结 truth table：角色 × actor groups × request groups × 合法性，至少覆盖 1/10、交集、admin 子集/超集、`__ALL__`、空、非法、重复、空白和不存在组。
4. 若保留 CSV，须证明真实 SQLite 与真实 MySQL 返回集合、total、pages、count 完全一致，并记录 EXPLAIN/耗时与数据规模。
5. 若新增关联表，逐项说明 CSV 独立语义、等价表达、不可区分状态、回填拒绝清单、双写窗口、校验及回滚。
6. 定义异常策略：查询/解析失败返回通用 500；单条历史脏数据对 scoped actor 不可见并进入可观测清单，不能静默扩大权限。

## 6. 当前测试充分性

剩余 4 个失败正确覆盖主要缺陷：RL-01（1/10）、RL-04（admin 子集及 total/badge）、RL-10（分页）、RL-11（筛选组合）。但它们不足以单独证明 R2-2 完成：

- 尚需显式增加空串、非法 token、重复 token、混合 `__ALL__`、空白和不存在组测试。
- RL-11 当前仍受 1/10 缺陷驱动，应增加“不含数字碰撞但筛选仍不得扩权”的独立用例。
- 须增加 admin 合法多组子集正向用例，以及 global actor 查看 `__ALL__` 的正向用例。
- 内存 SQLite 只能证明应用逻辑，不能替代真实 MySQL 语义和执行计划验证。

## 7. 风险与停止条件

| 风险 | 控制/停止条件 |
| --- | --- |
| 安全误放行 | 任何非法值、解析失败或方言差异均 fail-closed；负向集合未一致前停止。 |
| 合法申请误隐藏 | 保留 viewer 精确交集、admin 合法子集和 global 全量正向基线。 |
| 分页/count 漂移 | 禁止分页后过滤；同一 predicate 同时驱动 items、total、pages、pending badge。 |
| 性能退化 | 以生产近似规模比较 p50/p95 和 EXPLAIN；无明确阈值或出现全表解析不可交付。 |
| 迁移丢语义 | 关联表方案必须先完成字段逐项语义分析和可回滚迁移设计，再次用户确认。 |

## 8. 专业评分

| 维度 | 评分 | 结论 |
| --- | --- | --- |
| 问题与业务语义准确性 | 9.3/10 | 交集、admin 子集、全局标记及分页前授权边界判断准确。 |
| 架构合理性 | 9.1/10 | 先 R2-1 actor、后 R2-2 resource predicate 的顺序正确；同源查询是必要设计。 |
| 当前技术可实施性 | 7.4/10 | DEC 尚未选型，真实 MySQL、性能、脏数据与迁移细节未闭合。 |
| 测试专业性 | 8.5/10 | 核心红线有效，但非法/重复 token、独立筛选及真实 MySQL矩阵需补充。 |
| **综合** | **8.7/10（A-）** | **方案目标专业、准确且合理；只有完成 DEC 校准后才适合请求实施确认。** |

## 9. 推荐下一步

先完成只读的 R2-2 DEC/探针阶段：采集历史 `group_ids` 数据形态、确认 MySQL 版本、分别验证 CSV 精确表达式与关联表方案的语义和执行计划。若 CSV 无法同时满足 admin 子集、双后端与性能要求，应正式把 R2-2 修订为关联表迁移方案，再等待确认；不得以分页后 Python 过滤作为折中。
