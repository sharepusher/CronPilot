# B1 认证夹具复盘与修复计划（2026-09）

**日期**：2026-09-14　**状态**：Review 未通过，计划待执行

## 1. Bug 定位

Bugbot 对 B1 的 Review 发现，`tests/test_rbac_phase.py` 仍有 30 个失败、5 个错误，主要响应为 302“登录状态已失效”。`tests/test_registration.py` 另有多处手写 Session 缺少 `auth_version`；`TestCreateUserReplacesDisabled` 还存在独立的返回契约失败。

## 2. 根因

B1 只修复了部分测试模块。其余 fixture 直接写角色/用户名，后来又补写了 `user_id=1`，但没有在对应 SQLite 数据库创建同用户名、同角色的启用 `RbacUser`。认证 gate 按 fail-closed 语义清除 Session。部分模块还未导入注册申请、标签等模型，导致 before-request 查询缺表。

## 3. 测试漏洞

- 测试没有统一登录 helper，Session schema 演进后无法集中升级。
- 权限测试使用不存在的用户 ID，导致鉴权失败掩盖了原本的 403/200 断言。
- 最小应用的 `create_all()` 没有覆盖请求钩子会访问的全部模型。
- 注册恢复行为的测试仍假设旧的 `create_user()` 返回结构。

## 4. 修复方案

1. 新增测试专用登录 helper：在当前测试数据库中按用户名/角色创建或查询启用用户，从数据库读取 `auth_version`，再写入完整 Session。
2. 逐一替换 RBAC、注册、审计、Dashboard、CSRF、标签和操作记录模块的手写 Session；安全否定用例明确标注故意缺键/错配，不使用 helper。
3. 所有最小 Flask 应用在 `create_all()` 前导入请求钩子需要的模型。
4. 单独核对 `create_user()` 的 `confirm_reactivation` 返回契约，更新测试或实现，但不与认证夹具修复混合。

## 5. 防护测试

- 每个正常登录 fixture 必须通过 `web_session_user_is_valid()`。
- 保留缺少 `auth_version`、版本不匹配、一次性 bump 幂等三类否定用例。
- 运行受影响簇：`tests.test_rbac_phase`、`tests.test_registration`、`tests.test_oplog_audit_partial`、`tests.test_operation_log`、`tests.test_tag_scope`。
- 最终运行全量 discover，目标为 0 failure、0 error。

## 6. 同类排查

已用 `rg` 扫描 `tests/` 中的 `session_transaction()`、`user_id`、`auth_version`；仍需逐处确认用户名、ID、数据库行和版本值四者一致。重点文件为 `tests/test_rbac_phase.py` 与 `tests/test_registration.py`，而不是只修复 Review 首次命中的两个模块。

## 7. 预防方案

1. 新增 `tests/session_helpers.py`，提供唯一的正常登录入口；CI 增加静态检查，禁止非安全用例直接写 `session['is_login']` 而不调用 helper。验证命令：`rg -n "session\[['\"]is_login" tests` 并逐项标注豁免。
2. 新增 `tests/test_auth_fixture_contract.py`，遍历 helper 生成的 Session，断言其键集合与 DB 用户版本一致；同时直接覆盖缺键否定分支。
3. 在测试应用工厂集中注册完整模型清单，并在每次模型新增时由测试门禁断言请求钩子依赖的表存在。

## 修复顺序与完成条件

B1-A：统一用户与 Session；B1-B：补齐模型注册与旧契约测试；B1-C：运行五个受影响簇；B1-D：全量测试、Ruff、文档门禁。B1 全绿且 Bugbot 复核无 P1/P2 后，才开始 B2。

**实施记录（2026-09-14）：**已补齐 CronList、Lifecycle、NotFound、UserTopbar 的测试用户与 Session 字段，并修正 tbody 断言选择器；相关 15 项定向回归通过。B1 全量仍需继续核对 RbacUsersManage 与注册契约后方可进入 B2。

## 第二轮异常复盘与修复计划

第一轮补齐用户后，RBAC 仍有 10 个失败、2 个错误。剩余异常分化为 seed admin 与 Session 用户名不一致、重复创建 admin 触发唯一约束、Lifecycle 管理员路径 403、NotFound 应用未初始化数据库，以及请求钩子模型未注册。这些属于测试装配或数据契约问题，不应放宽生产鉴权。

1. 为每个测试类建立 username→user\_id→role→auth\_version 映射；统一注册 RBAC 请求依赖模型；核对 Lifecycle 权限/Scope；避免重复 seed。
2. 按 RBAC→注册→全量顺序验收，目标为 0 failure、0 error；Bugbot 复核通过后才进入 B2。
