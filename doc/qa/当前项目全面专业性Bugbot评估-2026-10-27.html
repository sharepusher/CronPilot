4. 主要风险与优先级

优先级风险影响建议的可验证收口
P2Release Notes 含过期 blocker 语义RELEASE_NOTES.md 的 4.1.1 节仍写“发布 4.1.0 前完成 MySQL 演练”，但 4.1.0/4.1.1 均已存在注释 tag；这会误导读者对当前发布状态的判断，但不破坏 tag 或资产事实。将该句改为已完成事实或移入对应历史版本；增加 release-note 内容断言，禁止已发布版本节出现“before publishing”指向更早已发布版本的 blocker 文案。
P2依赖供应链扫描未进入 CI锁定版本不等于无已知 CVE；Ruff 与单测都不能发现第三方漏洞。在 CI 增加受版本控制的依赖审计步骤及允许例外清单；以非零退出码阻断高危、可修复漏洞。
P2测试质量缺少覆盖率目标大量测试可以证明关键路径被测试过，却不能量化未覆盖区域，重构风险难以比较。先只采集基线覆盖率，再按模块设置递增阈值；不得以总覆盖率掩盖 RBAC、调度和迁移关键模块的缺口。
P2运行态 HTTP 验证并非每次本地全量测试必经本次 4 个 CSRF 集成用例 skipped；模板、会话、代理或真实端口配置问题仍可能逃过内存测试。在可启动服务的 CI job 中将这些用例设为必跑，或在本地交付脚本中把 skipped 判为未验收。

5. 值得保留的实践

  • 对安全缺陷实行设计、负例测试、复盘和规则回灌，避免只修单点。
  • 通过双后端迁移测试、路由冒烟和模型守卫处理 ORM 演进，降低“单测绿、页面 500”的常见风险。
  • 文档链接、索引注册和 HTML↔Markdown 同步均可自动验证，审计证据不依赖口头结论。
  • UI 颜色、内联 CSS、表单防重复提交等前端约束有可执行检查，适合长期多人协作。
