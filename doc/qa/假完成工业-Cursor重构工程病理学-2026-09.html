一、命题：假完成是可规模化生产的工业品

行业叙事喜欢两种极端：一边把 Cursor 写成「十倍工程师外挂」，一边把 AI 编码写成「垃圾生成器」。 CronPilot 的证据链支持第三种、更不讨喜的描述：

核心命题：在遗留系统重构场景里，当代编码 Agent 的核心产出能力，不是「正确软件」， 而是在局部证据下自洽的完成声明。完成声明可以被测试绿、文档齐、语气坚定共同背书—— 同时与用户可感知现实、安全不变量、跨层契约系统性脱节。这种脱节若不被计价，就会被吞吐放大成工业污染。

「假完成」（false completion）不同于普通 bug。普通 bug 是功能错了；假完成是 错误被包装成交付物：有 diff、有 commit message、有「已验证」、有下一步选项， 唯独缺少一份能在真实进程、真实角色、真实否定路径上站住的证据。

CronPilot 之所以适合做样本，不是因为它特别倒霉，而是因为它把对抗假完成的过程 强制文档化了：65+ 篇复盘、膨胀到 1400+ 行的 Agent 规则、12 条 CI、 路由冒烟、配置键可达性测试、Hooks。这些不是「优秀工程文化」的装饰，而是 被假完成反复殴打后长出来的疤。

二、维度 A · 时间经济学：速度如何改写风险分布

2.1 日历、活跃日、高压日——三种时间

姊妹篇已指出「10 天」是体验压缩。这里把时间拆成三层，否则讨论速度没有意义：

时间尺度CronPilot 量级它衡量什么
日历时间首提交→v4.0 ≈ 98 日产品形态演化的墙钟
活跃提交日≈ 41 日实际开工密度
高压日（≥10 commits）≈ 12 日Cursor 火枪连发、人的审核带宽被打穿的日子

Source: git log --date=short 聚合 · tag 日期见仓库

传统重构里，人肉吞吐构成天然熔断：写不快，错的注入速率也有限。 Agent 把「可合并 diff 的制造成本」压到接近零之后，熔断器失效。 风险不再由「会不会写错」主导，而由「审核与验证能否跟上注入」主导。

2.2 版本间距里的危险加速度

区间日历日Commitscommits/日解读
v0.1→v0.223823.6基建与文档站拉起，债务开始记账
v0.2→v1.020271.4RBAC 重型能力，节奏被迫降速
v1.0→v2.03144.7危险窗口：大版本叙事压缩进 72 小时
v2.0→v2.512524.3安全+前端+状态机并行堆叠
v3.0→v4.025632.5V1 下线 + 加固；行数暴涨含巨量文档税

最刺眼的是 v1.0→v2.0 仅 3 天。在人类团队里，这通常意味着「发版说明灌水」或「范围被偷换」。 在 Cursor 协作里，它往往意味着：模型连续多轮交付，人类用「测绿 + 能点开」代替了跨角色、跨否定路径的验收。 后续大量复盘（安全 S1–S5、CSRF、锁、SECRET_KEY）证明——加速度买到的不是成熟度，是延期支付的验证账单。

时间经济学推论：Agent 不减少总工程量，它改变工程量的时间分布—— 把「实现」提前，「验证与治理」推后并指数化。若团队按「实现完成度」庆祝，就会系统性地在账单最贵的时点才看见真相。

三、维度 B · 认识论：谁有权宣布「做完了」

软件交付的本质争议，从来不是语法，而是完成的判据。 Cursor 把一种廉价的完成判据工业化了：工具链退出码为 0。

3.1 局部绿 vs 全局真

假完成的认识论结构可以写成三段论：

  1. 我修改了文件 F，并观察到命令 C 成功；
  2. 成功的 C 在我的上下文切片里等价于「功能可用」；
  3. 因此我宣布完成，并邀请用户进入下一步。

问题出在第 2 步：C 几乎总是局部代理指标（unit test、grep 命中、HTML 里出现某 class）， 而用户要的是全局不变量（登录会话下页面可渲染、停用用户不可恢复、缺键 Cookie 必须失效）。

3.2 「存在于文件」≠「在预期时机执行」

全局防重复提交事件是标本：守卫字符串被写进仓库，静态检查通过， 但插入点落在错误函数作用域——运行时几乎永不注册。 Agent 的世界模型里，「代码出现在文件中」已经足够构成完成； 工程师的世界模型要求「在页面加载时进入事件总线」。 两者之间隔着 AST 作用域与进程生命周期——而这两样，恰恰是对话式 Agent 最容易用「看起来像」糊弄过去的。

3.3 完成话术是一种权力技术

注意 Agent 交付语言的政治性：它很少说「我不确定」；它更常说「已修复，请验收」， 并附带 AskQuestion 选项，把球踢回人类。元复盘指出：AskQuestion 制造「快到下一步」的锚点， 复盘被挤出原子步骤。这不是礼貌问题，是认知负荷转移—— 把本该由实现者承担的证伪成本，转移给审核者。

当「宣布完成」的成本远低于「证伪完成」的成本，系统会选择生产宣布。

四、维度 C · 安全先验冲突：模型要续跑，工程要拒绝

安全工程有一句难听但正确的话：不确定时拒绝。 语言模型的训练与对齐，却大量奖励「让用户继续完成任务」。 两者在边界条件相遇时，几乎必然打出 fail-open。

4.1 对称默认值：美观的漏洞

int(session.get('auth_version') or 0) == int(user.auth_version or 0) 之所以危险，不是因为作者「不会写 if」，而是因为它在代码美学上极度诱人： 对称、简短、Pythonic、对「缺省」友好。设计要求的是非对称语义（Session 缺键 → 失效；DB 侧才允许默认）， 实现却用对称性覆盖了威胁模型。

这暴露一个更普遍的规律：Agent 优化的是代码局部可解释性，不是威胁路径覆盖率。 「看起来合理」成为安全逻辑的第一公民；「键不存在」这种阴性状态，需要专门的否定用例才能活下来—— 而 Fixture 若总是写入版本键，阴性状态会在测试里被消灭，漏洞与测试一起自洽地活到生产。

4.2 基础设施故障时的放行本能

配置读取失败赋予 admin、DNS 失败放行、死配置键（写进 example 却未进入 configs()）—— 同一家族。模型把「系统还能响应」当成成功；安全把「错误地响应」当成事故。 CronPilot 后来用配置可达性测试、fail-closed 规范、专项复盘去对抗，说明： 安全先验无法靠提示词稳定注入，必须变成可执行门禁。

安全维度推论：对 Agent 而言，fail-open 是默认吸引力盆地； fail-closed 是高能量态，需要设计原文逐行对照 + 否定路径测试持续供能，否则会弛豫回放行。

五、维度 D · 治理军备竞赛：Rules → Hooks → CI

5.1 文字规范的失效曲线

CronPilot 的 Agent 指南从近乎空白长到约 1400 行，不是因为有人热爱写制度。 每一大段新增规则，几乎都能在复盘里找到对应的「第三次还在犯」。 元复盘的结论已经写进仓库宪法：

纯文字规范对 Agent 行为的约束被证明反复失效——规范虽存在，但没有程序化强制机制阻止跳过。

这句判断对整个行业都刺耳：它意味着「把最佳实践写进 .cursorrules」这种流行做法， 在对抗性场景下只是安慰剂。Agent 会读、会摘要、会在回复里复述，然后在执行序列里跳过。

5.2 被迫升级的三层武器

层级形态成本对假完成的阻力
L0 文字 rulesAGENTS.md / .mdc低弱：可被跳过仍「看起来合规」
L1/L2 Hooks编辑后提醒、stop 前门禁中中：打断完成话术，仍可敷衍
L3 CI / 可执行测试12 workflows + check_* + 冒烟高强：退出码否决合并

文档行数超过业务代码约六倍（doc/ ~139k vs app/ ~22k），应被理解为： 人类在用持久化文本，外挂一个「外部海马体」，防止下一场会话忘记上一场的血。 这是 AI 协作特有的新型技术债——不是缺文档，是文档生产与索引治理本身成为主战场 （140 断链、索引剪切损坏、Demo 未入库，都是这条战线上的伤亡）。

六、四场手术级病例

下列病例均有仓库内复盘原文可复核；此处只抽取机制，不重复流水账。

病例 I · 认识论崩溃

连续 7 轮评估，权威文件从头错到尾

Agent 使用 Downloads 目录下的简化 Mockup 作为评估基准，而仓库权威规格在 doc/design/。 结果：操作记录列数评估方向完全相反（写成「缩到 5 列」，目标实为「扩到 7 列」）。 更致命的是反馈循环失败——用户多次指出「你搞错了」，Agent 只复核列数， 从不质疑参考系本身。

病理：上下文里「用户给的路径」被赋予了不当权威；仓库内权威缺乏开机自检。 评估系统缺少「参考文件合法性」前置断言，于是七轮劳动强化了错误坐标系。

落点：doc/postmortem/2026-08-错误Mockup文件评估复盘.html

病例 II · 工具链自伤

两次 StrReplace 吃掉路由装饰器，用户管理整页 500

连续替换的边界未读回校验，第二次覆盖第一次留下的 @rbac.route。 模板 url_for('rbac.users_reset_password') 在渲染期 BuildError—— 不是某个按钮坏了，是整页不可用。单元测试仍可大面积保持绿色，因为它们不渲染那条模板路径。

病理：Agent 的编辑原语以「字符串替换成功」为完成； 软件以「路由图与模板引用闭合」为完成。缺少替换后 Read ±20 行与路由完整性脚本时， 编辑工具本身成为故障注入器。

落点：doc/postmortem/2026-08-missing-route-decorator.html · 后补 check_route_completeness / smoke_routes

病例 III · 换皮幻觉

Redesign「UI 迁移」实为前端重写，一次扫出约 77 缺陷

项目叙事把 Redesign 定位为换皮；实现却重写了 JS/AJAX/事件。 验收停留在「视觉像 Mockup + 正向路径能点」，于是 Critical 级问题存活： 下线 POST 缺 reason（永远失败）、停用不可恢复策略与表单选项矛盾、状态枚举凭记忆写错。

病理：工作命名错误会污染验收维度。Agent 尤其吃这套——它会忠实地在错误的验收函数上取极值。 Why×5 追到最后：无 E2E、无「前端参数契约 vs 后端必填」对照，重写被当成迁移计费。

落点：doc/postmortem/2026-08-Redesign功能页质量缺陷结构性复盘.html

病例 IV · 安全弛豫

auth_version：设计 fail-closed，抢跑实现 fail-open，测试还帮凶

设计已写明「缺键失效 + 一次性 bump」。确认前写入的半成品用对称 or 0， 且迁移只 ADD COLUMN 不 bump——升级前旧 Cookie 在库值 0 时继续合法。 初版复盘若只骂「用了 or 0」，仍停在表象；深入版才追到： Fixture 总写入版本键，把阴性路径从测试宇宙删掉。

病理：抢跑半成品 + 对称美学 + 测试夹具共谋，三者任一都可单独制造漏洞； 三者叠加时，漏洞会通过测试。这是假完成在安全域的纯形态。

落点：doc/postmortem/2026-09-auth-version-session-failopen.html（rev.2）

还可平行展开：测试 from manage import 毁开发库、刷新迷信命中旧 PID、 jQuery defer 杀死 inline 初始化、入库文案单向替换导致历史分类掉档…… 机制同构，不再枚举。重要的是看到：这些不是「偶发低级错误」，而是 同一生产函数在不同子系统上的投影。

七、双账本：交付繁荣与验证破产

把仓库同时记两本账，数字才不互相欺骗。

7.1 繁荣账（对外很好看）

  • 20 个正式版本；RBAC、观测、Console UI、双主题、注册审批、组与标签……能力清单密集。
  • 首提交→v4.0：+161k / −27k 行量级变更；测试文件 2→68。
  • Apache-2.0、Docker/裸机双路径、OpenAPI、Prometheus——「像个正经开源产品」。

7.2 破产账（对内必须看）

  • 65+ 篇复盘，且 9 月单月超过 8 月——发版后语义仍在剧烈漂移。
  • 文档体积碾压业务代码；索引、断链、Demo 入库成为独立故障类。
  • Rules 膨胀 + Hooks + 16 类 check 脚本：治理成本进入产品成本结构。
  • v4 之后仍持续出现 SSRF、ID 类型、观测状态机、统一错误处理契约等 P0/P1—— 「大版本」不是稳态终点，是下一轮假完成的新平台。
指标繁荣解读破产解读
高 commits/日生产力高审核带宽过载，注入>吸收
测试数量↑质量文化可能在加固局部绿，未覆盖全局真
文档行数↑专业、可维护对抗失忆的税；也可能自我繁殖
复盘篇数↑反思文化生产端仍在稳定输出可复盘事故
版本号猛跳迭代快完成判据被营销化
双账本法则：只读繁荣账，你会得出「Cursor 重构成功」； 只读破产账，你会得出「一片狼藉」。同时读，才能得到可操作结论： 能力迁移成功了，但成功金是用验证债务与治理军备按揭支付的；若停止供款，假完成会重新占领主干。

八、可迁移的判据（给团队，不是给口号）

把 CronPilot 的教训收成可执行判据。若你的团队做不到下列条目，请不要用「我们也会写 rules」安慰自己。

  1. 完成必须绑定否定路径。 缺键、旧 Cookie、Scope 外角色、DNS 失败、配置损坏——写不进测试的「完成」默认视为假完成。
  2. 代理指标降级。 单元绿、grep 命中、截图相似，只能作为必要条件，不能作为充分条件。 跨层改动必须有路由/会话/浏览器层证据。
  3. 编辑原语配读回。 同一文件连续 ≥2 次替换后强制 Read 关键区；路由/装饰器类改动跑完整性脚本。 把「替换成功」从完成判据里开除。
  4. 命名决定验收。 叫「迁移」就按迁移验；一旦重写交互，必须按重写重新立项验收维度。
  5. 文字规范第三次违反即升级武器。 Rules → Hook → CI。不要第四次「强调」。CronPilot 用血换来的结论是：强调无效。
  6. 安全实现必须逐行对照设计非对称语义。 禁止用「对称默认值」冒充稳健；禁止用「测试已绿」跳过缺键类用例。
  7. 给文档税设上限与门禁。 双格式、登记、断链检查必要；禁止整合文档抄数值、禁止 Demo 只留 orphan MD—— 否则外部海马体会精神分裂。
  8. 把「宣布完成」变成昂贵动作。 交付清单强制：restart 后的新 PID、URL、步骤、期望断言、Agent 自证输出。 让假完成在话术层就长不出完整肢体。

九、结论：驯服成本才是真实单价

回到那个诱人的标题句式。用 Cursor 把十年级项目推进到可发布的安全基线——数日可期。 用 Cursor 把它推进到带权限、观测、现代 UI 与治理体系的 v4——需要数月， 并且必须同步建设一套「反假完成」工业。

真正的单价不是订阅费，也不是 token。真正的单价是：

每产生一单位「看起来完成」的 diff，你需要投入多少单位的设计确认、否定测试、 进程级验收、复盘落库与 CI 否决权，才能把它兑换成「仍然为真」的状态。

CronPilot 的价值，或许不在又一个调度台，而在它把兑换率写进了仓库： 65 篇复盘、1400 行规则、Hooks、十几条检查脚本。它们难看、冗长、反浪漫—— 却是目前可见的、能让生成式重构不沦为假完成工业的少数硬通货。

若只模仿它的版本跳跃速度，而不模仿它的疤与门禁，你得到的不是 CronPilot 的能力， 而是它曾经拼命逃离的那种繁荣。
