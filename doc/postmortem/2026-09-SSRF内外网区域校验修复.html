SSRF 内外网区域校验修复复盘

日期：2026-09-21

1. Bug 定位

外网域名在 DNS 二次解析全部返回私网地址时返回成功但无 pinned IP；执行侧随后回退到普通 requests。重定向还可能离开 pinned adapter。

2. 根因

校验逻辑把“私网”当成全局禁止项，没有表达内网目标；同时校验结果允许“成功但无连接证据”，请求层又依赖 requests 默认跳转。

3. 测试漏洞

测试只覆盖公网任务拒绝私网，没有覆盖内部 DNS 域名/内网 IP和执行侧无 pinned IP 的路径。

4. 修复

撤回应用侧内网域名/CIDR 白名单；内网和外网均使用系统 DNS 的实际解析结果，过滤环回/链路本地/保留地址，返回具体 pinned IP；请求关闭自动重定向。部署前提是内外网 DNS 分区隔离。

5. 防护测试

新增内网 IP、内部 DNS 域名和公网域名 pinning 测试；P0 专项测试通过，Ruff 与配置可达性检查通过。

6. 同类排查

检查了 URL 校验、执行请求构造、DNS pinning、请求适配器和配置读取路径；未发现新的普通 requests 回退点。

7. 预防方案

部署文档明确内外网 DNS 分区契约；后续重定向若需恢复，必须逐跳解析和 pin，并增加跨协议/跨主机 E2E 测试。验证命令：.venv-py311/bin/python -m unittest tests.test_p0_phase_a tests.test_config_keys -v。
