# CronPilot · 仓库拆分方案

新项目 **CronPilot** 承接 Phase A（P0）及文档；原 aniu-lee/xiaoniu\_cron 保持冻结

[← 文档索引](index.html) ·
[P0 测试手册](P0测试用例与验收手册.html)

**目标：**上游 [aniu-lee/xiaoniu\_cron](https://github.com/aniu-lee/xiaoniu_cron) 不再合并本次改造；
新仓库作为「增强版 / 下一代」持续迭代（文档 + P0 代码 + 后续 P1/P2）。

## 1. 仓库关系（推荐）

```
flowchart LR
  subgraph upstream["原项目（冻结）"]
    O["aniu-lee/xiaoniu_cron\nmaster"]
  end
  subgraph newproj["新项目（承接变更）"]
    N["<你的账号>/CronPilot\nmain"]
    B1["branch: enhanced/p0"]
    B2["branch: enhanced/p1"]
  end
  O -.->|只读同步 bugfix 可选| N
  N --> B1
  B1 --> B2
```

| 仓库 | 用途 | 默认分支 |
| --- | --- | --- |
| `aniu-lee/xiaoniu_cron` | 开源原版，不提交 P0 改造 | `master` |
| `<你>/CronPilot` | 文档 + P0/P1 代码、测试、脚本 | `main` |

## 2. 推荐命名

- 仓库名：`CronPilot`（已采用）
- 描述：基于 CronPilot 的 HTTP 定时调度增强版（P0 安全与质量 / Plombery 对标演进）
- README 首段注明：Fork 自 aniu-lee/xiaoniu\_cron，原仓库不再直接合并

## 3. 操作步骤（一次性迁移）

### 步骤 A：在当前机器保留「新项目的完整内容」

新项目目录：`/Users/summer/projects/opensource/CronPilot`（已从增强版复制）。初始化 Git：

```
cd /Users/summer/projects/opensource/CronPilot

# 勿提交 conf.ini、venv、sqlite（已在 .gitignore）
git checkout -b enhanced/phase-a-p0
git add app/ configs.py datas/utils/json.py doc/ scripts/ tests/ conf.ini.example
git status   # 确认无 conf.ini、*.db、.venv*

git commit -m "$(cat <<'EOF'
feat(phase-a): P0 安全与质量改造及完整技术文档

- SQL ORM 化、密码哈希、SSRF、JSON 契约、cron 校验统一
- Plombery 对比/PRD/P0 测试手册与新建项目方案
EOF
)"
```

### 步骤 B：GitHub 创建空仓库并推送

```
# 在 GitHub 网页创建 CronPilot（无 README）

cd /Users/summer/projects/opensource/CronPilot
git remote add origin https://github.com/<你的用户名>/CronPilot.git
git push -u origin main
```

之后在新仓库将默认分支设为 `main`，并打 tag：`v0.1.0-phase-a`。

### 步骤 C：原目录恢复为「干净的原版」（不改动远程原项目）

以下命令会**丢弃**当前目录未推送的修改；执行前请确认步骤 B 已 push 成功。

```
cd /Users/summer/projects/opensource/CronPilot
git remote remove next   # 若不再需要在此目录推新库
git checkout master
git reset --hard origin/master
git clean -fdx   # 慎用：删除未跟踪文件（含 doc、tests 等未提交内容）
# 若已提交在 enhanced 分支，clean 不影响远程 next 仓库
```

**更稳妥做法：**复制整个目录为新路径，原路径再 reset：

```
cp -a /Users/summer/projects/opensource/CronPilot \
      /Users/summer/projects/opensource/CronPilot
cd /Users/summer/projects/opensource/CronPilot
# 仅在此目录绑定 next 远程并 push

cd /Users/summer/projects/opensource/CronPilot
git checkout master && git reset --hard origin/master
```

## 4. 分支策略（新项目内）

| 分支 | 说明 | 合并目标 |
| --- | --- | --- |
| `main` | 可发布稳定版 | — |
| `enhanced/phase-a-p0` | 当前 P0（可已合并入 main） | main |
| `enhanced/phase-b-p1` | P1 可观测（status、详情页等） | main（PR 评审） |
| `sync/upstream-YYYYMMDD` | 可选：cherry-pick 原仓库安全修复 | enhanced/\* |

## 5. 与原项目的关系说明（写入新 README）

- 本仓库**不是** aniu-lee/xiaoniu\_cron 的官方后续，而是独立演进线。
- 问题修复若需回馈上游，单独向原仓库提 PR（仅最小 diff）。
- 文档与测试以本仓库 `doc/`、`tests/` 为准。

## 6. 目录与 .gitignore 补充建议（新项目）

```
.venv/
.venv311/
*.db
datas/*.db
caches/
__pycache__/
conf.ini
```

## 7. 合并/发布检查清单

| 检查项 | 说明 |
| --- | --- |
| P0 测试 | `python -m unittest tests.test_p0_phase_a -v` 全绿 |
| 手工冒烟 | 见 [P0 测试手册](P0测试用例与验收手册.html) 签字表 |
| 无密钥入库 | 无 conf.ini、无真实 token |
| 原仓库 | 未向 origin push enhanced 分支（除非刻意贡献上游） |
| 许可证 | 保留原项目 LICENSE 与版权声明 |

```
git clone https://github.com/aniu-lee/xiaoniu_cron.git xiaoniu_cron_upstream

# 增强版日常开发
git clone https://github.com/<你>/CronPilot.git CronPilot
```
