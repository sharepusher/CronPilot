# 集群 Redis 互斥锁原子化 · 生产 SECRET\_KEY fail-fast

Track R1/R2：不改调度拓扑（ADR-05），堵住正确性与会话签名硬伤

状态：已确认并交付 · v2.1.1 · 2026-07-21

**交付结论：**R1 将 `@single_task` 改为 `SET NX EX` + token Lua 释放；R2 在
`ProductionConfig.init_app` 与 `check_conf_production.py` 拒绝弱
`SECRET_KEY`；`run_production.sh` 可首次写入 `datas/.flask_secret_key`。

## 一、问题与根因

| ID | 问题 | 根因 |
| --- | --- | --- |
| OPT-P0-09 | 集群模式下同一任务可能被多节点并发执行 | `single_task` 使用 `GET` 再 `SET`（非原子）；无条件 `DELETE` 在 TTL 过期后可能误删后继持有者的锁 |
| OPT-P0-10 | 生产漏配会话密钥时仍可静默启动 | `config.py` 对任意配置名回退到源码内公开默认值 `hard to guess string` |

## 二、方案

### 2.1 OPT-P0-09

```
acquire: token=uuid4(); SET key token NX EX 120 → 失败则跳过（语义不变）
release: Lua GET==token 才 DEL
```

实现：`app/common/functions.py` → `acquire_task_lock` / `release_task_lock` / `single_task`。
`is_single=1` 路径不访问 Redis。

### 2.2 OPT-P0-10

- 弱密钥：空 / 默认字符串 / 长度 < 16
- `FLASK_CONFIG=production`：`ProductionConfig.init_app` 抛 `RuntimeError`
- `scripts/check_conf_production.py` 增加 `check_secret_key`（`run_production.sh` 已调用）
- 未设环境变量时：`run_production.sh` 读取或生成 `datas/.flask_secret_key`（已加入 `.gitignore`）
- development / testing 仍允许默认密钥（本地 / CI）

## 三、范围

| 做 | 不做 |
| --- | --- |
| 锁原语、生产密钥门禁、单测、部署文档、ADR-05 补丁说明 | 回调重试、APS 4、进程拆分、redis 客户端大版本升级、Vault（CSRF 见 [OPT-P0-11](OPT-P0-11-管理端CSRF设计.html)，已交付） |

## 四、分批与验收

| 批 | 内容 | 验收 |
| --- | --- | --- |
| R1 | 原子锁 + token 释放 | `tests.test_single_task_lock` |
| R2 | fail-fast + 预检 + bootstrap | `tests.test_secret_key` · `tests.test_check_conf_production` |

```
bash scripts/cronpilot.sh test
bash scripts/verify_golden_path.sh
```

## 五、风险

- 直接 `gunicorn` 且未设 `SECRET_KEY` 的生产进程将拒绝启动——预期行为；请用 `run_production.sh` 或显式注入环境变量。
- 轮换 `SECRET_KEY` 会使既有 Session Cookie 全部失效。
- 多节点必须共用同一 `SECRET_KEY`（勿各节点各自生成 `.flask_secret_key`）。
