# 近期代码变更影响与质量评估

日期：2026-09-20 · 主焦点：`7063ff7` / `0e1cc41`（业务 ID → 数据库自增）· 辅焦点：2026-09-18 执行观测修复簇（`0a303ed`…`700ec94`）· 状态：审查完成，未改业务代码

## 1. 总体结论

**已合入部分质量 B+，影响面高，发布条件未满足。** A–C 批次正确关闭了多 worker 下 `next_id` 碰撞的生产写路径；ExecutionTracer 省略主键与 SQLite 事件表值不变重建质量良好。但设计稿 Batch D–F 未完成，且切回无 `AUTOINCREMENT` 关键字的 SQLite 主键后，硬删除场景会复用 ID——这与 OPT-P0-21 当年引入应用层 ID 的原始动机冲突。完成 MySQL 复验、复用防护与死代码清理前，不应标记可发布。

## 2. 审查范围与证据

- 代码：三模型 PK、`execution_tracer.py`、`scripts/ensure_business_tables.py`、`tests/test_id_autoincrement.py`
- 命令：`.venv-py311/bin/python -m unittest tests.test_id_autoincrement tests.test_execution_tracer tests.test_ensure_business_tables -v`（16 OK）
- 本地库：`datas/job_log.sqlite` 中 `cron_infos`/`job_log` 为 `INTEGER` PK；`job_log_events` 已为 `INTEGER PRIMARY KEY`
- 复现：内存库硬删 `CronInfos` 后新插入 `id` 复用（deleted=1 → new=1）
- 对照文档：[迁移设计](../design/OPT-P0-21-数据库自增ID迁移设计-2026-09-20.html)、[下线复盘](../postmortem/2026-09-数据库自增ID生成器下线.html)、[深度 Review](4.0之后提交深度Review-2026-09-20.html)

## 3. 影响矩阵

| 维度 | 影响 | 说明 |
| --- | --- | --- |
| 多 worker ID 唯一性 | 高正面 | 关闭 CR-2：生产路径不再依赖进程内序列 |
| 历史数据兼容 | 中正面 | 事件表重建复制列值；测试断言超大历史 ID 不变、新 ID=max+1 |
| ExecutionTracer | 中正面 | Core INSERT 省略 `id`，避免显式 NULL 抑制 SQLite 分配 |
| ID 复用 / 健康别名 | 中负面残差 | 无 AUTOINCREMENT；生产靠 retire 软下线缓解；硬删仍可别名 `job_health` |
| MySQL 生产路径 | 未验证 | ALTER 已写；Batch D 未实跑；失败仅 WARN |
| 4.1.0 readiness | 仍阻断 | 叠加 CR-3（IPv6）、观测 R3/R6/R7、本变更 D–F |

## 5. Finding 清单

| 级别 | 发现 | 证据 / 影响 | 建议 |

| P1 | 交付未闭环（Batch D–F） | 设计仍写「实施中」；MySQL 未复验；`id_generator.py` 与 `tests/test_id_generator.py` 仍在树内；无双进程并发插入测试 | 完成 D–F 前不标已交付 |
| P1 | SQLite 硬删后 ID 复用 | 本机复现硬删后复用；`job_health` 以 `cron_info_id` 为 PK；生产 retire 缓解但不构成 DDL 级防护 | 补 `AUTOINCREMENT`，或创建时清理孤儿关联 + 否定用例 |

## 6. 辅评：9/18 执行观测簇

transport 异常矩阵与 Run Inspector 兜底修复质量高，定向测试补强充分。仍开放：fatal 阶段代理（R3）、事件 unique vs 迁移索引（R6）、混合 `run_id` 查询（R7）、IPv6 pinning（CR-3）。与本轮 ID 切换正交，共同构成 4.1.0 发布门槛。

## 7. 建议下一步

1. **关闭 P1：**MySQL 三表 AUTO\_INCREMENT 实跑 + 并发插入；硬删复用否定用例或 AUTOINCREMENT DDL；清理/隔离 `id_generator`。
2. **加固迁移：**ALTER 失败 fail-closed；`create_all` 与迁移目标 DDL 对齐断言。
3. **发布门禁：**仅当 D–F + CR-3 + 观测残留项有明确 Closure 状态后，再评估 4.1.0。
