# OPT-P0-22 同名停用覆盖启用 — 前端页面对比 Demo

rev.3 · 左侧 Before / 右侧 After · 黄框为变更焦点

关联：<停用用户同名恢复设计.html> · 须用浏览器打开

**产品原则（rev.3）**
同名再申请未必是原使用人。**申请人侧零提示**。仅**审批人**与**管理员**需知情：将覆盖旧停用账号的资料与权限；因同一 user\_id，历史日志会被继承。

## 5. 注册审批 · 列表 + 批准弹窗（审批人）

registration\_review.html
审批人警示

仅审批人可见。标签「同名停用」；弹窗必须说明：覆盖资料/权限 + 同一 user\_id 继承历史日志 + 未必是原使用人。

Before

| 用户名 | 角色 | 操作 |
| --- | --- | --- |
| **returning** 曾被停用 | operator | 通过 |

批准注册申请

确认批准用户 **returning**？

错误叙事

注意：该用户名曾被停用，审批通过后旧账号记录将被替换。

取消确认批准

After

| 用户名 | 角色 | 操作 |
| --- | --- | --- |
| **returning** 同名停用 | operator | 通过 |

批准注册申请

确认批准用户 **returning**？

正确叙事

注意：用户名与已停用账号相同（user\_id=14）。批准后**不会删除**旧行，将在该 user\_id 上**覆盖**角色、业务组、邮箱、花名、岗位与密码，并撤销旧 Session / Token；该 ID 下的**历史日志将被继承**。申请人未必是原使用人。

将覆盖（示意）

user\_id
:   14（保留 · 日志继承）

角色
:   viewer → operator

业务组
:   旧业务组 → 新业务组（全量替换）

密码
:   使用申请密码

取消确认批准

## 6. 添加用户 · 同名确认（管理员）

user\_form.html + CpModal
新增 · 仅管理员

第一次保存命中同名停用 → 弹窗确认。语义与审批人一致：覆盖资料/权限，同一 user\_id 继承历史日志。

Before · 静默删建

用户名 \*

问题

直接保存时可能物理删除停用用户并新建，无「覆盖 + 日志继承」知情确认。

保存

After · 显式确认

新增弹窗

确认同名覆盖启用

用户名与已停用账号相同（user\_id=14）。确认后将**覆盖**该账号全部资料与权限并重新启用；历史日志因同一 user\_id 保留；密码重置为默认并强制改密；旧 Session / Token 失效。新使用人未必是原使用人。

角色
:   viewer → operator

业务组

密码
