# 执行详情 URL 字段角色化脱敏修复设计

已实施并验证 · 日期：2026-09-15 · 范围：`/job_log_detail` 的 URL 展示边界

**问题：**当前 `run_inspector.html` 直接读取 `cif.req_url`。拥有 `log:read` 的 Viewer 因而可看到任务 URL 中嵌入的 token、API key 或密码；模板也绕过了已确认的角色化 Presenter 契约。

## 一、问题、根因与目标

### 1.1 事实与根因

任务 URL 是配置字段，不等于无敏感数据的地址。诸如 `?token=...`、`?api_key=...`、URL userinfo（`https://user:password@host/`）都可能是有效配置。当前页面仅在 `actual_url` 的局部展示处做角色判断，却无条件输出原始 `req_url`；原因是详情模板仍直接访问 ORM 对象，而现有 Presenter 只包装了时间线事件。

### 1.2 目标

- 所有执行详情角色均不能在 HTML、DOM 或复制控件中获得任何 URL 参数原值或 userinfo 凭据。
- 保留排障必需的 scheme、host、path、参数名与参数存在性。
- 详情模板只消费 `RunInspectorView`，不再读取 `JobLog`、`CronInfos` 或原始 URL 字段。
- 本次只修复展示面；不回写、删除或迁移历史 `JobLog.actual_url`，不改变任务配置编辑能力。

## 二、范围与非范围

| 范围 | 处理 |
| --- | --- |
| 执行详情请求区 | 原始 `req_url` 改为统一 DTO 的脱敏展示值。 |
| 管理员实际 URL 区 | 保留管理员可见性，但只显示脱敏后的 URL；不显示签名或任意参数原值。 |
| 模板数据边界 | 以 `RunInspectorView` / 子 DTO 取代模板中的原始 ORM 字段访问。 |
| 非范围 | 原因 |
| 事件 detail、异常文本、SSRF 原因入库脱敏 | 属于 Bugbot P0-2，另立修复，避免本次混入存储语义变更。 |
| 任务配置编辑页的 URL 展示 | 由 `cron:write` 与表单安全契约管理，不属于执行详情读取面。 |
| 历史库数据清洗 | 任务与执行证据不自动删除；展示修复立即覆盖历史记录，存储侧净化另经确认处理。 |

## 三、方案选择

| 方案 | 优点 | 缺陷 | 结论 |
| --- | --- | --- | --- |
| 仅隐藏 Viewer 的 URL | 改动小 | Operator 仍可泄露；模板仍绕过 Presenter；管理员仍会回显凭据 | 拒绝 |
| 按敏感参数名单替换值 | 保留普通参数原值 | 无法识别自定义凭据键；“管理员可见原值”仍扩大泄露面 | 拒绝 |
| **统一 DTO + 全参数值脱敏** | 对未知参数 fail-closed；所有角色看到同一安全地址；模板边界清晰 | 管理员不能从执行详情复制任意参数原值 | **采用** |

**决策：**执行详情页对所有角色展示同一个 `display_url`：保留 `scheme://host[:port]/path`，保留 query 参数名与顺序，但每个参数值替换为 `***`；URL userinfo 统一替换为 `***:***@`。片段不展示。管理员可额外看到“实际请求已注入 trace 参数”的事实，但不能看到任一参数或签名原值。

## 四、详细技术设计

### 4.1 URL 脱敏函数

新增纯函数 `sanitize_url_for_display(raw_url)`，输入为字符串或空值，输出语义化占位值或脱敏 URL。使用标准库 `urlsplit` / `parse_qsl(..., keep_blank_values=True)` / `urlunsplit`，不以正则替换整个 URL。

1. 空值返回 `—`；无法解析时返回 `地址格式异常（已隐藏）`，绝不回退原文。
2. 移除 fragment；fragment 不会发送到 HTTP 服务端，展示它只会扩大暴露面。
3. 保留 scheme、hostname、port 和 path；若 URL 含 username/password，netloc 固定显示为 `***:***@host`。
4. 解析 query 时保留重复键、原顺序与空键；每个值一律替换为 `***`，即 `?page=2&token=x` 显示为 `?page=***&token=***`。
5. 不得记录 raw URL、不得把 raw URL 作为异常消息、不得向模板传递 raw URL。

### 4.2 Presenter DTO 边界

新增 `build_run_inspector_view(...)`。View 层完成资源 Scope 鉴权后，将 `JobLog`、`CronInfos`、组名、健康度、事件与当前角色交给 Presenter；Presenter 输出只含页面允许渲染的基本类型（str / int / bool / list / dict）。

| DTO 区域 | 字段示例 | 数据约束 |
| --- | --- | --- |
| request | `method`、`display_url`、`has_actual_request` | 只含脱敏 URL，不含 `req_url` / `actual_url` 原值。 |
| response | `http_status`、`body_visible`、`display_body` | 沿用已确认的管理员正文边界。 |
| metadata | `task_name`、`trace_id`、`timeout_display` | 不包含 ORM 实例。 |
| timeline | 既有事件 DTO | 维持当前角色化 detail 规则。 |

模板改为只读 `run.request.display_url` 等 DTO 字段。代码审计门禁应拒绝 `run_inspector.html` 内出现 `cif.`、`jl.`、`item.`。

### 4.3 角色矩阵

| 角色 | 请求地址 | 实际请求信息 | 响应正文 / 业务日志 |
| --- | --- | --- | --- |
| Viewer | 脱敏 `display_url` | 不显示 | 不显示 |
| Operator | 脱敏 `display_url` | 不显示 | 不显示 |
| Biz Admin / Seed Admin | 脱敏 `display_url` | 显示“已注入运行参数”，但 URL 值仍脱敏 | 按既有管理员策略显示 |

| 批次 | 文件边界 | 内容 | 完成条件 |
| --- | --- | --- | --- |

## 六、验收标准

- 使用含 `token=secret-value`、`api_key=secret-value`、重复 query key、空 query value 与 userinfo 的任务 URL，任意执行详情响应 HTML 不得包含 `secret-value`。
- Viewer、Operator 访问同一详情页仅见脱敏地址，且看不到实际 URL、响应正文、业务日志。
- 两类 Admin 的页面仍能确认请求 method、host、path、参数名、是否有实际请求，但不能复制秘密值。
- 历史 `JobLog.actual_url` 不被修改；同一历史记录刷新后也必须脱敏显示。
- 运行定向单测、`python scripts/smoke_routes.py --check`、UI 浏览器正反向验证与模板静态门禁。

## 七、风险与回滚

主要代价是管理员不能通过执行详情复制普通 query 参数值。该信息应从具备写权限的任务编辑面读取；执行详情是审计读取面，安全优先。改动只影响展示 DTO，不改变表结构和存量数据；如需回滚，仅回退应用代码，历史数据不受影响。不得以恢复原始 URL 展示作为临时排障手段。

## 八、实施与验证记录

- 已实现 `sanitize_url_for_display()` 与完整 `RunInspectorView`，执行详情模板只接收 `run` DTO。
- 单元与集成测试覆盖 userinfo、重复参数、空参数值、非法 URL，以及 Admin / Operator / Viewer 的展示边界；三种角色的响应 HTML 均不含测试凭据，只有 Admin 可见实际请求已注入的事实。定向回归共 36 项通过。
- 2026-09-15 本地浏览器以管理员身份加载执行详情，确认请求区只显示脱敏摘要与“敏感值已隐藏”；复制控件仅复制执行记录 ID。
- 已通过 `ruff check app/`、`scripts/check_ui_contract.py --check`、`scripts/smoke_routes.py --check`（86/86）及文档同步/完整性检查。
- 本次仍只处理展示面。事件 detail、异常文本及存储字段的统一脱敏仍是独立的 Bugbot P0-2 修复项，未在本次变更中修改。
