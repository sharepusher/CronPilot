三、P1-03 · 执行详情页（方案 D1）

3.1 路由

路由行为
GET /job_log/<int:job_log_id>主入口：完整管理端布局（顶栏 tabs + 内容区）
GET /job_log_detail?id=保留：无导航的轻量页，供 iframe；内部可复用同一 partial

分享链接示例：http://host:5860/job_log/147（需登录 Session，不新增公开 token）。

3.2 页面结构（线框）

整页详情 D1（推荐）
[任务列表] [任务添加] [执行记录] …  ← 与 cron_list 同款 tabs

3.3 列表入口调整

位置现行为D1 后
执行记录「查看详情」iframe 弹窗默认新开整页 /job_log/<id>；旁链「弹窗查看」可选保留
任务内「运行记录」iframe job_log_list记录行「查看详情」同样链到 /job_log/<id>

推荐（简化）：「查看详情」统一改为整页跳转，去掉 iframe，减少双套 UX。若你需保留弹窗，确认后加「小窗」链接。

四、P1-04 · 立即执行（方案 R1）

4.1 交互

任务列表 · 操作列（推荐）
任务操作
teststp（运行中） 立即执行 · 运行记录 · 停止 · 编辑 · 删除
  • 点击「立即执行」→ 确认框（可选，默认要）→ POST → 等待（回调最长 120s）→ 跳转 /job_log/<new_id>
  • 不校验任务 status==1：已停止任务也可手动跑一次（仅读 cron_infos + URL）
  • 若 req_url 为空 → 返回 JSON 错误，不调用 cron_do

4.2 后端流程

POST /cron_run_now?id=<cron_id> (@login_required) → 校验 CronInfos 存在、req_url 合法 → 调用 run_cron_now(cron_id) # 包装 cron_do，返回 job_log.id └─ 仍走 @single_task：集群 120s 内同任务互斥；冲突时返回「执行中，请稍后」 → web_api_return(code=0, url='/job_log/%s' % job_log_id)

4.3 cron_do 改造（最小）

项说明
返回值cron_do 成功时返回 job_log.id（int），失败/跳过返回 None
调度触发APScheduler 调用处忽略返回值（行为不变）
single_task 冲突返回 None → 立即执行接口 code=1, msg=任务正在执行中
