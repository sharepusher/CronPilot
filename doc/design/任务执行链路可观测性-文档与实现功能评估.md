| 项 | 设计 | 实现 |

| 双栏 vs 列表→详情 | 已统一为整页跳转（§5.5） | 仍为 `/job_log_detail` → `run_inspector.html`，无双栏 |

## 三、功能实测（本地）

**已验证的正向能力**

- 库内 `job_log_events` 约 49 条；近期成功链路可见完整类型：`task.enqueued → task.start → db.load_cif → ssrf.check → http.start → http.error|complete → db.write_log`。
- `task.enqueued.detail` 样例：`{"trigger_source":"schedule","scheduled_delay_ms":16}`（调度延迟未污染 `trigger_delay_ms`）。
- 详情页（登录 admin）HTTP 200，含 `ri-timeline`；Seed Admin 可见事件 detail 字符串。
- 相关单测 11 项通过：`test_execution_tracer` / `test_execution_context_executor` / `test_run_inspector_presenter` / `test_job_log_retention` / `test_job_log_display`。

**功能缺口与风险（按优先级）**

1. **列表误标 pending**：`_exec_logs_rows.html` 仅特殊处理 `running`，`pending` →「未知」；而 `job_log_display.job_log_badge` 已正确返回「已入队」——列表未复用。
2. **Presenter/安全契约未兑现**：设计要求模板不读敏感原字段、任何角色不可见原始 detail JSON；现状 `can_view_sensitive = (role == 'admin')` + 模板直读 + admin 时间线 dump JSON。
3. **事件字段不完整**：`http.start` 仅存 `method`（库证）；缺脱敏 URL；超时字段用 `exc_*` 而非设计 `timeout_sec`。
4. **时间线非主诊断区**：DOM 顺序为请求 → 响应 → 业务日志 → 元数据 → 时间线，与设计「摘要下主时间线」不符。
5. **缺少合同/集成测试**：无 lock-skip 零记录、三触发路径、Tracer 故障隔离、四角色矩阵测试。
6. **旁路观察**：库内 `http.error` 出现 `assert_hostname` TypeError——属触发 HTTP 客户端路径问题，会污染链路结论，建议另开缺陷跟踪（非本方案核心，但影响「可观测」可信度）。

说明：本轮未能强制 `cronpilot.sh restart`（环境拦截杀旧 PID）；页面冒烟命中当时监听进程。库内事件与代码审查结论不受影响；正式验收前仍须 restart 后再做浏览器四角色断言。

## 四、功能就绪度结论

| 场景 | 可否依赖 |
| --- | --- |
| 工程师用详情时间线排查「走到哪一步」 | 有限可用（阶段有；URL/耗时/角色裁剪不足） |
| 运维用列表发现「执行中/已入队」 | 不可靠（pending 显示未知；默认筛选易藏进行中） |
| 按角色脱敏对外演示 / 发版 | 不可 |
| 作为「收敛版已交付」写入路线图 | 不可 |

**一句话：**文档已收敛且可指导实施；实现处于「写入侧中期可用、产品契约未闭环」阶段。优先补齐 B4/B5 与合同测试，再谈 B6 与交付标注。

## 五、建议的收口顺序（仍须确认范围后改代码）

1. 列表：复用 `job_log_badge`；补 pending/running 筛选；默认视图可发现进行中记录。
2. Presenter：完整 DTO；模板去敏感直读；禁止原始 detail JSON；时间线上移并合并业务日志排序。
3. 事件白名单对齐 §4.2（至少 `http.start.url` 脱敏、`scheduled_at`、`timeout_sec`）。
4. 补 `test_execution_observability_contract.py` + cron\_do 集成路径。
5. B6：restart + 四角色浏览器 + RELEASE 功能条。
