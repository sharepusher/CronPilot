CronPilot V1（Legacy UI）下线方案

日期：2026-08-26  |  编号：OPT-P1-16 Phase Final  |  状态：设计评审中

1. 问题陈述

CronPilot 当前运行 双轨 UI 系统：V1（Legacy Simpleboot + Bootstrap 3）和 V2（Redesign 自研架构）。 双轨通过 Cookie cp_ui_version 或配置项 CRONPILOT_FORCE_NEW_UI=1 切换。

1.2 维护痛点

  • 双倍测试成本：每个功能需验证 V1 和 V2 两条路径
  • 代码膨胀：views.py 中 35 处 getattr(g, 'ui_version', 'v1') == 'v2' 三元表达式
  • 依赖锁定：V1 依赖 Bootstrap 3 + Simpleboot + artDialog + ajaxForm + wind.js 等不再维护的库
  • 安全负债：V1 模板中硬编码颜色、inline style 不受 CI 门禁监管（CI 仅覆盖 redesign/ 目录）
  • 认知负荷：新贡献者需理解两套模板系统的关系

3. 下线方案

3.1 策略选择

方案描述推荐
A. 硬切直接删除 V1，FORCE_NEW_UI=1 为默认✓ 推荐
B. 过渡期保留 V1 代码 1 个版本周期，通过 deprecation warning 引导适用于外部用户多的项目
C. 渐进式按页面逐个下线 V1（先 Dashboard → 最后 Login）复杂度高，不推荐

推荐方案 A 的理由：CronPilot 为内部工具型项目，用户群可控；V2 已稳定运行；无第三方 API 兼容性顾虑。

3.4 模板目录重组（可选，Batch 5 之后）

可选决策：下线 V1 后，app/templates/redesign/ 中的文件成为唯一模板。 是否将它们移到 app/templates/ 根目录？
方案优点缺点
保持 redesign/ 子目录零改动；git history 连续路径略长；"redesign" 名称过时
移到根 templates/路径简洁；语义清晰需改 35+ 处 render_template 路径；git blame 断裂
重命名为 templates/views/语义中性同上 + 额外重命名工作

建议：保持 redesign/ 子目录。名称可在下一个 major version 时统一重命名（通过 git mv + 全局替换），当前改动的 ROI 过低。

4. 风险评估

风险概率影响缓解
V2 存在未发现的功能缺失低中Batch 1 先默认 V2 但保留回退能力
外部集成依赖 V1 特定 DOM 结构极低低无外部浏览器自动化集成
删除后发现测试依赖 V1 模板低低Batch 2 前全量运行测试
用户习惯 V1 界面不适应低低Batch 1 阶段提供回退 Cookie 说明

5. 验收标准

批次验收条件
Batch 1无 Cookie 时默认加载 V2；cronpilot.sh test 全绿；浏览器登录→操作→登出正常
Batch 2views.py 无 ui_version 引用；测试全绿；设置 cp_ui_version=v1 Cookie 不再生效
Batch 3ls app/templates/*.html 仅剩 index.html（如有）；app/templates/rbac/ 目录已删除；测试全绿
Batch 4ls app/static/js/ 仅包含 redesign 模块 + jquery；测试全绿；浏览器无 404
Batch 5grep -r "admin_base\|simpleboot\|artDialog\|wind\.js" app/ 返回空；CI 全绿

6. 不做清单

  • 不删除 jquery.js — V2 仍依赖 jQuery（common-redesign.js）
  • 不删除 console-theme.css — V2 的 Design Token 来源
  • 不重命名 redesign/ 目录（见 3.4 分析）
  • 不改变 URL 路由 — 所有用户可见 URL 不变
  • 不影响 API 层 — app/api/views.py 无 UI 版本分支

7. 时间线建议

阶段建议时间点说明
Batch 1（默认 V2）立即可执行风险最低，可回滚
Batch 2-5（完全下线）Batch 1 稳定运行 1-2 周后确认无功能缺失再执行不可逆操作
或一次性全做立即如果对 V2 功能完备性有信心
