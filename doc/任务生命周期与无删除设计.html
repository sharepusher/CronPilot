任务生命周期与无删除

暂停 ≠ 下线；取消任务/日志人工删除；下线为不可逆终点，同类需求须新建

LIFECYCLE-1：已落地 · v1.0.0 · LIFECYCLE-2：已落地 · v1.0.0

关联：RBAC v4 · 架构设计（§操作审计 OPT-P1-09）· 交付状态

一、问题与根因

项内容
问题任务/执行流水提供「删除」，易丢失审计与历史；「停止」与「结束」语义混淆
根因早期 CRUD 把删除当生命周期终点；模型已有 status=-1 结束态，但 Web 以物理删除为主
目标配置与流水可追溯；暂停可恢复；下线不可逆；同类需求新建任务
LIFECYCLE-2 补充下线无原因/时间难查阅；备注可空；无创建/编辑时间戳

二、状态机（权威）

动作含义cron_infos.status可逆？
运行调度执行中1—
暂停临时停调度，配置保留0是（可再「运行」）
下线生命周期终点-1否（不可再启/再改；同类需求新建）
创建 → 运行 ⇄ 暂停
         ↘       ↙
          下线（终点）
不做：管理端/API 人工删除任务；管理端人工删除执行日志/流水；对已下线任务再启动或编辑「复活」。
保留：按 job_log_counts 的系统自动裁剪（容量策略，非用户删除功能）；one-shot 自然结束后写 status=-1（LIFECYCLE-2 同时写系统下线原因与时间）。

三、方案要点（LIFECYCLE-1 · 已落地）

3.1 Web

  • 退役 /cron_del、/cron_batch_del、/job_log_delete、/job_batch_delete（返回 410）
  • 新增 /cron_retire：写 status=-1 + remove_job；不删 cron_infos / job_log
  • 列表：运行中/已暂停对所有角色展示「下线」入口；仅具备 cron:retire 的账号可进入下线表单并执行；其它角色（含种子 admin）点击弹出「权限不足：当前账号不可下线任务」。已下线仅展示状态，无启动/暂停/编辑/下线
  • 已下线禁止 update_status、cron_edit

3.2 API

  • /api/cron/status 仍仅 0|1（暂停/运行）
  • 新增 /api/cron/retire（按 task_name）
  • /api/cron upsert：若同名任务已 status=-1 → 拒绝，提示须新建（新 task_name）

3.3 RBAC

ROLE_PERMISSIONS = {
    'viewer':   {'cron:read', 'log:read'},
    'operator': {'cron:read', 'cron:write', 'log:read', 'operation:read'},
    'admin':    {'cron:read', 'cron:write', 'cron:retire',
                 'log:read', 'operation:read', 'user:manage', 'audit:read'},
  }
  # cron:write = 添加/编辑/启动/暂停；cron:retire = 下线（仅 admin）
  # operation:read = 操作记录（operator+admin）；audit:read = RBAC 审计（仅 admin）
  # 废弃 cron:delete / log:delete

cron:write = 添加/编辑/启动/暂停；cron:retire = 下线（仅 admin）。废弃 cron:delete、log:delete。

四、LIFECYCLE-2 · 元数据与下线可追溯（已落地 · v1.0.0）

目标：列表/详情可直接查阅下线原因与时间、任务备注与创建/最后编辑时间。不新建「任务更新日志」表；完整「谁改了什么」仍走 OPT-P1-09 operation_log。

4.1 cron_infos 扩展字段

字段类型（建议）说明
task_keywordVARCHAR(500)任务说明/备注；新建与编辑必填（1～500 字 trim 非空）
created_atVARCHAR(25)创建时间；只写一次
updated_atVARCHAR(25)最后配置编辑时间；创建时与 created_at 相同
retire_reasonVARCHAR(500)下线原因；人工下线必填（1～500 字 trim 非空；与说明同长）
retired_atVARCHAR(25)下线时刻

不做 retired_by：操作人属体验增强，与远期 operation_log 重叠；列表用原因文案区分人工/系统即可。

4.2 校验与行为规则

规则内容
备注必填Web/API 新建、编辑：task_keyword trim 后 1～500 字，否则拒绝
存量空备注允许继续运行/暂停；下次编辑必须补全（避免 bulk 迁移失败）
updated_at仅添加/编辑配置时更新；暂停/运行/下线不刷（下线用 retired_at）
人工下线Web POST /cron_retire、API /api/cron/retire 必传 reason；写 status=-1 + retire_reason/retired_at + remove_job
系统下线one-shot 结束 / 调度收束：写 retired_at；retire_reason 固定文案（如「一次性任务执行完成（系统）」）

4.3 UI（对齐 simpleboot：control-group + 行内灰字）

  • 添加/编辑：备注标签改为必填；灰字说明「用途/负责人/告警联系等」；去掉「可为空」
  • 编辑页：只读展示「创建时间」「上次编辑时间」
  • 列表：已下线行展示「下线于 … · 原因 …」（可截断）；可选展示创建时间列
  • 下线：确认框或小表单必填原因后再提交（不可一键无因下线）

4.4 与审计分工（不做独立更新日志）

能力落点状态

六、验收

6.1 LIFECYCLE-1

  1. UI 无任务删除、无日志删除
  2. 旧删除 URL → 410
  3. 暂停 ⇄ 运行；下线后不可运行/编辑；列表显示已下线
  4. 下线后流水仍可查；同类需求走添加（新 task_name）
  5. 三角色分权：operator 可暂停不可下线；admin 可下线
  6. 自动日志裁剪仍可按配置工作

6.2 LIFECYCLE-2（实现后）

  1. 无备注不可新建/编辑；存量空备注编辑时被拒绝直至补全
  2. 无 reason 不可人工下线；下线后列表/详情可见原因与 retired_at
  3. 新建可见 created_at；编辑后 updated_at 变化；暂停不改变 updated_at
  4. one-shot 结束后有系统原因与下线时间
