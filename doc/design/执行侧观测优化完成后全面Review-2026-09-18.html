3. 根因与范围

本轮优化把状态枚举从“单一失败文案”推进到三元契约，但枚举扩展仍分散在分类函数、模板分支和迁移脚本中，缺少集中式状态字典与穷举门禁。F1/F2/F6 解决了主要误导，却暴露出新增状态未被 UI 消费、异常基类边界过宽和阶段上下文不足的问题。R5/R8 已分别通过 AST 语义修复与链接校正关闭。

4. 修复计划

  1. B5 · 状态兜底（R1/R4）：集中定义传输状态标签；补齐未知/客户端失败/未开始分支；真实 Jinja 三角色矩阵。
  2. B6 · 异常矩阵（R2）：按 Requests 异常子类、response 是否存在、请求边界拆分状态；保留历史值兼容。
  3. B7 · 阶段上下文（R3）：用显式阶段变量替代 saved_jl is not None 代理。
  4. G1 · 门禁修复（R5）：已完成 AST 语义修复与别名回归。
  5. M1 · 迁移观察（R6/R7）：补 unique/index 和混合事件查询验证，不在本轮直接删除历史数据。

5. 验收标准

  • 每个 transport_state 枚举在分类函数、Presenter、模板和测试中均有登记；未知值有兜底文案。
  • ConnectTimeout、ReadTimeout、ProxyError、RemoteDisconnected、TooManyRedirects、客户端 TypeError 各有正反断言。
  • 三角色真实模板渲染无空白传输状态、无错误“已收到响应”文案。
  • bash scripts/cronpilot.sh test 全量通过；ruff、UI 契约、86 路由冒烟通过。
  • SQLite/MySQL 迁移幂等，唯一约束和混合事件时间线可验证。

6. 风险与回滚

异常细分只影响诊断字段与展示，不改变任务业务结果；旧状态保留读取兼容。若新分类导致历史页面误读，可先回滚 Presenter/模板标签映射，保留 JobLog 原始字段和事件数据；迁移批次不得删除旧事件或 trace_id。
