R1 · 执行记录列表 pending / running 显示收口设计

已实施 UX · 执行记录 收敛版 B5 前半 · 短设计
日期：2026-09-16 · 父设计：收敛版 rev.6 · 收口评估：2026-09-16 未提交评估

入口： 问题 根因 方案 页面对比 范围 分批 验收 风险

一句话：数据库里状态仍是 pending（已入队），列表「结果」列却显示成「未知」。本轮只修执行记录列表的文案/样式，并加一个「进行中」筛选；不改默认「非成功」筛选，不动详情 Presenter（那是 R2/B4）。

1. 问题

用户在「执行记录」页看结果列时：

  • 一条其实是 pending（触发后已建父记录、尚未进入业务）的记录，显示成灰色 「未知」；
  • running（执行中）虽文案对了，但套用了与「未知」相同的灰色样式 class（el-log-unknown），语义偏弱；
  • 默认筛选是「非成功」（只含 fail/error/timeout），进行中记录本来就不在默认列表里；即使修好徽章，用户若不点「全部」仍看不到它们。需要一个明确入口发现进行中记录。

不是：把库里的 pending 字段改成别的值；也不是把「未知」这个词全局删掉（空 status 的历史脏数据仍可显示「未知」）。

2. 根因

层事实
模板_exec_logs_rows.html 结果列只分支了 success/fail/error/timeout/running，其余进 else → 「未知」。pending 无分支。
已有正确文案未复用job_log_display.job_log_badge() 已定义 pending→已入队、running→执行中，列表未调用。
筛选 SQLjob_log_outcome_clause('not_success') 仅 fail/error/timeout，不含 pending/running；筛选项也无「进行中」。

3. 方案（推荐）

3.1 结果列徽章（必做）

  • 模板改为调用 job_log_badge(log.status)（或与其对齐的同等映射），按返回的文案与 tone 渲染。
  • 映射锁定：
status文案CSS class（新建/复用）
success成功el-log-success（已有）
fail失败el-log-fail
error异常el-log-error
timeout超时el-log-timeout
running执行中el-log-running（新建，信号色，不用 unknown）
pending已入队el-log-pending（新建，警告/中性进行中语义）
空 / 非法未知el-log-unknown（保留兜底）

颜色一律 var(--cp-*)，写入 redesign-pages.css 的 .cp-page-exec-logs / 既有 .el-log-* 作用域。

3.2 筛选「进行中」（推荐同轮）

  • 在 outcome chip 组增加 「进行中」，对应 outcome=in_progress（或 active，实现时统一一名称并写进测试）。
  • job_log_outcome_clause：该值 → status IN (pending, running)。
  • AJAX 局部刷新契约不变（沿用现有 execution_logs.html filter JS）。
  • 默认筛选仍为「非成功」：不把 pending/running 塞进默认失败视图，避免运维「非成功」列表语义突变。
待你确认的产品点：若希望打开执行记录页默认就能看见进行中记录，备选是把默认改为「全部」，或把 pending/running 并入「非成功」。本短设计默认不采用这两种（噪音大、改变「非成功」运维习惯）。若你点名要改默认，实现前再补一行确认即可。

3.3 交互契约

项约定
页面仍是 GET 列表 + AJAX 换行；不整页刷新降级
chip 文案现有：非成功 / 全部 / 仅失败 / 仅异常 / 仅成功；新增：进行中（建议放在「全部」旁）
表头不改列名、不改列数
详情 / 任务中心本轮不改（任务详情近期点已有 pending/running class）

6. 分批

禁止与 R2 Presenter 重排同 commit。

7. 验收

  1. python -m unittest 覆盖 job_log_outcome_clause('in_progress')（或最终命名）与 badge 映射；既有 not_success/success 回归不过期。
  2. bash scripts/cronpilot.sh restart --daemon 后登录：
    • 准备一条 status=pending 的 job_log（或触发后未终态）；
    • 点「进行中」→ 结果列文案为「已入队」，class 非 el-log-unknown；
    • 点「非成功」→ 该 pending 行不出现；
    • 点「全部」→ pending/running 文案正确；
    • 筛选切换仍为 AJAX（无整页闪白）。
  3. Agent 自证：curl/会话 HTML 含「已入队」且同页 pending 行无「未知」误标。

8. 风险

  • 默认仍藏进行中：刻意保留；靠「进行中」「全部」发现。若产品要默认可见，需另确认改默认。
  • 历史空 status：仍显示「未知」，避免把脏数据硬标「已入队」。
  • 回归面：执行记录 AJAX；勿破坏 OPT-P1-18 局部刷新。
