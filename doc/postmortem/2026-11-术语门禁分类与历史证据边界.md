# 术语门禁分类与历史证据边界修复

2026-11-03 · 用户确认设计后实施 · 专项验证通过

设计及最新验收：[术语门禁与任务编辑基线工具修复设计](../design/terminology-baseline-repair-2026-11-03.html)。本次仅修复工程工具及文档；完整发布结论以设计末节为准。

## 1. Bug 定位

scripts/check\_terminology.py 的全仓扫描产生 41 个命中行；源文档业务旧称、技术标识符和历史检查诊断被同样处理。HTML 与生成 MD 的命中属于同一源文案问题。

## 2. 根因

检查器用字符串和少数整行例外表达语义，开发流程又只测示例而未覆盖真实仓库。冻结的失败输出进入下一轮扫描，形成自我命中；缺少按字段限定的历史诊断边界。

## 3. 测试漏洞

原四项用例没有覆盖精确标识符与同一行业务旧称共存，也没有覆盖 JSON 编码、相邻记录、重复键和命令退出码。未对真实仓库运行结果设置回归断言。

## 4. 修复

逐段校准十份 HTML 源及一处脚本说明，生成 MD；只移除精确技术标识符 `callback_executed` 后继续检查剩余文本。历史诊断仅在登记路径、精确命令、非零整数退出码、合法三字段唯一键记录中屏蔽 `output_tail` 原始值片段，保留源行号。其他字段及相邻记录继续检查。两个历史 JSON 原字节未改，指纹见下方 manifest。

## 5. 防护测试

tests/test\_check\_terminology.py 共 12 项通过，含混合行、相似标识符、Unicode/转义、错路径/命令/退出码、重复键、非诊断字段及实际 CLI 退出码。全仓检查退出 0。

## 6. 同类排查

复核 doc/、scripts/ 的全部原始命中，区分任务执行、响应处理和事件处理；核对技术键历史证据及检查诊断两处文件的 SHA256。未更名业务持久化值或机器协议字段，未新增目录白名单。

## 7. 预防方案

新增真实仓库零命中及最小例外否定用例，落点 tests/test\_check\_terminology.py；现有 unit-tests.yml 的 unittest discover 自动执行。第三方可运行下方命令，并用测试内的错路径、同一行混合词和重复键控制验证检查不会被宽泛豁免。未来新增历史诊断路径必须同时补充对应否定用例。

## 可执行验收

```
.venv-py311/bin/python -m unittest tests.test_check_terminology -v
.venv-py311/bin/python scripts/check_terminology.py --check
```
