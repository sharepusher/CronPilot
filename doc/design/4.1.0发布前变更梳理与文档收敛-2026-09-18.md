# CronPilot 4.1.0 发布前变更梳理与文档收敛

日期：2026-09-18 · 基线：`v4.0.0` · 当前 HEAD：`4d8f2ac`

## 1. 目标与结论

本文把 `v4.0.0..HEAD` 的代码提交、设计/复盘文档和当前未提交变更分成发布范围、历史留档和发布阻断三类，避免把过期设计稿误写进 4.1.0 Release Notes。

**结论：**当前变更可以提交为发布前修复集，但暂不应创建 `v4.1.0` 正式 tag。全量测试已恢复为 818 条通过、11 条跳过；执行侧观测全面 Review 仍保留 R1/R2 两个 Medium 风险。

## 2. 4.1.0 建议纳入范围

- 任务中心统计语义收敛：标题移除总任务数与今日失败，今日失败留在独立统计卡。
- 执行观测链路：run\_id 关联、事件上下文、失败阶段/传输状态/HTTP 响应语义、Run Inspector 契约。
- 任务与安全修复：50-bit ID、健康度阈值、用户同名覆盖、SSRF fail-closed、Pinned HTTP/HTTPS 参数分离、下线任务排除。
- 工程门禁：文档索引/双格式同步、术语门禁、离线/沙盒验收、AST ORM legacy 门禁误报修复。

## 3. 明确不纳入 4.1.0 发布说明的文档

- `doc/archive/**` 历史设计、评估轮次和质量报告：保留追溯，不进入功能清单。
- 仍标记“待确认/暂停”的 R2-D、R3-C、传输状态机下一批 B5/B6/B7 与未完成测试修复方案。
- 仅描述评估过程、未对应已合并行为的旧 Review 快照。

不纳入发布说明不等于删除文件；历史文档继续保留。

## 4. 4.0.0 之后的提交清单

共 31 个已提交变更，主题覆盖 CQ-9、OPT-P0-21/22、Dashboard/UI、SEC-6、生命周期日志、RBAC/全量回归、沙盒验收、调度展示、执行观测、Pinned adapter，以及对应设计/复盘/索引登记。完整哈希与主题见同名 Markdown。

## 5. 当前未提交变更与提交边界

可提交内容包括执行观测 F1/F2/F3/F6、任务中心标题统计收敛、对应双格式设计/复盘、ORM legacy AST 误报修复和文档断链修复。不应在同一提交中伪装关闭 R1/R2。

## 6. 发布阻断与验收

1. 补齐 R1 状态兜底与真实模板测试。
2. 完成 R2 Requests 异常矩阵。
3. 完成 R6/R7 迁移与混合事件 fallback 验收。
4. 重跑全量测试、Ruff、路由冒烟及文档门禁，更新版本文件。

```
bash scripts/cronpilot.sh test
ruff check app/
python3 scripts/smoke_routes.py --check
python3 scripts/html_docs_to_markdown.py --check
python3 scripts/check_doc_completeness.py --check
python3 scripts/check_doc_links.py --check
python3 scripts/check_version_consistency.py --check
```

## 7. 发布操作顺序

先提交当前修复集；R1/R2 关闭且门禁全绿后，再将确认条目从 `[Unreleased]` 下沉到 `[4.1.0]`，同步 README、路线图和双格式 Release Notes，最后由发布人创建 tag。本轮不执行 tag 或 push。
