## F-1：Vue 组件 Font Awesome 图标缺失

### 问题

`CronFormValidator.vue` 使用 4 处 Font Awesome 图标（`fa-exclamation-triangle`、`fa-clock-o`、`fa-exclamation-circle` ×2），但 Redesign shell 不加载 Font Awesome CSS。图标在任务表单中不显示。

### 根因

该 Vue 组件最初在 v1 simpleboot 环境下开发（v1 通过 `admin_base.html` 加载 FA CSS）。迁移到 Redesign v2 后，FA 依赖未同步替换为 inline SVG。

### 方案

将 4 处 `<i class="fa ...">` 替换为 inline SVG，复用 Redesign 已有的 SVG 图案（Heroicons 风格）。

### 对比 Demo

BEFORE（当前效果 — 图标不可见）

分 超出范围 0-59：65

⬆ `<i class="fa fa-exclamation-triangle">` 无样式，图标不渲染

每天 09:30

⬆ `<i class="fa fa-clock-o">` 时钟图标不渲染

AFTER（修复后 — inline SVG 可见）

分 超出范围 0-59：65

⬆ 警告三角形 inline SVG，与 Redesign `error.html` 一致

每天 09:30

⬆ 时钟 inline SVG（Heroicons clock 风格）

### 范围

| 文件 | 变更 |
| --- | --- |
| `frontend/src/components/CronFormValidator.vue` | 替换 4 处 `<i class="fa ...">` 为 inline SVG |
| `app/static/dist/cron-form-validator.js` | `npm run build` 重新生成 |
| `app/static/dist/cron-form-validator.css` | 同上 |

### 不做

- 不引入 Font Awesome CSS（Redesign 统一使用 inline SVG）
- 不修改 Vue 组件逻辑或其他视觉样式

### 分批

单批次：替换 → build → 验收。

### 验收

1. `cd frontend && npm run build` 无报错
2. `bash scripts/cronpilot.sh restart --daemon`
3. 浏览器打开 `/cron_add`，填写 cron 表达式 → 预览区显示时钟 SVG + 人话描述
4. 填写无效值 → 错误提示显示警告三角形 SVG
5. 填写无效 URL → 错误提示显示感叹号 SVG

### 风险

低。仅替换不可见的图标标签，不改变组件逻辑或数据流。

## F-6：AJAX 错误响应触发重定向（丢失表单数据）

### 问题

`common-redesign.js` 第 112-113 行：当 `errcode !== 0`（验证失败）且响应包含 `url` 字段时，800ms 后自动重定向到 `data.url`，导致用户丢失已填写的表单数据。

### 根因

该分支最初设计为"错误时跳转回列表页"的兜底行为，但与项目规范冲突：错误响应中不应包含 `url` 字段（已在 `.cursor/rules/cronpilot-project.mdc` 中明确禁止）。双重保护缺失。

### 方案

删除 `errcode !== 0` 时的重定向分支，仅保留 `errcode === 0` 的正常重定向。

### 对比 Demo

BEFORE — 验证失败 + 后端返回 url 时的行为

```
// 用户在"新建任务"表单中填写了大量内容
// 提交后后端返回 {errcode: 1, errmsg: "任务名已存在", url: "/"}

// common-redesign.js 行为：
1. CpToast.error("任务名已存在")  ← 用户看到错误提示
2. 800ms 后 → window.location.href = "/"  ← 跳转回首页！
3. 用户填写的所有内容全部丢失 ✗
```

AFTER — 仅在成功时重定向

```
// 相同场景：后端返回 {errcode: 1, errmsg: "任务名已存在", url: "/"}

// common-redesign.js 行为：
1. CpToast.error("任务名已存在")  ← 用户看到错误提示
2. 表单保持原位，用户可修改后重新提交 ✓
```

### 代码变更

```
// BEFORE (common-redesign.js:110-113)
if (data.url && data.errcode === 0) {
  window.location.href = data.url;
} else if (data.url && data.errcode !== 0) {
  setTimeout(function() { window.location.href = data.url; }, 800);
}

// AFTER
if (data.url && data.errcode === 0) {
  window.location.href = data.url;
}
```

### 范围

| 文件 | 变更 |
| --- | --- |
| `app/static/js/common-redesign.js` | 删除 `else if (data.url && data.errcode !== 0)` 分支（2 行） |

### 不做

- 不修改后端返回逻辑（后端 `url` 字段的清理是独立的 P2 任务）
- 不修改 v1 `common.js`（已无使用场景）

### 分批

单批次：删除分支 → restart → 验收。

### 验收

1. `bash scripts/cronpilot.sh restart --daemon`
2. 浏览器打开"新建任务"（`/cron_add`），填写内容后提交触发验证错误
3. 确认：① Toast 显示错误消息 ② 页面不跳转 ③ 表单数据保留
4. 提交正确内容 → 确认成功后正常跳转到列表页

### 风险

极低。删除的分支本身就是违反项目规范的行为；如有后端 endpoint 依赖"错误时重定向"逻辑（不应存在），会退化为"停留在表单页"，不会丢失数据。
