# RBAC 用户编辑 U2 事务收口验收

日期：2026-10-29 · 状态：**通过** · 范围：`POST /rbac/users/edit` 写边界

**结论：**U2 已达到进入 U3 的门禁。数据库当前授权、锁内三方比较、业务与审计单事务、授权副作用和五种写边界结果均有可重现证据；未发现部分保存、冲突覆盖、成功审计漂移或锁泄漏。

## 1. 实施内容

- `update_user_management()` 改为强制接收 actor、target、签名原始快照、规范化请求和意图 change set；服务内重算意图，拒绝调用方伪造。
- 结束路由阶段只读事务后，按用户 ID 顺序锁 actor/target；管理员降权场景把启用 admin 行纳入同一确定顺序锁集合。随后按 user/group ID 顺序锁关系行和目标业务组。
- 使用数据库当前 actor 权限、组集合、target 状态和 Scope 再授权；Session 与路由早期判断都不是最终写授权证据。
- 资料字段独立三方比较，`role + group_ids` 作为耦合授权单元比较；只应用 `effective_change_set`。
- 资料-only 不 bump；角色/组真实变化仅 bump 一次 `auth_version`、重签 Token，并在 commit 成功后失效当前 worker Scope 缓存。
- 审计 detail 只从五字段有效差异白名单构建 JSON v1，与业务同一 flush/commit；邮箱清空理由在写边界再次校验并随审计持久化。
- 冲突/失败留页只使用独立表单值回显，不再修改已持久化的 `User` ORM 实例，避免后续查询或提交触发 autoflush，把被拒绝的请求意外写回数据库。

## 2. 结果真值

| 结果 | 数据库语义 | 副作用 |
| --- | --- | --- |
| UPDATED | 有效差异与审计一次 commit 成功 | 只按实际差异触发 |
| ALREADY\_APPLIED | 数据库当前值已等于请求值，显式 rollback 释放锁 | 零 DML、零成功审计、零授权副作用 |
| CONFLICT | 当前值同时不同于页面原值和请求值，整体拒绝 | 不覆盖、不部分保存 |
| FAILED | 授权、存在性、理由或 flush 确定失败 | 全部 rollback |
| COMMIT\_UNKNOWN | 进入 commit 后异常，应用不猜测最终状态 | 不自动重试；授权尝试 best-effort 失效缓存 |

## 4. 专业评估

**准确性：A。**实现逐项对应 D1c、D5、D6a、D7、D8，没有把页面快照误当授权，也没有把 SQLite 测试等价为 MySQL 行锁证据。

**专业性：A。**锁顺序、授权再验证、业务/审计原子性、明确冲突和 commit unknown 符合低并发管理写入的工程实践，审计采用正向字段白名单。

**合理性：A。**管理用户量与审批并发低，真实写入才锁少量用户/关系/业务组行；no-op 仍在 U1 写前短路。性能成本与一致性收益匹配。

## 5. 残余边界

U2 只完成后端写边界。U3 仍需实现前端 no-op 不发 POST、邮箱清空必填理由 CpModal、各 outcome 的稳定留页/跳转、审计 JSON 安全渲染及最终浏览器矩阵。多 worker 缓存仍保留既有 120 秒 TTL 安全网，不在本方案扩展为共享即时撤权。
