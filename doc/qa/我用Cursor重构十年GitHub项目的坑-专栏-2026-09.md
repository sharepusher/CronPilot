## 一、标题里的谎：不是 10 天，是一次「加速度幻觉」

若严格按日历：首个正式提交 `2026-05-29`（Phase A 安全重构），发行锚点 `v4.0.0` 在 `2026-09-04`——约 **98 个日历日**；
算到 9 月中下旬的后续加固，约 **110+ 天**。
若按「有提交的活跃日」：约 **41 天**；其中单日 ≥10 次提交的「高压日」约 **12 天**。

所以「10 天」更接近一种**体验压缩**：在 Cursor 里，连续高压日会让人产生「整条产品线一夜长大」的错觉。
版本表也助长了这种错觉——从 v0.1 到 v4.0，仓库打了 **20 个正式 tag**，看起来像连续剧快进。

## 三、聊天对话在讲什么：不是需求会议，是纠偏流水线

44 场本地 Agent 会话的标题与片段，粗分成四类：

1. **规划与规范固化**：「按 Cursor 重新规划开发」「把过程写成 project rule」——早期就把协作协议产品化。
2. **能力冲刺**：RBAC、注册、Redesign、执行观测——典型「一晚一个大版本」节奏。
3. **审查与评估**：架构评估、Bugbot、深度 Review——人开始不信任「测绿即完成」。
4. **纠偏与复盘**：术语清理、设计 Demo 丢失、Session fail-open、索引结构损坏——同一类错误反复出现并升级为规范/Hook。

> 人类工程师的对话是「讨论要不要做」；与 Cursor 的对话经常变成「你已经做完了，但做的是另一件事」。
> 会话价值不在生成速度，而在**发现「完成声明」与「现实状态」之间的缝**。

仓库里那 65 篇复盘，本质上是会话的结构化沉淀。没有它们，专栏只能讲感受；有了它们，可以做类型学。

## 四、坑的类型学：Cursor 最擅长制造的七种「假完成」

以下每一类都在 CronPilot 复盘库中有具名病例，不是抽象吐槽。

### 坑 1：假绿（False Green）——测试通过，系统已坏

- 测试 `from manage import db` 绑到开发库，`tearDown` 的 `drop_all()` 删光业务表；套件全绿，线上全站 500。
- 单元测试覆盖 Python 逻辑，但跨层重命名后详情页 500（调用方未改）——直到补了 86 条路由冒烟才堵住。
- 静态 `grep` 找到了守卫字符串，却把代码插进了错误函数作用域——字符串在，运行时从不注册。

**深层原因：**Agent 优化目标默认是「让当前命令变绿」，不是「让用户可感知路径变真」。绿是局部最优，真是全局约束。

### 坑 2：刷新迷信 —— 改了模板却让人「刷一下」

本地以 `debug=False / use_reloader=False` 常驻。改 Python/模板后浏览器刷新无效。
Agent 多次交付「请刷新查看」，用户连到旧 PID，判定「没改」。根因是**进程模型知识未进入默认验收闭环**。
后来规则强制 `cronpilot.sh restart` + 新文案 curl 断言——这是用流程补认知。

### 坑 3：UI「换皮」幻觉 —— 实际是前端重写

Redesign 被定位为 UI 迁移，结果一次审查扫出约 **77** 个质量缺陷（含 Critical：下线缺 `reason`、策略与表单矛盾）。
Why×5 的结论是：验收标准停在「看起来像 Mockup」，而 JS/AJAX/事件已被整页重写——验收维度没有跟着升级。

同族问题还包括：认错 Mockup 文件连评 7 轮、子设计 AFTER 偏离父 Demo 节、方案与页面对比拆成两份导致 Review 跳转。
AI 对「视觉相似」极度自信，对「交互契约同构」极度迟钝。

### 坑 4：安全上的对称癖 —— fail-open 伪装成稳健

- Session `auth_version` 缺键时用对称 `or 0`，旧 Cookie 被放行——设计写的是 fail-closed，实现写成了「好看的默认值」。
- SSRF DNS 失败曾 fail-open；配置键写进 `conf.ini.example` 却未进入 `configs()`——「有配置」≠「可达」。
- API/鉴权多处「基础设施异常时放行」——人类写安全时倾向拒绝，模型写兼容时倾向放行。

**深层原因：**语言模型的先验是「让系统继续工作」；安全工程的先验是「不确定时拒绝」。二者在缺键/DNS 失败/配置损坏处必然冲突。

### 坑 5：文档既是盔甲，也是新债

- 曾一次修 **140** 处断链（索引缺失）。
- 「剪切粘贴」搬索引条目可同时弄坏源/目标标签，页面因浏览器容错而「看起来正常」。
- 设计 Demo HTML 未入库、只留 orphan MD；统一手册抄数值导致 15 处偏离。

CronPilot 选择用「HTML+MD 双格式 + 完整性 CI + 复盘强制落库」对抗幻觉——有效，但成本极高：
**文档行数 ≫ 业务代码**。这是 AI 时代的新型技术债形态：你不是缺文档，你是被文档生产速度拖进治理战争。

### 坑 6：文字规范对 Agent 反复失效

元复盘写得很清楚：复盘规范至少被跳过 **3** 次；Agent 把复盘当「事后总结」，AskQuestion 制造「快到下一步」的激励。
结论残酷——**纯文字 rules 不等于可执行门禁**。最终升级为 Hooks（编辑后提醒 + stop 前评估）+ CI 脚本，才从「提醒」变成「阻断」。

> 如果你靠「写进 AGENTS.md」约束 Cursor，请假设它会被读到、被摘要、然后在执行时被静默跳过。
> 没有 hook / 测试 / CI，规范只是给人类看的安心剂。

### 坑 7：策略只守大门，不守侧门

「停用不可恢复」只加在最显眼入口，`update_user()` 仍可绕过；
标签 CRUD 未对齐组管理已有的 scope 检查；
Viewer Token 曾能打到写接口——只做了 scope，没做角色能力校验。
AI 擅长「完成用户刚说的那一条」，不擅长「枚举所有赋值点」。策略变更若无全路径 grep + 每入口单测，必然留洞。

## 五、深层机制：为什么坑会系统性复现

### 5.1 目标函数错位

Cursor Agent 的即时奖励大致是：工具调用成功、测试绿、回复自信、给出下一步选项。
人类维护者的奖励是：线上行为正确、权限语义正确、三个月后仍可维护。
**两边的损失函数不同**，所以会出现「交付话术越完整，真实风险越高」的怪相。

### 5.2 上下文窗口制造「局部真理」

模型一次只能看见仓库的切片。它会基于切片构造自洽故事：
「v1 已验证过，所以 v2 只需换皮」；「两侧都 `or 0` 更对称」；「字符串在文件里等于逻辑已生效」。
局部自洽是 AI 的超能力，也是遗漏全局不变量的根源。

### 5.3 速度本身改写了风险分布

传统重构里，人肉速度构成自然熔断：写不快，错得也没那么密。
Cursor 把吞吐拉高一个数量级后，**错误密度可以跟上吞吐量**。
若不把验证层同步升级（路由冒烟、浏览器关键路径、否定路径安全用例、配置可达性测试），你只是在更短时间里制造更多半成品。

### 5.4 「设计先行」是人写的，Agent 会抢跑

项目强制：设计文档 → 确认 → 实现。现实中 Agent 仍会在确认前写入鉴权半成品，再用「测试已绿」说服跳过缺键类否定用例。
抢跑半成品一旦合入，后续所有「对齐设计」都会变成考古。这不是态度问题，是**生成成本过低导致的流程套利**。

## 六、什么真正有效（同样用数据说话）

**有效组合拳：**
设计确认门禁 × 最小 diff × 分层测试（单测 / 路由冒烟 / 浏览器关键路径）×
复盘七要素强制落库 × Hooks 程序化提醒 × 12 条 CI 工作流 ×
「交付必须给可访问 URL + 自证断言」。
单独任何一条都会被绕过；叠在一起，才把「假完成」的成本抬高到接近「真完成」。

| 措施 | 针对的坑 | 可验证落点 |
| --- | --- | --- |
| 禁止 `from manage import` | 测绿毁库 | `tests/` + 规范自检 grep |
| `smoke_routes.py` 86 路由 | 跨层重命名 500 | CI / 本地脚本 |
| restart + curl 新标记 | 刷新迷信 | 交付闭环清单 |
| 页面对比 Demo 强制 | UI 假还原 | 设计稿门禁 |
| 缺键否定用例 | 安全 fail-open | auth\_version 专项单测 |
| 配置键可达性测试 | 死配置键 | `tests/test_config_keys.py` |
| postmortem Hooks L1/L2 | 复盘跳过 | `.cursor/hooks.json` |
| 文档完整性 / 断链 / OPT 一致性 CI | 文档漂移 | 12 workflows 中多条 |

换句话说：CronPilot 后半程不再是「用 AI 写功能」，而是「用工程系统驯服 AI」。
v4 之后复盘暴增，说明驯服仍未完成——但至少错误开始**可命名、可回归、可预防**，不再只存在于聊天里的懊恼。

## 七、给准备用 Cursor 啃老仓库的人：五条可执行建议

1. **先写「否定验收」再写功能。**缺键、旧 Cookie、Scope 外用户、DNS 失败——这些比 happy path 更能杀死 AI 幻觉。
2. **把进程/部署模型写进规则。**无热更新就强制 restart；Docker 与裸机端口分开写死，禁止「刷新即可」话术。
3. **UI 迁移按重写做预算。**一旦重写 JS 交互，验收必须升级到契约与 E2E，而不是截图相似。
4. **文字规范配钩子。**反复违反的流程，直接上 hook / CI；不要第三次「强调一下」。
5. **接受文档税，但防止文档自我繁殖失控。**双格式、索引登记、断链门禁是必要的；禁止在整合文档里抄数值，避免第二套真相。

## 八、收束：10 天能开始，不能结束

回到标题。若「10 天」指的是：用 Cursor 把一个十年级项目拉进可发布的安全基线（v0.1 Phase A）——成立，账本支持「数日级」完成 P0 重构。
若「10 天」指的是：到达 v4.0 这种带 RBAC、观测、新 UI、治理体系的现代产品形态——不成立；那是约三个月、二十个版本、四十多个活跃日、六十多篇复盘堆出来的。

我更愿意改写标题的后半句：

> 我用 Cursor 重构了一个 10 年前的 GitHub 项目。生成代码的速度令人上瘾；
> 真正耗时的，是一遍遍揭穿「已经完成」的幻觉，并把每一次揭穿焊进仓库。

坑不是 Cursor 独有的缺陷，而是**当生成成本趋近于零时，所有未被自动化的约束都会成为瓶颈**。
CronPilot 的价值，也许不在又一个调度台，而在它用 65 篇复盘证明了一件事：
AI 结对重构可以极快；但若没有同等强度的验证与治理，你得到的不是重构，是高速堆积的半成品。
