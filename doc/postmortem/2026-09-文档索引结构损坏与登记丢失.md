# 2026-09 文档索引结构损坏与登记丢失复盘

**日期**：2026-09-11　**发现方式**：提交前逐主题审查未提交改动时自查发现

## 1. Bug 定位

| # | 位置 | 现象 |
| --- | --- | --- |
| 1 | `doc/index.html` 复盘列表（原第 1125–1127 行） | `<li>` 之后出现 `<div <li>`：一段 `<li>` + `<div`  文本被剪贴到此处，HTML 解析器把 `<li` 当成 `<div>` 的属性名 |
| 2 | `doc/index.html`（原第 1167 行） | 「全面 Code Review 复盘」条目丢失 `<li><div`  开标签，只剩裸露的 `class="title">` 文本 |
| 3 | `doc/index.html` / `doc/index.md` | `design/测试Session补齐auth-version修复设计.html` 的整条登记被删除，文件仍存在 → `check_doc_completeness.py` 报 UNREGISTERED |
| 4 | `doc/postmortem/index.md` | 丢失「停用用户同名覆盖启用（OPT-P0-22）」一行，而 `index.html` 仍有该条目，两边不一致 |
| 5 | `doc/postmortem/index.html` / `index.md` | 附带发现：篇数声明「共 33 篇」与实际 35 个文件不符；`2026-08-调度器幽灵任务清理复盘.html` 在 MD 侧从未登记（HEAD 即缺失） |

## 2. 根因

重排 1200 行索引页时采用「剪切一段 `<li>` 块 → 粘到新位置」的手工搬运方式，剪切边界落在 `<li>` 与 `<div class="title">` 之间，于是同一段文本既在原位少了开标签、又在目标位置多了半截开标签。

行为层原因是这类破坏在编辑环节没有任何反馈信号：浏览器与 `markdownify` 对不配对标签都容错，页面渲染看起来正常；唯一的文档门禁 `check_doc_completeness.py` 只用正则提取 `href` 集合，对标签结构完全不敏感。登记丢失（#3）本可被该门禁捕获，但门禁只在 `doc-completeness.yml` 的 push / PR 事件运行，编辑当时不会报警，而编辑后也没有在本地跑过它。

归纳：**结构类破坏无门禁；登记类破坏有门禁但不在编辑环节执行。**

## 3. 测试漏洞

| 门禁 | 为何没发现 |
| --- | --- |
| `scripts/check_doc_completeness.py` | 只做 href 集合比对，无任何标签配对校验 → 结构损坏 100% 漏过 |
| `scripts/check_postmortem_completeness.py` | 只校验「HTML 有无同名 MD」和「是否被 RELEASE\_NOTES 引用」，不校验两个索引页登记是否齐全、篇数声明是否准确；且该脚本未接入任何 workflow，即使有规则也不会在 CI 运行 |
| `scripts/html_docs_to_markdown.py --check` | MD 由损坏的 HTML 生成，两边天然一致 → 同步门禁无法发现源文件结构问题 |

## 4. 修复

四处最小 diff，不改动其他条目：还原第 1 处被剪贴进来的半截开标签；补回第 2 处的 `<li><div class="title">`；在 OPT-P0-22 条目后重新登记「测试 Session 补齐 auth\_version 修复设计」（HTML + MD 各一条）；补回 `doc/postmortem/index.md` 丢失的 OPT-P0-22 复盘行、补登「调度器幽灵任务清理复盘」并把篇数声明改为实际值。

## 5. 防护测试

`scripts/check_doc_completeness.py` 新增两项检查，并由 `tests/test_check_doc_completeness.py` 锁定行为：

| 用例 | 断言 |
| --- | --- |
| `test_detects_cut_paste_corruption` | 把本次事故原文作为夹具，必须同时报出「剪贴断裂」「裸露的属性文本」「不配对」 |
| `test_accepts_well_formed_list` | 结构完好的列表零告警 |
| `test_detects_unclosed_block_tag` | `<li>` 未闭合被检出 |
| `test_ignores_attribute_text_inside_code_samples` | `<pre>` / `<code>` 内的代码示例不误报 |

另有 `check_postmortem_index_pair()` 校验每篇复盘同时登记在 `index.html` 与 `index.md`，且「共 N 篇」与文件数一致——该检查在修复过程中直接命中了第 5 组遗留问题。

## 6. 同类排查

用新校验器扫描全部 `doc/**/*.html`（排除 `_pending_sync`）：首轮报出 11 个文件，逐一核查后确认全部是 `<pre>` / `<code>` 内展示用代码片段的误报（例如 `2026-08-missing-route-decorator.html` 中作为示例展示的 `href="{{ url_for(...) }}"`）。据此为校验器加入原始文本容器排除，再次全量扫描结果为 **0 个文件存在结构问题**，说明本次两处剪贴断裂是全仓唯一实例，其余索引与设计稿标签配对完好。

## 7. 预防方案

| 措施 | 落地位置 | 验证命令 |
| --- | --- | --- |
| `check_index_structure()`：对手工维护索引页做块级标签配对 + 裸属性残留校验 | `scripts/check_doc_completeness.py`（已被 `.github/workflows/doc-completeness.yml` 在 `doc/**` 变更时执行，PR 阶段即拦截） | `python scripts/check_doc_completeness.py --check` |
| `check_postmortem_index_pair()`：复盘 HTML/MD 双索引登记 + 篇数声明一致性 | 同上 | 同上 |
| 校验器行为单测（含事故原文夹具） | `tests/test_check_doc_completeness.py`，随 `unittest discover` 进入 `unit-tests.yml` | `python -m unittest tests.test_check_doc_completeness -v` |
| 规范条目：索引条目搬运禁止「剪切 + 粘贴」，须先在目标位置写完整 `<li>` 块、再删除源块；编辑后必须在本地跑上述两条命令 | `.cursor/rules/cronpilot-documentation.mdc` + `AGENTS.md` | 见上两条命令 |
