# 传输状态机与 Run Inspector 展示收口

入口：[专业 Review 评估](执行侧观测近期提交专业Review评估-2026-09-18.html) F1–F4 / F6。父语义：[失败分类与 HTTP 响应语义](执行侧观测-失败分类与HTTP响应语义优化设计-2026-09.html)。**页面对比**见 [§5](#page-compare)。

**抢跑说明：**工作区已有未提交半成品（`exception_failure_info` 区分 Connect/Read、`run_inspector.html` 部分文案分支）。确认本设计后，以本文为唯一准绳重审半成品；不得以「测试已绿」跳过文末验收矩阵。

## 1. 问题

| ID | 现象 | 用户影响 |
| --- | --- | --- |
| F1 | 凡请求调用开始后失败（含 ReadTimeout）均写 `failed_before_response`，页面写「未建立连接」。 | 读超时被误判为根本没连上。 |
| F2 | `actual_request_sent` 认 `sent|response_received`，但终态从不写 `sent`。 | 布尔与枚举文档脱节；成功才显示「已发送并收到响应」。 |
| F3 | Presenter 已算 `http_status_label`，meta 仍渲染 `http_status`（多为 —）。 | 无响应场景缺少可读说明。 |
| F4 | 模型声明 `Unique(run_id,seq)`，存量库仅有非唯一索引。 | 新建/存量约束漂移（风险低）。 |
| F6 | 外层 fatal 默认 `pre_request/not_started`。 | 中段 fatal 可能被标成请求前置。 |

## 2. 根因

- 父设计把超时/连接失败折叠进同一终态 `failed_before_response`，并配「未建立连接」文案，未区分「连接前失败」与「已发起后无响应」。
- 枚举含过渡态 `sent`，但 JobLog 只落终态；Presenter 仍按过渡态判定「已发送」。
- 模板与 Presenter 字段未做「算了就渲染」门禁。

## 3. 方案

### 3.1 推荐：终态枚举拆分 + 展示契约对齐

**JobLog.transport\_state 终态（写入库）：**

| 值 | 何时写入 | 页面「传输状态」文案 |
| --- | --- | --- |
| `not_started` | 未准备请求目标 | （请求区不展示传输行，或「未开始」） |
| `prepared` | 已注入参数，尚未调用 `_http.get/post` | 已准备，尚未确认发送 |
| `client_failed` | 客户端初始化失败（如 assert\_hostname TypeError），请求栈未真正发出 | 客户端初始化失败 |
| `connect_failed` | ConnectTimeout / ConnectionError / SSLError / TooManyRedirects | 连接未建立 |
| `sent_no_response` | ReadTimeout 或通用 Timeout（无法证明仅连接阶段） | 已发起，未收到响应 |
| `response_received` | 获得 HTTP response object | 已发送并收到响应 |
| `failed_before_response` | 仅作**历史兼容/未知兜底**；新写入尽量不用 | 未确认发送 |

**明确不做：**不在 JobLog 终态写入过渡值 `sent`（事件 `http.start` 的 detail 仍可用 `prepared` 表示「即将发送」）。文档与模型 doc 同步删除「终态含 sent」表述，或标注「仅事件过程态，不入库终态」。

**Presenter 契约：**

- `actual_request_sent` 仅当 `transport_state == 'response_received'`（且 admin）为 true → 模板「已发送并收到响应」。
- 其余态走模板显式分支（上表）；`client_failed` / `unknown_failure`（若保留）必须有分支，禁止落入「连接未建立」。
- meta 行：`HTTP <strong>{{ run.summary.http_status_label }}</strong>`（关闭 F3）。

**分类函数：**`exception_failure_info(exc)` 必须返回三元组 `failure_stage` / `fail_reason` / `transport_state`。映射表：

| 异常 | fail\_reason | transport\_state |
| --- | --- | --- |
| `ReadTimeout` | timeout | sent\_no\_response |
| `ConnectTimeout` | timeout | connect\_failed |
| `Timeout`（基类，非上两者） | timeout | sent\_no\_response（保守：不宣称「未连接」） |
| ConnectionError / SSLError / TooManyRedirects | connection | connect\_failed |
| TypeError + assert\_hostname | client\_incompatible | client\_failed |
| 其他 | internal | 若已 `_request_call_started` → `sent_no_response`；否则 `prepared` 或 `client_failed` 按能否证明调用边界 |

`cron_do`：已发起请求时采用 `failure_info['transport_state']`；未发起时写 `prepared`（或 client\_failed）。外层 fatal（F6）：若已有 `saved_jl`/trace 且越过 prepared，写 `failure_stage=transport`（或 `persistence` 若异常在写库），禁止默认 `pre_request`。

### 3.2 备选（不推荐）

仅改正文案、不拆枚举：无法支撑筛选/API/事件 detail 同源，拒绝。

### 3.3 F4（观察项，可同轮或下轮）

在 `ensure_business_tables` 幂等尝试创建 unique `(run_id, seq)`（SQLite 多 NULL 可共存；MySQL 注意 NULL 语义）。若存量有冲突数据，先报告计数再决定是否跳过。本轮默认：**检查脚本 + 文档记录**，不强行破坏性建约束，除非验收证明无冲突。

## 5. 页面对比（Run Inspector · 强制）

示意：同一任务两次超时失败 — ConnectTimeout vs ReadTimeout。列结构与父 Demo 请求/响应区同构，仅传输状态与 HTTP 摘要文案变化。

#### BEFORE · 当前（折叠态）

结果 超时 · 失败阶段：传输层 · 失败原因：请求超时

HTTP **—**

请求　GET https://api.example.com/hook

参数准备　已注入 trace\_id / sign

传输状态　未建立连接 · 未确认发送（Connect 与 Read 相同）

响应　HTTP 响应：（空白 / —）

#### AFTER · 目标

结果 超时 · 失败阶段：传输层 · 失败原因：请求超时

HTTP **未获得 HTTP 响应**

请求　GET https://api.example.com/hook

参数准备　已注入 trace\_id / sign

ConnectTimeout → 传输状态　连接未建立

ReadTimeout → 传输状态　已发起，未收到响应

响应　HTTP 响应：未获得 HTTP 响应

| 可见变更 | 旧 → 新 |
| --- | --- |
| 请求区传输状态文案 | 「未建立连接 · 未确认发送」→ 按态拆分为「连接未建立」/「已发起，未收到响应」/「客户端初始化失败」/「未确认发送」（兜底） |
| meta HTTP | `http_status`（—）→ `http_status_label`（未获得 HTTP 响应） |
| 列数 / 按钮 | 不变 |
| 新增 CSS class | 无（复用现有 `ri-*`） |

```
.venv-py311/bin/python -m unittest \
  tests.test_job_log_outcome \

  tests.test_execution_tracer -v

```

- ConnectTimeout → JobLog.transport\_state=`connect_failed` → 文案「连接未建立」
- ReadTimeout → `sent_no_response` → 「已发起，未收到响应」
- client\_incompatible → `client_failed` → 「客户端初始化失败」（不得显示「连接未建立」）
- `actual_request_sent` 仅 response\_received 为 true
- 模板存在 `http_status_label`；不存在把 ReadTimeout 映射到「连接未建立」的分支
