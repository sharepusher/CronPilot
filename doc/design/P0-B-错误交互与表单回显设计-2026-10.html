1. 问题、目标与范围

Ajax、普通 POST、网络异常和非 JSON 响应各自处理；失败可能被误作成功跳转，字段错误与全局错误冲突，普通表单失败可能丢失输入。目标是以 P1-A2 安全错误对象统一呈现，但保留 SSR 和原生 form 语义；不建设 SPA、不展示原始 exception、不把双模式 POST 强制纳入 request_id。

2. Before / After 交互示意（B-0 仍须真实页面）

BEFORE

各页面分别处理失败，现状待 B-0 截图核实。

AFTER：字段校验失败

任务名称：每日同步

名称冲突，请修改。

保留非敏感输入，焦点移至首个错误字段，不显示全局弹窗。

AFTER：已确认业务失败（独立场景）

任务未保存，请核对后重试。

仅显示一个全局错误，关闭后恢复触发点焦点。

AFTER：结果未知（独立场景）

未收到处理结果，请先查询当前状态，避免重复提交。

不判定保存失败，不自动重试写请求。

3. 交互流程与规则

请求 → P1-A2 响应/网络异常 → 验证 JSON → 按 code 分类 → 字段错误内联或全局错误或结果未知 → 按场景管理焦点与后续操作。成功才允许刷新、跳转或 Toast；失败响应的 url 永不自动消费。

  • VALIDATION_* 映射已登记 input，未知字段安全回退全局错误。
  • 普通 POST 失败回渲染同一模板，保留非敏感值；密码、token、sign 清空。
  • 超时、断网、无法解释的非 JSON 响应归为结果未知；组件可复用，但不显示已确认失败文案、不自动重试写操作。登录失效等可明确识别的响应按已登记认证行为处理。
  • Redesign 使用 CpModal/CpConfirm，不使用 Bootstrap，不插入不可信 HTML。

4. 分批、验收与风险

批次退出条件
B-1共享映射器、字段映射登记、网络/非 JSON 适配和单测。
B-2一个 Ajax 页面与一个普通 form 垂直接入；失败回显、成功跳转、目标角色浏览器验证。
B-3按资源组迁移；每页 Before/After、正反向路径和截图完成。

必须验证键盘焦点、Esc/关闭、屏幕阅读器标题、复制仅复制关联号、防重复提交、无权限、超时和非 JSON。共享组件风险以一页一批控制；UI 可只回滚本批渲染分支，后端协议不随 UI 回滚。

5. 确认点

确认后先选择 B-2 的两条具体页面路径，补齐字段映射与真实页面对比，再单独申请实现授权。

6. 实施范围冻结

根因：当前失败呈现分散在页面脚本、普通 POST 回渲染和 JSON helper 中；响应形状、字段名、跳转和焦点规则未形成按页面验证的契约。第 2 节仅是交互规则示意，不是任何现有页面的 Before/After 实施稿，不能据此改模板或 JS。

B-0 前置清单：先为首个候选页面记录路由、模板、JS、提交方式、字段名、现有错误分支、目标角色、错误码与真实 Before 截图；再给出与该页一一对应的 After、字段映射和浏览器验收脚本。该页面级补充经确认后，才可进入 B-1/B-2。未选择具体页面前，本设计仅授权准备共享规则，不授权 UI 实现。

关联号、用例与实施产物

required JSON 仅展示与 Header 一致的 body trace_id；原生 form/豁免 JSON 无该字段时不展示复制关联号按钮。无响应时若展示客户端已生成 ID，必须标注“本次请求号（结果未确认）”，不能冒充服务端错误号。request_id 无幂等能力。只读查询可按页面策略重试；写入必须先核实状态并由用户明确再次提交。

B-01：字段错误与全局错误分别触发，断言互斥、焦点和输入回显。B-02：模拟服务端写入已完成但响应丢失，不自动二次提交。B-03：原生 form 无 trace、敏感字段清空、未知字段转全局、目标角色权限正反向与防重提交。B-0 产出 doc/design/error-ui-page-baseline.html 及真实页面对比，B-2 产出 doc/qa/error-ui-acceptance.html，逐条记录浏览器操作/网络断言/截图；上述文件尚未创建，不能声称 UI 验收通过。
