### 1.1 定位与价值

**CronPilot（CronPilot管理）** 是一套基于 Python Flask + APScheduler 的**轻量级分布式定时任务调度平台**。它将传统 Linux Crontab 的能力产品化：通过 Web 可视化界面或 REST API 统一管理定时任务，在触发时刻向业务系统发起 HTTP GET 回调，并记录执行日志、异常告警。

典型场景：每月还款提醒、每日凌晨数据清理、周期性健康检查、异步长任务的执行进度回传等。

### 1.2 核心特性（源码印证）

| 特性 | 实现要点 | 源码位置 |
| --- | --- | --- |
| Crontab 兼容 | 支持 day / day\_of\_week / hour / minute / second，含 `*/n`、区间、枚举 | `app/main/views.py` 校验逻辑 |
| 秒级调度 | `is_dev=0` 时启用 second 字段；体验版禁用 | `conf.example.ini`、`cron_add.html` |
| 一次性任务 | `trigger=date` + `run_date` | `app/crons.py`、views |
| 集群部署 | Redis 分布式锁 + portalocker 文件锁 + MySQL JobStore | `app/common/functions.py`、`CuBackgroundScheduler.py` |
| API 动态管理 | `/api/cron` 增改、`/api/cron/status` 启停 | `app/api/views.py` |
| 执行日志 | 主日志 `job_log` + 明细 `job_log_items` | `datas/model/` |

| 回调签名 | `cronpilot_sign` MD5 签名校验 | `get_cronpilot_sign()` |

### 4.2 表结构

#### cron\_infos — 定时任务定义

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 主键，对应调度 Job ID：`cron_{id}` |
| task\_name | VARCHAR(120) | 任务名称，全局唯一 |
| task\_keyword | VARCHAR(500) | 备注/说明；**必填** 1～500 字（LIFECYCLE-2；存量空允许运行，下次编辑须补全） |
| run\_date | VARCHAR(25) | 一次性执行时间（date 触发器） |
| day\_of\_week | VARCHAR(10) | 星期：0-6 或 mon-sun，支持 \*/n、区间、枚举 |
| day | VARCHAR(20) | 日：1-31，同上表达式 |
| hour / minute / second | VARCHAR(10) | 时/分/秒 Cron 表达式片段 |
| req\_url | VARCHAR(200) | 回调 URL（GET） |
| status | SMALLINT | 0=暂停，1=运行中，-1=已下线（不可逆） |
| created\_at | VARCHAR(25) | 创建时间（LIFECYCLE-2） |
| updated\_at | VARCHAR(25) | 最后配置编辑时间；暂停/下线不刷（LIFECYCLE-2） |
| retire\_reason | VARCHAR(500) | 下线原因；人工必填 1～500 字（与说明同长；LIFECYCLE-2） |
| retired\_at | VARCHAR(25) | 下线时刻（LIFECYCLE-2） |

LIFECYCLE-2 字段权威说明见 [任务生命周期 §四](任务生命周期与无删除设计.html#lifecycle-2)。完整变更历史不另建表，走 OPT-P1-09 `operation_log`。

#### job\_log — 执行主日志

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自增主键 |
| log\_id | VARCHAR(65) INDEX | UUID，回调时传给业务方，用于回传明细 |
| cron\_info\_id | INTEGER INDEX | 关联任务 |
| content | TEXT | HTTP 响应体或错误信息 |
| create\_time | VARCHAR(25) | 执行时间 |
| take\_time | VARCHAR(25) | 耗时（秒） |

#### job\_log\_items — 执行明细（可选）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | INTEGER PK | 自增 |

| content | TEXT | 业务方通过 API 上传的进度/明细 |

**数据保留策略：**内置任务 `cron_del_job_log` 每 8 小时执行，按 `job_log_counts`（默认 1000）按任务维度删除超额历史记录。

## 5. 调度引擎设计

### 5.1 任务生命周期

创建/编辑 ──► scheduler.add\_job("cron\_{id}", cron\_do, trigger=cron|date)
│
┌──────────┼──────────┐
▼ ▼ ▼
运行中(1) 已停止(0) 已结束(-1)
│ │ │
resume\_job pause\_job remove\_job (date 到期)
│ │ │
└──────────┴──────────┘
│
cron\_do 触发
▼
requests.get(req\_url, params={log\_id, sign})
▼
写入 job\_log + 错误关键词检测 ──► 多渠道通知

### 5.2 触发器映射规则

| 模式 | 条件 | APScheduler trigger |
| --- | --- | --- |
| 一次性 | `run_date` 非空 | `date`，`run_date=...` |
| 周期 | 填写 day/day\_of\_week/hour/minute/second 至少一项 | `cron`，各字段透传 |
| 体验版 | `is_dev=1` | 强制清空 `second` |

### 5.3 集群与高可用

#### 文件锁（进程级）

`CuBackgroundScheduler._process_jobs()` 使用 `portalocker` 对 `scheduler.lock` 加非阻塞排他锁。同一机器多 worker 仅一个进程拉取到期任务。

#### Redis 锁（节点级）

`@single_task()` 装饰器在 `is_single=0` 时，以 `task:{func}:{cron_id}` 为 key，TTL 120s，保证集群中同一任务同一时刻只执行一次。

### 5.4 内置维护任务（config.py JOBS）

| Job ID | 周期 | 功能 |
| --- | --- | --- |
| cron\_check | 每 30 分钟 | 校验 apscheduler\_jobs 与 cron\_infos 一致性，缺失则 status=-1 |
| cron\_del\_job\_log | 每 8 小时 | 按配置条数清理 job\_log |
| cron\_check\_db\_sleep | 每 15 秒 | SELECT 1 探活，失败则告警 |

### 5.5 任务执行时序（cron\_do）

1查询 CronInfos，校验 req\_url

2生成 UUID 作为 cronpilot\_log\_id

3解析 URL 已有参数，计算 cronpilot\_sign（MD5，参数 ASCII 排序 + api\_key）

4GET 请求，User-Agent: CronPilot，超时 120s

5响应体检测 error\_keyword（逗号分隔，不区分大小写）→ 触发 wechat\_info\_err

6写入 JobLog（content、take\_time、log\_id）

## 6. API 接口规范

统一响应格式（`datas/utils/json.py`）：`{ "errcode": 0|1, "errmsg": "...", "data": ... }`

### 6.1 POST/GET /api/cron — 添加或更新任务

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| access\_token | 配置后必填 | 与 conf.ini api\_access\_token 一致 |
| task\_name | 是 | 唯一键；存在则更新，不存在则创建 |
| req\_url | 是 | http(s) 回调地址 |
| run\_date | 二选一 | 有值则 date 模式 |
| day, day\_of\_week, hour, minute, second | 二选一 | Cron 模式字段 |
| task\_keyword | 是 | 备注/说明（LIFECYCLE-2；1～500 字） |

```
curl -X POST "http://host/api/cron" \
  -d "access_token=abcdabcd" \
  -d "task_name=daily_cleanup" \
  -d "task_keyword=夜间清理·运维" \
  -d "hour=2" -d "minute=0" \
  -d "req_url=https://api.example.com/cron/cleanup"
```

### 6.2 /api/cron/status — 启停任务

| 参数 | 说明 |
| --- | --- |
| task\_name | 任务名称 |
| status | 0=关闭，1=开启；不传则 toggle |

### 6.2b /api/cron/retire — 下线任务（不可逆）

| 参数 | 必填 | 说明 |
| --- | --- | --- |
| task\_name | 是 | 任务名称 |
| reason | 是 | 下线原因（LIFECYCLE-2 · 1～500 字） |
| access\_token | 配置后必填 | 与 conf.ini 一致 |

写 `status=-1` 及 `retire_reason` / `retired_at`（LIFECYCLE-2；无 `retired_by`）。详见 [生命周期设计](任务生命周期与无删除设计.html#lifecycle-2)。

### 6.3 /api/cron/add\_log — 上传执行明细

业务系统在收到 `cronpilot_log_id` 后，长任务执行过程中可多次调用，将进度写入 job\_log\_items。

```
curl -X POST "http://host/api/cron/add_log" \
  -d "access_token=abcdabcd" \
  -d "cronpilot_log_id=uuid-from-callback" \
  -d "content=步骤3/5 数据处理完成"
```

### 6.4 回调签名算法

1. 收集回调 URL 已有 query 参数 + `cronpilot_log_id`
2. 按参数名 ASCII 升序排列
3. 拼接为 `key1=val1&&key2=val2&&...&&api_key={api_key}`
4. 对拼接串做 MD5 → `cronpilot_sign`

前端参考：`app/static/js/signs.js`、`md5.js`

## 7. 安全与鉴权

| 机制 | 实现 | 风险与建议 |
| --- | --- | --- |
| Web 登录 | Session `is_login` + 单密码 conf.ini login\_pwd | 无用户名、无 bcrypt；建议生产改用哈希存储 + HTTPS |
| API Token | access\_token 可选校验 | 明文配置；建议环境变量注入 |
| 回调签名 | api\_key + MD5 | 业务方验签防伪造；api\_key 为空则不签名 |
| SQL | 部分 raw SQL 字符串拼接（delete） | 存在注入风险，建议改为 ORM 参数化 |
| 体验模式 | is\_dev=1 时登录页显示明文密码 | 仅用于演示环境 |

## 12. 专业评估与改进建议

### 12.1 优势

- 功能闭环完整：配置 → 调度 → 回调 → 日志 → 告警 → API 集成
- Cron 表达式校验详尽，与 APScheduler 语义对齐
- 集群场景考虑周全（双锁机制 + JobStore 持久化）
- 部署门槛低，Docker 开箱即用

### 12.2 技术债与风险

- 安全 单密码 Session、SQL 拼接；Flask 1.1 / SA 1.4 仍待 Tier 3/4 代际升级；gunicorn 22 + gevent 23（RFC-2.1/2.2），路线见 [依赖升级 RFC](依赖升级RFC.html)
- 代码 views.py 校验逻辑 Web/API 大量重复，维护成本高
- 前端 Jumbotron 每页重复、无组件化、响应式弱
- 架构 多 worker 各启 Scheduler，依赖锁而非单 leader 选举

### 12.3 优先级改进路线图

| 优先级 | 项 | 说明 |
| --- | --- | --- |
| P2 | 依赖升级（RFC） | 耦合从弱到强：Tier 0 `flask db` → Tier 1 SA 1.4 渐进 → Tier 2 gevent → Tier 3/4 SA2/Flask2；侧车 CVE 补丁。详 [依赖升级 RFC](依赖升级RFC.html) |
| P0 | SQL 参数化 | 替换 raw delete 语句（Phase A 部分已交付） |
| P1 | 校验逻辑抽取 | 独立 cron\_validator 模块，Web/API 共用 |
| P1 | 密码哈希 | werkzeug.security 或 bcrypt |
| P2 | 模板 partial | 抽取 header/nav 为 {% include %} |
| P2 | 统计 API + 仪表盘 | 提升运维可观测性 |
| P3 | 前端 SPA 重构 | Vue3 + Element Plus，对接现有 REST |
