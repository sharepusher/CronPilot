# 任务中心标题统计收敛

UX 已实施  
**日期**：2026-09-18  
**状态**：已实施；首屏与 AJAX 局部刷新均已验证  
**承接**：已实施的[《任务中心顶栏运行中/已暂停分列统计》§3.1.1](任务中心排除已下线任务统计与默认列表设计-2026-09.html#page-compare) AFTER；本稿仅收敛该标题统计行。

## 1. 问题

- 标题行展示“17 个任务”，与页面下方任务列表和状态筛选重复，不能帮助判断当前需要处理什么。
- “24 今日失败”与任务总数、任务状态混排在标题中；“今日失败”已有独立统计卡，标题重复且把执行结果与任务存量混为一行。

## 2. 根因

方案 E 为补足“运行中 / 已暂停”分列，将新字段追加到既有 `stat-line`，但保留了原有总任务数与今日失败。首屏渲染和 AJAX 刷新均拼接同一条完整统计串，因此信息架构在两个刷新路径中一致地过载。

## 3. 方案

### 3.1 推荐方案：标题只保留状态与需关注信号

将 `stat-line` 固定为：

> `运行中 <b>10</b> · 已暂停 <b>3</b> · <span>2</span> 持续异常 · <span>0</span> 逾期`

- 移除：**“N 个任务”**与**“N 今日失败”**，首屏与 AJAX 局部刷新必须同步移除。
- 保留：“运行中 / 已暂停”作为当前配置状态摘要；“持续异常 / 逾期”作为待关注信号。
- “今日失败”继续且只在下方“今日失败”统计卡中展示，保留其“0:00 以来 / 今日尚无执行记录”说明。

### 3.2 页面 Before / After 对比

**示意数据**：Scope 内共 17 个任务；运行中 10、已暂停 3；2 个持续异常、0 个逾期；今日 24 次失败。卡片与筛选 chip 的结构和样例均沿用父设计 §3.1.1 的 AFTER。

| 标题 `stat-line` | 总任务数 + 状态 + 风险 + 今日失败 | 状态 + 风险；不含总任务数、今日失败 |

| 筛选 chip / 列表 | 全部 / 运行中 / 已暂停 / 已下线 | 不变；不改变默认列表或筛选交互 |

### 3.3 交互与数据契约

- 不新增点击、链接、筛选或接口字段；仅消费现有 `running`、`paused`、`consecutive_failing`、`overdue_count`。
- 首屏模板与 `refreshStats()` 的 `statLine.innerHTML` 使用完全相同的四项和顺序，避免 AJAX 后旧文案回现。
- 状态与风险数字仍按当前 Scope 口径统计，不随用户选择的列表 status/health 筛选收缩。

## 4. 范围

| 路径 | 处理 |
| --- | --- |
| `app/templates/redesign/dashboard.html` | 修改标题首屏文本与 AJAX 标题拼接。 |
| 既有 Dashboard stats JSON | 不改字段、计算口径或 API 返回结构。 |
| 统计卡、异常面板、筛选 chip、任务表格 | 不改样式、文案、交互和查询逻辑。 |
| 不做 | 不隐藏“今日失败”卡；不新增“全部任务”卡；不调整响应式样式或数据模型。 |

## 5. 分批

| 批次 | 内容 | 独立验收 |
| --- | --- | --- |
| B1 | 将模板标题与 AJAX 拼接同步改为四项结构。 | 静态检查两处均不含“个任务”或“今日失败”。 |
| B2 | 补充模板/AJAX 回归断言。 | Stats payload 不变；标题结构与卡片结构分别断言。 |
| B3 | 重启后浏览器验证。 | 首屏与一次筛选 AJAX 刷新均显示四项标题；今日失败只出现在卡片。 |

## 6. 验收

1. 存在 17 个任务、24 次今日失败时，标题不出现“17 个任务”或“24 今日失败”。
2. 标题显示“运行中 10 · 已暂停 3 · 2 持续异常 · 0 逾期”（数值随实际数据变化）。
3. “今日失败”统计卡仍显示 24；当今日无执行记录时，卡片原有“— / 今日尚无执行记录”语义不变。
4. 筛选后触发 AJAX 局部刷新，标题不会恢复总数或今日失败；筛选 chip 和列表结果不变。
5. 实现时运行对应 Dashboard 测试、`python scripts/check_ui_contract.py --check`，并按项目规范重启后自动完成浏览器登录与截图验证。

## 7. 风险

- 移除总数后，用户需要从列表/筛选语境获取总量；这是本轮明确的降噪取舍，若未来需要总量应另设计为非标题位置的独立信息。
- 模板与 AJAX 若只改一处会造成刷新前后不一致；B1 以双点同步修改和回归断言控制。
- 窄屏更短，不引入额外换行风险；仍需浏览器验证浅色、深色和窄屏布局未受影响。
