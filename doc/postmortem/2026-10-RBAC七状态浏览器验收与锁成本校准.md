# RBAC 七状态浏览器验收与锁成本校准复盘

日期：2026-10-30 · 类型：验收完整性与方案准确性补修 · 状态：**按用户确认设计完成B1–B3，F2/F3关闭。** 未发现本批需要修改的生产锁释放或页面结果处理缺陷；以下修复对象是验收能力、工具和成本表述。

[批准设计与分步评估](../design/RBAC用户编辑七状态浏览器验收与锁成本文案校准设计-2026-10-29.html) · [完整验收与截图](../qa/RBAC用户编辑七状态浏览器验收-2026-10-30.html) · [JSON证据](../qa/evidence/rbac-outcomes-2026-10-29/results.json)。

## 1. Bug定位

F2位于交付证据：历史U3主要页面截图和服务/路由单测不能逐项覆盖ALREADY\_APPLIED与COMMIT\_UNKNOWN的实际浏览器行为。F3位于父设计§7：普通写入的固定用户数描述覆盖不了管理员降权时启用管理员集合锁定。新工具B1首次真实登录又发现注册申请模型未提前加载；响应采集在成功导航后读取body可能丢失，均属工具自身缺陷，已修正。

## 2. 根因

行为层把分散的绿色测试合并当成端到端完整证明，未定义逐状态的网络/UI/持久化证据。成本分析把主路径推广为所有分支。新工厂只按编辑直接依赖建表，忽略登录前置查询；初版采集把Ajax响应与导航生命周期分开，没有固定“success跳转之前”的观察点。

## 3. 测试漏洞

既有mock commit抛错只覆盖未提交一侧，不证明“真实提交后应用仍应显示未知”；静态DOM和JSON不能证明模态、按钮或PRG。单个场景成功不能发现缺场景/skip或旧结果文件；已有内存fixture可能已提前导入模型，掩盖新进程工厂建表顺序缺陷。

## 4. 修复

新增scripts/user\_edit\_browser\_harness.py和verify\_user\_edit\_outcomes\_browser.py。内存URI在engine创建前核验，逐HTTP请求核验哨兵；真实认证/CSRF、实际页面和公共JS。并发状态由第二管理员会话写入；注入只包当前具体Session并恢复。响应使用只读Ajax prefilter done订阅在success导航前采集白名单，等明确事件，不伪造响应。补齐模型初始化与真实登录守卫；非空证据目录拒绝覆盖。F3按批准文本校准源设计rev.2.8，未改生产锁协议。

## 5. 防护测试与实际结果

```

Ran 64 tests in 55.617s — OK
USER_EDIT_GROUP_PREFLIGHT: OK cases=18

```

完整命令见[validation.txt](../qa/evidence/rbac-outcomes-2026-10-29/validation.txt)及QA§5；64项包含11项新工具守卫。27项覆盖真实登录后的受限角色、七状态、原生POST、CSRF、其他角色拒绝和注入恢复；30张截图由runner生成并原样归档。U-before无持久化；U-after业务/审计已提交；两者均未知且一笔业务POST。授权子例认证版本+1、缓存失效一次，没有第二笔自动提交。

初版无效响应观察器、字段测试触发了浏览器原生校验的尝试均未计入通过证据；最终字段失败改为真实可输入的空自定义岗位，原生失败使用空岗位选项。早期诊断只执行了子集，不作为27项交付证据；正式结果来自完整case集合。

## 6. 同类排查

逐项核对users\_edit、\_users\_form\_response、公共Ajax和页面preflight的真实分支；UPDATED/部分FAILED无显式outcome属于现有契约，不为凑枚举改响应。原生确认、冲突、等价完成和未知结果均有独立用例。组选择preflight重跑18项通过；资料-only和A+B外组保护由scope\_projection等回归继续覆盖。全仓事务所有权、锁热点、EXPLAIN及真实网络断连不在本批，未冒称完成。

## 7. 预防方案

1. **证据集合可执行闭包：**CASES与七状态集合同时校验；results不得缺、重复、失败或skip；输出目录必须为空，避免重跑失败后留下旧pass。落点：scripts/user\_edit\_browser\_harness.py::verify\_results/prepare\_output、主runner汇总。第三方验证：运行tests.test\_user\_edit\_browser\_harness\_guard，缺结果/重复/skip/旧pass文件均应被拒绝。
2. **初始化与故障生命周期：**新增test\_factory\_real\_login\_and\_csrf\_without\_network，确保工厂能完整执行登录前置查询且CSRF真的拒绝；新增未命中/重复命中/异常后方法恢复和真实提交后异常仍持久化测试。命令：.venv-py311/bin/python -m unittest tests.test\_user\_edit\_browser\_harness\_guard -q，11项须通过。
3. **状态证明和提交真值绑定：**runner保留commit\_before、commit\_after、unknown\_after\_auth与recovery的固定case，网络、数据库和审计同时断言；任何一侧缺证据均失败。成本段同时给出普通/特殊分支限制和代码定位，不再作无测量的固定成本保证。执行完整浏览器命令可重复验证。

## 8. 分步专业评估与交付边界

B1先评估隔离、真实认证和计数污染，再实现工厂、精确注入与守卫；用真实HTTP保存证明内存连接共享。B2先冻结七状态触发方式、未知结果两种真值和原生回退，再逐项执行。B3在27项、64回归和18preflight通过后，评估归档脱敏、源设计准确性及历史时态，才修订F3与关闭状态。详见设计§10。

SQLite不是MySQL锁证明；故障注入不是完整网络混沌实验；单机worker缓存语义仍按现有实现。未改app生产源码、依赖pin、迁移、CI或业务配置；保留工作区原有他人未提交变更，不代为commit。临时服务已退出，文档由现有5001服务提供，无登录要求。
