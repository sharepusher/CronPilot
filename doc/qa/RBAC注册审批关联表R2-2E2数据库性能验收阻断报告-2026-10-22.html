RBAC 注册审批关联表 R2-2E2 数据库性能验收阻断报告

日期：2026-10-22（2026-10-23 补充 E2-Fix A 执行记录）· 状态：未通过；E2-Fix A 已验证回滚；E2-Fix B 待确认 · 范围：隔离 SQLite 的 100k 真值/EXPLAIN/性能验收、真实 MySQL 环境可用性检查，以及一次受控查询重构验证。

结论：不能宣布 R2-2E2、R2-2E 或 R2-2 完成。SQLite 的 10 组 scoped 场景触发 2× 性能停止线；真实 MySQL 恢复后在第一个组 1 真值 count 即超过 7 分钟。已确认的 E2-Fix A 仅在隔离 SQLite 小样本实施验证，因仍不达标而回滚；没有修改关联数据、CSV 或权限语义。

1. 已实施的验收能力

新增 scripts/benchmark_registration_scope.py 和 tests/test_registration_scope_benchmark.py。脚本仅接收显式专用库 URL，要求数据库名或路径含 cronpilot_r2e2_；SQLite 还必须位于 /private/tmp。三张核心表任一已存在即拒绝覆盖，因此不会写入 datas/ 开发库。

脚本固定生成业务组、父申请、关联行及 1/10 冲突真值样本；逐轮检查结果稳定性，输出 JSON 和 Markdown。MySQL 使用会话级 30 秒查询超时，任一超时或数据库异常都写入结构化 FAIL 结果，避免依赖人工中断。自动化自测覆盖非专用库拒绝、SQLite 小样本、1/10 真值和关联索引计划。

3. MySQL 真实执行

Docker Desktop 最终恢复为 running。在只绑定 127.0.0.1:33067 的临时 MySQL 8 容器中使用同一数据集执行真值矩阵时，组 1 scoped count 连续执行超过 7 分钟仍未返回。这已明显超出性能停止线，因此终止了仅存在于临时容器的查询。

EXPLAIN FORMAT=JSON 显示父表 rbac_registration_requests 为 access_type=ALL、估计扫描 98,930 行；关联表的三个相关子查询均以 ref/eq_ref 命中 uq_reg_req_groups_req_group。这证明问题是父表全扫与 OR 查询形状，而非关联表索引缺失。临时容器已删除，其中测试数据不可恢复。

4. 根因与风险判断

  1. 性能根因：当前单个 OR 谓词同时表达 viewer/operator 精确交集与 admin 完整子集。MySQL 因此从父申请表全扫并对每行执行相关子查询；关联侧索引正常。
  2. 测试漏洞：此前只有小规模 SQLite 和 MySQL 方言编译；没有 100k、多组 p95、等价基线或真实 MySQL 门禁，故无法提前发现该退化。
  3. 安全结论：不应以恢复 LIKE、分页后 Python 过滤或降低阈值解决。三者会重新引入授权错误或隐藏真实性能问题。

5. E2-Fix A 实施结果与新的确认边界

已按原 §17 实施角色互斥的 UNION ALL ID 集合：viewer/operator 从 ix_reg_req_groups_group_req 反查，admin 保留相关 EXISTS + NOT EXISTS 子集检查。隔离 SQLite 小样本（10,004 父申请、29,506 关联、1 次预热、2 次计时）中，组 1/3/10 的新旧组合 p95 分别为 2.037× / 4.267× / 3.948×，均超过 2×。

计划证明普通角色分支使用反向索引，但 admin 分支仍为 SCAN rbac_registration_requests，且每个候选行执行相关关联查询。因此没有进入真实 MySQL 或完整 100k 计时；实现已回滚，当前代码仍为已验证的精确单谓词版本。

下一步必须重新确认：新 §18 的 E2-Fix B 将 admin 子集判断改为关联表 CASE + SUM 集合聚合，消除相关父表扫描；先小样本计划/真值、再 100k SQLite、最后真实 MySQL。任一阶段失败即回滚，不恢复 LIKE。

6. 验收脚本数据分布修复复盘

  1. Bug 定位：首版基准生成器用 roles[row_id % 3] 循环角色，而 global 条件同时要求 admin 且 row_id % 60 == 0。
  2. 根因：被 60 整除的 row_id 在上述下标规则中总映射为 viewer，导致十万样本只剩额外真值用例的 1 条 global。
  3. 测试漏洞：小样本只验证了关联行数与索引计划，未断言 manifest 中的 global 数量和实际分布。
  4. 修复：改为 roles[(row_id - 1) % 3]，使被 60 整除的第三类角色为 admin；修正后正式 SQLite manifest 包含 1,667 条合法 global 申请。
  5. 防护测试：tests/test_registration_scope_benchmark.py 断言小样本 120 条中有 3 条 global，同时断言 124 张申请与 358 条关联行守恒。
  6. 同类排查：每次正式运行都将输出 manifest（父申请、关联、global、pending、业务组数），SQLite/MySQL 使用同一生成规则。
  7. 预防方案：验收脚本现在还固化了 MySQL 会话级 30 秒超时、结构化 FAIL 输出与 JSON 计划递归解析；第三方可用下方命令重现与检查。
