# 近期提交 P1/P2 问题深度评估与修复设计

**日期**：2026-09-11　**类型**：Bugbot 审查结论深化与修复设计　**状态**：已交付（P1/P2，2026-09-11）

评估范围为近期分支提交，重点复核认证版本 fail-closed 与任务触发请求 URL 记录。本文仅记录已验证证据和拟议修复；未确认前不修改业务或测试实现。

## 1. 问题

| 编号 | 已复现现象 | 影响判定 |
| --- | --- | --- |
| P1 | `tests.test_cron_run_now` 中 3 个失败、1 个错误；`tests.test_job_log_detail_integration` 中 1 个错误。前者被重定向到登录页，后者在真实登录预检查查询注册申请表时缺表。 | CI 回归失真，原有 Dashboard/运行详情测试不再验证目标页面。 |
| P2 | GET 配置 URL 含 fragment 时，`actual_url` 以字符串直接拼接注入参数；存储 URL 与 Requests 规范化 URL 不同。 | 运行详情错误呈现请求参数；同时 fragment 可能进入签名输入、却不会随 HTTP 请求发送，存在对端验签失败风险。 |

## 2. 根因与证据

### 2.1 P1：生产安全契约与测试 fixture 脱节

`app/rbac/services.py::web_session_user_is_valid()` 已明确要求 `user_id`、匹配的用户记录、`username` 与存在的 `auth_version`；`app/rbac/views.py` 的 before-request gate 对不满足条件的会话清空并重定向。该 fail-closed 语义正确，专项矩阵已验证缺键、版本不匹配、一次性 bump 均通过。

`tests/test_cron_run_now.py` 的列表页 fixture 仅写入 `is_login`、角色、用户名、组；没有创建对应用户，也未写入 `user_id` 与 `auth_version`。它因此被安全 gate 拒绝，失败不是生产逻辑应回退的依据。`tests/test_job_log_detail_integration.py` 通过真实 `/rbac/login`，但建表前未导入 `RbacRegistrationRequest` 模型，登录预检查访问该表时发生 SQLite 缺表错误。

### 2.2 P2：URL 解析、签名与记录并非同一个数据模型

`app/crons.py` 先用 `req_url.split('?')` / `split('&')` 构造签名参数，再以 `req_url + '?' / '&' + urlencode(...)` 记录 GET URL，实际发送则交给 `_http.get(req_url, params=...)`。已用 Requests PreparedRequest 验证：`https://host/path#section` 的记录值会成为 `.../path#section?cronpilot_trace_id=...`，而 Requests 生成的是 `.../path?cronpilot_trace_id=...#section`。

更严重的是，带 query 与 fragment 的 URL（如 `?x=1#section`）会令字符串切分把 `#section` 混入 `x` 的签名值；HTTP 传输不含 fragment。故只替换记录 URL 的拼接方式，不能修正签名与真实请求之间的不一致。

## 3. 方案与取舍

### 3.1 P1 推荐方案：修复 fixture，不放宽认证

1. 在需要通过 RBAC before-request gate 的测试中创建启用的 `RbacUser`，并把该用户 ID 与数据库中的 `auth_version` 写入 Session。
2. 在真实登录的运行详情集成测试中显式导入 `RbacRegistrationRequest` 后再 `create_all()`，使最小应用的模型注册与登录路径一致。
3. 只在 `TestDisabledSessionRevocation` 保留故意缺少 `auth_version` 的否定用例。

**不采用**：测试模式跳过版本校验、缺键时以 `or 0` 放行、或数据库缺表时吞异常。这些做法分别制造 fail-open、破坏迁移安全覆盖、掩盖真实应用装配缺陷。

### 3.2 P2 推荐方案：以 URL 解析结果作为唯一事实来源

1. 提取纯函数：`urlsplit(req_url)` 分离 fragment，`parse_qsl(parsed.query, keep_blank_values=True)` 得到待签名 query 参数，再加入 `cronpilot_trace_id`。
2. 使用该参数映射调用已验证的 `get_cronpilot_sign()`；GET 发送继续使用 `_http.get(req_url, params=inject_params, ...)`，不改变 DNS pinning Session。
3. 用同一 `req_url` 和 `inject_params` 调用 `requests.Request('GET', req_url, params=inject_params).prepare().url` 生成记录候选 URL，再统一脱敏后持久化。

**重复键边界**：现有签名 API 接受 dict，历史行为已是同名 query 后者覆盖前者。首批修复应显式保留并测试这一既有语义；若要支持多值 query 签名，必须另立协议兼容设计，不能在本修复中暗改。
