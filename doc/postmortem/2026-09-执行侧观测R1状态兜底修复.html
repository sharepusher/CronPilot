执行侧观测 R1 状态兜底修复复盘

日期：2026-09-18 · 状态：已修复并验证

1. Bug 定位

Run Inspector 只覆盖已响应、已发起未响应、连接失败、历史兼容态和 prepared；client_failed、not_started、unknown_failure 以及未来未知值没有传输状态行，导致执行记录出现状态空白。

2. 根因

传输状态枚举在分类函数和模板中分散维护，模板采用有限分支但没有为新增枚举提供显式分支或最终兜底。

3. 测试漏洞

Presenter 测试覆盖了字段值，却没有通过真实 job_log_detail 路由渲染模板，也没有覆盖三种角色和未知未来状态。

4. 修复

新增客户端初始化失败、尚未开始请求、状态未知三条文案，并增加最终未知分支，确保任意未识别状态也显示“状态未知，未确认发送”。

5. 防护测试

新增真实路由渲染矩阵，覆盖四种状态及 admin/operator/viewer 三角色。

.venv-py311/bin/python -m unittest tests.test_job_log_detail_integration.TestJobLogDetailIntegration.test_transport_state_fallbacks_render_for_all_roles -v
.venv-py311/bin/python -m unittest tests.test_run_inspector_presenter tests.test_execution_observability_contract -v

6. 同类排查

已检查 Run Inspector 请求区、响应区和 Presenter 的传输状态输出；响应优先级仍先于 sent/失败状态，历史 failed_before_response 展示保持兼容，未改变业务结果判定。

7. 预防方案

将传输状态真实模板矩阵作为状态枚举扩展的强制验收项：每新增一个状态，必须在 tests/test_job_log_detail_integration.py 中加入三角色渲染断言，并保留未知值兜底断言；CI 直接运行该测试，避免只测 Presenter 不测页面消费。
