级别位置结论
P0app/services/url_security.py:149-157二次 DNS 解析未经同等校验；可把首次通过校验的主机切换并 pin 到环回、链路本地、保留或组播地址。

历史 P0：DNS rebinding 可绕过禁止地址过滤（已关闭）

已更正的功能边界：私网/ULA 默认允许不是回归。doc/postmortem/2026-09-SSRF内外网区域校验修复.html §4 及 Release Notes 已定义：内网和外网均依部署 DNS 的实际解析结果访问，应用只拒绝环回、链路本地、保留和组播地址，并以 pinned IP 防止解析漂移。当前 tests/test_p0_phase_a.py:84-107 对私网字面量和内部 DNS 的允许断言与该设计一致。

定位与证据：validate_trigger_url() 的 98–111 行会检查第一次 DNS 解析出的每个地址；但 validate_and_resolve_url() 在 149–157 行重新解析并直接将每个答案加入 allowed，未调用 _is_private_or_reserved_ip()。攻击者可令首次解析为公网、第二次解析为 127.0.0.1、169.254.169.254、保留或组播地址，最终 adapter 使用第二次的禁止地址。

影响：拥有创建或修改触发 URL 权限且能影响 DNS 回答的攻击者，可绕过项目已定义的环回/链路本地/保留/组播拒绝边界，访问本机控制面或云元数据。此问题与私网服务的正常可达性无冲突。

合并前最低修复：执行阶段必须使用第一次已逐一校验的 DNS 结果，或对第二次每个结果重新执行同一禁止地址过滤后才允许 pin。新增“首次公网、第二次环回/链路本地/保留”的双解析回归测试；私网 RFC1918 和 IPv6 ULA 的允许测试应继续保留。

历史 P2：活动文档未同步已确认的网络区域契约（已关闭）

定位：README.md:377 将 block_private_ip=1 描述为“禁止触发内网/本机/元数据地址”；doc/index.html:339 与 doc/index.md:64 仍描述“内网域名/IP 白名单、外网隔离”。然而 doc/postmortem/2026-09-SSRF内外网区域校验修复.html §4 和 Release Notes 已明确：私网/ULA 可依据部署 DNS 正常访问，应用不再维护内网 hostname/CIDR 白名单，只拒绝环回、链路本地、保留和组播地址。

影响与处理：运维人员可能错误关闭 block_private_ip 才能访问内部服务，或错误配置不存在的应用侧白名单。应同步 README 与索引为当前契约，并保留 url_allow_hosts 作为可选的精确主机限制，而非内网访问的必需前提。
