# 执行失败分类与 HTTP 响应语义复盘

**结论：**记录 `264147763200` 的异常发生在本地 HTTP 客户端初始化阶段，不是远端 HTTP 响应失败。旧实现把异常归为“内部错误”，时间线又统一显示“连接失败”，并把“参数已构造”误标为“实际请求”。

## 1. Bug 定位

同一执行记录出现主摘要“内部错误”、时间线“连接失败”、HTTP 状态“—”以及“实际请求已注入”的混合语义，无法回答请求是否发送、远端是否响应。

## 2. 根因

- `exception_fail_reason` 只识别 requests 连接异常，未知 `TypeError` 统一归入 `internal`。
- Presenter 对所有 `http.error` 硬编码“连接失败”。
- `actual_url` 在 transport 调用前生成，旧字段没有“参数准备/传输结果”边界。
- 页面没有区分“无 HTTP 响应”和“响应正文不可见/被截断”。

## 3. 测试漏洞

原测试只覆盖 Timeout、HTTP 状态和敏感 URL 脱敏，没有覆盖 HTTP 客户端初始化异常、无 response object、历史事件 detail 缺少新分类字段，以及页面传输状态文案。

## 4. 修复

| 层次 | 修复 |
| --- | --- |
| 分类 | 新增 `exception_failure_info`，区分 `connection`、`timeout`、`client_incompatible`。 |
| 存储 | `job_log` 增加 `failure_stage`、`transport_state`、`response_received`；迁移回填历史记录。 |
| 事件 | http.start/error/complete 写入传输状态；Presenter 对历史 `assert_hostname` 事件兼容推断。 |
| 页面 | 显示参数准备、传输状态和“未获得 HTTP 响应”，不再用 actual\_url 证明已发送。 |

## 5. 防护测试

- 分类单测覆盖 `assert_hostname → client_incompatible`。
- Presenter 测试覆盖时间线分类和无 HTTP 响应文案。
- 详情集成测试覆盖三角色 URL 脱敏与新参数准备文案。
- 46 项执行观测/详情定向测试通过；Ruff、86 路由冒烟、UI 契约均通过。
- 真实浏览器登录后打开 `/job_log_detail?id=264147763200`，四个关键文案断言通过。

## 6. 同类排查

检查了所有异常分类调用、事件白名单、Run Inspector Presenter、详情模板和历史迁移路径；未发现其他页面自行把 `http.error` 固定为“连接失败”的展示路径。

## 7. 预防方案

1. 在 `tests/test_execution_observability_contract.py` 增加失败分类枚举与 Presenter 文案一致性门禁；新增枚举必须同时有写入、展示和否定用例。
2. 在 `scripts/ensure_business_tables.py` 保留历史语义回填，并把迁移后的非空字段计数输出纳入发布验收。
3. 在浏览器验收脚本中固定检查“失败阶段、传输状态、HTTP 响应未获得”三类断言，防止模板回退到模糊文案。
