| 严重级别 | 位置 | 发现与影响 | 缺失防护 |

| P1 | `app/rbac/views.py:91` `:575` `:630-635` `:745-748` | 用户列表、详情和编辑 GET 继续以 Session role/group\_ids 作为最终授权。角色降权不 bump `auth_version`，组变更也不撤销 Web Session；旧 Cookie 可继续读取范围外用户资料。 | 统一使用 `resolve_user_management_actor()`，或对角色/组变化实施 Session 撤销；列表/详情/编辑旧 Cookie 反向矩阵。 |

## 4. 方案与实现一致性

- **成立：**注册审批列表已使用数据库当前 actor；关联表精确表达多组关系；列表、分页、total 与 badge 使用同一授权集合；授权查询失败按 500 fail-closed。
- **不成立：**“受限 Biz Admin 不能通过单条或批量审批影响范围外申请”只对批准路径成立，拒绝路径仍可绕过 Scope。
- **状态过度声明：**`doc/qa/RBAC全局权限授予边界S0-S5全过程专业Review-2026-10-16.html` 将写入安全和整体闭环标为正式通过；当前拒绝越权使该表述需要收窄。
- **已知风险遗漏：**先前 Review 已明确记录用户管理陈旧 Session 与 `__ALL__` 回显缺口，当前实现没有消除，却仍进入“关闭”状态。
- **边界说明：**F-02 若严格只指“注册审批列表读取”，其关闭证据仍成立；若文档以此推导整个 RBAC 用户管理/审批面已闭环，则结论不成立。

## 5. 值得保留的工程质量

- 将授权事实从 Session 收敛到数据库当前 actor 的方向正确，并且在注册审批列表/批准写入上实现了请求级同源。
- 关联表方案消除了组 1/10 的字符串碰撞，并覆盖 SQLite/MySQL 方言、迁移幂等与性能验证。
- 异常信息脱敏、trace\_id、批量三态摘要、分页/count/badge 同源等工程细节成熟。
- 测试角色矩阵、存储漂移、正向 global 基线和 fail-closed 场景覆盖广，说明缺陷集中在边界完整性而非整体实现失控。

## 6. 修复优先级与重新放行条件

1. **先修 P1：**拒绝路径对象级授权；用户管理所有读取入口统一数据库当前 actor 或可靠撤销旧 Session。
2. **再修 P2：**补全 global admin 表单双向映射；让批量反馈表达最终状态而非仅表达 `ok`。
3. **补防护测试：**每个发现至少一条 HTTP/浏览器否定路径；拒绝越权必须同时覆盖单条和批量。
4. **校准文档状态：**在修复和复验前，将“S0–S5 正式通过/全部闭环”等宽泛表述改为条件通过或明确限定范围。
5. **重新验收：**专项自动化、目标角色浏览器正反向、86 路由、Ruff、文档门禁与本地可验证环境全部通过后，方可 commit。
