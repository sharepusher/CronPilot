规模化 Scope 过滤与角色差异化设计

管理员跨组下钻 · 非管理员 1～2 Scope 轻量展示 · HTML Demo · L2 专章

状态：设计稿 v2 · 讨论已收束 · 权威总稿见 规模化信息架构设计（OPT-P2-13） · 2026-07-15

定位：本页为 OPT-P2-13 总设计 的 L2 Scope 专章（含可切换角色 Demo）。 后端鉴权不变（仍走 build_scope_filter_clause / authorize）；本设计只新增可视范围内的二次过滤与按可滤桶数量适配的控件。 总稿已拍板结论见总设计 §二；B0/B1 已落地，列表视觉见总设计 §5.1。
B0 落地形态（相对本节历史侧栏 / Pill Demo）： 任务列表将 Scope 收拢进两段式工具栏「业务组」下拉，与健康/生命周期快筛同行；可见桶仍为矩阵语义（全部 / GLOBAL / 可见组）， UI 不再按 G 数切换侧栏占位，以避免与健康徽标、操作列叠加造成行高爆炸。交互参数不变：scope_view + group_id。

一、问题与目标

角色场景现状痛点目标体验
admin（可见全库） 数十～数百任务跨多业务组平铺；无 group_id / Scope 列与筛选；顶栏不展示组 一键按 Scope 下钻；默认「全部」；可单看 GLOBAL 或某业务组
非 admin · 1 组 后端已限 GLOBAL+本组，但列表不区分；若照搬左侧大侧栏会显得空洞且多余 不出现侧栏；顶栏上下文 + 轻量「全部 / 本组 / 全局」三分段，减少 GLOBAL 干扰
非 admin · 2 组 两组任务混排难辨；也装不下 admin 级侧栏 水平 Pill：全部 | 组 A | 组 B | 全局；无侧栏
非 admin · 0 组 仅见 GLOBAL；顶栏已警告「未分配业务组」 保持警告；仅「全部/全局」等价；禁止伪装成某组过滤
原则：控件密度随「可滤选项数量」缩放，不随角色名缩放。 admin 与「绑定 8 个组的 operator」都可能需要侧栏；「仅 1 组的 operator」绝不使用空侧栏撑布局。

二、角色 × Scope 数量决策矩阵

令 G = 用户 session 内业务组数（admin 视为「可浏览全库组列表」）。过滤控件按 可滤桶数 选择形态：

条件可滤桶推荐控件禁止
admin 全部 + GLOBAL + 每个 resource_groups 左侧 list-group 侧栏（组数 ≥ 8 时侧栏顶加搜索框） 把 Scope 只藏在「高级查询」里且无计数
非 admin · G = 0 （实质仅 GLOBAL） 顶栏危险标签；列表无 Scope 过滤器；文案提示联系管理员绑组 假侧栏 / 可选空下拉
非 admin · G = 1 全部 · 本组 · GLOBAL（3） 上下文条 + 水平分段控件（Segment）；无侧栏 单元素侧栏；强制「业务组下拉」多一步
非 admin · G = 2 全部 · 组1 · 组2 · GLOBAL（4） 水平 Pill / Segment（一行排开）；无侧栏 为 2 项引入 180px 侧栏
非 admin · G = 3～4 全部 + 各组 + GLOBAL 可换行 Pill；仍优先水平 —
非 admin · G ≥ 5 同上 与 admin 同构侧栏（仅列出本人组 + GLOBAL），避免 Pill 换行爆炸 把别人不可见的组渲染进 UI（即使点了会 403）
与创建表单对齐：Scope 设计 §五 已规定「仅一组成员时只读展示；多组时下拉」。 列表过滤沿用同一密度哲学：1 组只读上下文 + 轻滤；多组才给选择器；admin 全量导航。

2.1 默认选中

角色默认 Scope 滤镜理由
adminscope_view=all（全部）运维总览；异常任务可能跨组
非 admin · G≥1scope_view=all（含 GLOBAL + 所属组）与现网后端可见集合一致，避免升级后「突然少了全局任务」
可选增强记住上次选择（localStorage cronpilot.scope_view）二次进入更快；清除缓存即回默认

2.2 「全部」语义（关键）

  • admin 的全部 = 库内所有任务（等价于今日无 Scope WHERE）。
  • 非 admin 的全部 = 仍应用 build_scope_filter_clause 后的集合（GLOBAL ∪ 所属组），不是突破隔离。
  • UI 文案：非 admin 写作「全部（可见范围）」或「全部」，旁注灰字「含全局共享 + 我的业务组」。

三、查询契约与安全边界

3.1 查询参数

GET /cron_list
  ?task_name=      # 已有，保留
  &page=           # 已有
  &status=         # 可选 Wave：lifecycle 0|1|-1；空=全部
  &health=         # 可选 Wave：failing|ok|unknown；连续失败等（维度 B）
  &scope_view=     # 新增：all | global | group
  &group_id=       # 当 scope_view=group 时必填；仅允许 session 可见组（admin 任意组）

3.2 服务端校验（强制）

规则行为
非 admin 传入其它 group_id忽略或 403；写 scope:deny 审计（与单资源越权一致）
scope_view=group 缺 group_id回退 all 或返回 400 + 表单错误
先 Scope 权限过滤，再套 scope_viewUI 过滤永远是可见集的子集，不能扩大可见性
列表 SQL 仍经 build_scope_filter_clause禁止在 views 里手写 if role == admin 旁路

3.3 Scope 过滤 SQL 语义

# 在已有 scope_clause（权限）之上追加 UI 过滤：
scope_view=all     → 不追加
scope_view=global  → CronInfos.scope_type == 'GLOBAL'
scope_view=group   → CronInfos.scope_type == 'GROUP' AND group_id == :id

四、交互契约

项约定
页面形态普通 GET 跳转（保留 query：task_name / status / health / scope_view / group_id / page）。首期不做无刷换 tbody，降低与分页宏耦合风险。
切换 Scope点击侧栏或 Segment → 导航到带参 URL，page 重置为 1。
与搜索组合「高级查询」提交时原样带回当前 Scope 参数（hidden 或 URL 拼装）。
启停 / 下线沿用 js-ajax-dialog-btn / 下线表单；本设计不改写。
运行记录沿用 open_iframe_dialog(job_log_list?id=)；建议详情默认可带 status=fail（后期）。
列表列新增「作用域」列：GLOBAL 徽章 或 组名徽章（admin 与多组用户尤其需要）。
顶栏非 admin 继续展示组名标签；admin 仍可不在顶栏堆组名（侧栏已承载）。

六、线框细则

6.1 Admin

  • 主内容区改为「左 180px Scope + 右表格」；顶栏 Tab 布局不变。
  • 侧栏第一项「全部」恒在；第二项固定「全局共享」；其后按组名排序列出全部 resource_groups。
  • 每项右侧弱化任务计数（可选；可用一次聚合查询或缓存）。
  • 组数 ≥ 8：侧栏顶部增加 <input placeholder="筛选业务组"> 前端过滤侧栏锚点（不请求服务器）。
  • 表格必显「作用域」列。

6.2 非 admin · 1 Scope

  • 不渲染侧栏，避免「只有一个组却占 180px」的空洞感。
  • 内容区顶部上下文条：只读芯片展示「全局共享 + 本组名」（与顶栏组标签信息呼应，列表页更完整）。
  • 其下三段 Segment：全部 | 本组 · {name} | 仅全局共享。
  • 「本组」点击 → scope_view=group&group_id={唯一组id}。
  • 权限上仍可读 GLOBAL；不能在 UI 上「假装」去掉 GLOBAL 的可读性——只能过滤列表视图。

6.3 非 admin · 2 Scopes

  • 无侧栏；水平四个桶：全部 | 组1 | 组2 | 全局。
  • 组名过长时截断 + title 悬停全称（Bootstrap 3 无 tooltip 插件亦可用原生 title）。
  • 创建任务页已是「下拉选组」；列表用 Segment 比再造下拉更适合「翻阅」。

6.4 文案与无障碍

  • 当前选中项：aria-current="page"（侧栏链接）或 Segment aria-pressed="true"。
  • 勿用 emoji 作状态主视觉；沿用 Font Awesome / label / 本 Demo 的 badge 色。

七、与任务健康板、全局日志的衔接

本设计主交付维度 A（任务运营）的 Scope 维；维度 B 的健康信号共用同一查询轴：

入口行为
快筛「连续失败」保持当前 scope_view，追加 health=failing；避免切健康时丢掉 Scope 上下文
全局执行记录同样按矩阵渲染 Scope 控件；默认建议可切「仅失败」（OPT-P1-01c）；过滤在可见集内
任务看板 Metric卡片点击带上同一 scope_view 跳进列表（后期 Wave）
秒级日志淹没：Scope 过滤不能单独解决；须配合「任务行最近执行」与「失败优先」。但 Scope 下钻可在 admin 场景先把问题缩到某业务线，再进该任务日志，形成「组 → 任务 → Run」的三级穿透。

八、实现落点与分期

波次内容主要文件
S1（本设计确认后） 查询参数 + 服务端二次过滤 + 列表作用域列；按矩阵渲染侧栏 / Segment / 警告条 app/main/views.py · cron_list.html · 可选 rbac/_scope_filter.html partial
S2 生命周期 / 连续失败 Quick Filters；侧栏计数 同上 + 聚合查询 service
S3 执行记录页同构 Scope 控件；Metric strip job_log_all_list.html 等

Bootstrap / 原生 JS：侧栏用 .list-group 风格自写；Segment 用按钮组；不引入前端脚手架。

九、验收清单

  1. admin：侧栏切换 GLOBAL / 某组后，表格仅含对应任务；「全部」恢复全库；URL 可复制分享。
  2. operator（1 组）：页面无左侧栏；三段切换工作正常；越权 group_id 被拒绝。
  3. operator（2 组）：四段 Pill；只能落到自己的两个 group_id。
  4. 未绑组：仅 GLOBAL；无 Scope 过滤器；顶栏危险提示保留。
  5. bash scripts/cronpilot.sh test + 静态门禁如有模板改动；浏览器路径覆盖三角色；改模板后须 cronpilot.sh restart 再验。
