1. Bug 定位

P2-A：app/templates/redesign/user_form.html::requestedValues 曾用 [name="group_ids"]:selected 读取选项；name 实际在 select，selected 在 option。具体组 no-op 多发请求，全局改具体组却被误判无变化；无选择也被归一为空数组、误当明确全局。P2-B：app/rbac/services.py::format_user_update_audit_detail 与 _audit_logs_rows.html 曾允许未知字段 partial 渲染、未知顶层键、bool/float 版本与错误字段类型，偏离父设计 D6c。

2. 根因

前端用“可选字段当前值”和“可靠的业务集合”共用一个空数组表示，既选错 DOM 层级，又没有单列不可比较状态。审计 reader 把兼容理解为“能解析多少就展示多少”，用 Python 宽松相等/str 转换代替版本和字段类型契约。编写 partial 测试时沿用实现输出作为预期，没有以已冻结 D6c 作为独立判据。

3. 测试漏洞

  • 静态测试只检查 preflight 字符串，后端 no-op 用例不执行 JS；只验证 locked hidden 或全局原样会碰巧通过，没有跨 select/hidden 和全局/具体/空选择的请求数矩阵。
  • 审计用例明确期待 partial，只断言已知字段可显示，未检查坏字段应使整条变化/理由都不返回，也缺 full/Ajax partial 与数据库原文保持断言。
  • 本轮新增 partial 测试曾写错响应 envelope，已根据实际 views.py 修正为 rows；live harness 遇到 Ajax 成功后立即跳转导致响应体不可读，改以 HTTP 状态、真实 URL 和 DB/版本/Token/审计断言判断成功，未改变产品行为适配测试。

4. 修复

  • 增加局部 requestedGroups：读启用 select.val() 或锁定 hidden；明确 marker 才映射 []，合法具体组严格转整数、去重升序。空选、混合 marker、坏 ID、多来源用 null 表示不可比较，继续交后端原校验。
  • 不改表单 payload、授权策略、公共 Ajax 或 P1 token。只有合法、可可靠比较且等于原值时阻止 POST。
  • reader 验证精确整数版本、顶层键、changes 白名单和 before/after 形状；资料字符串/null、角色字符串、组排序整数数组与理由语义均整条验证。任何错误返回空 changes/无 reason，不部分展示。
  • 模板只在 ok 时显示变化；legacy/invalid/unsupported 保留基础事件和固定提示。删除 partial 解释分支，不迁移、不删除历史 detail。
  • 兼容保留历史角色/岗位字符串，不执行当前业务枚举/邮箱格式的二次校验；无新增依赖、DB 字段或外部 API 结构变化。

6.1 新发现 R5：单组管理员编辑多组目标的范围外绑定保留

历史发现，已由后续 R5 批次修复。 见R5 修复与最新验收。以下保留 P2 当时的发现与只读证据。管理员 Scope 设计 §3.6（HTML 第 231–233 行）和 §7（第 467–469 行）明确：只 diff 管理员可见组，保留范围外绑定。

只读浏览器探针：单组 actor 管理组 13，目标原始签名 group_ids=[13,14]，表单 hidden 只有 13；不修改字段点击保存仍准备发送 group_ids=[13]。探针在 Ajax transport 前截获，实际业务 POST=0，未对该目标实施删除绑定。原始结果。

服务当前按完整 desired_group_ids 删除目标多余绑定，未实现上述“保留范围外组”的设计。此缺口在旧 hidden 读取路径也存在，与本次修正 select 选择器不同；不能用强行 no-op 或前端补回范围外组来掩盖。需要单独设计明确 actor 可编辑投影、签名原值/授权单元比较、服务端只 diff 可管理集合与外组保留，并补“未改表单”和“真实改可见组”两类否定路径。

初始四项 Review 发现已经补修，但新增 R5 当时仍开放，后续已按独立确认设计关闭。当前 228 项回归与 16 项 live 的通过范围不覆盖这一组合；请勿将它们解释为范围外绑定保护已经成立。

7. 预防方案

  • scripts/verify_user_edit_group_preflight.py 固化 18 场景，使用实际模板代码而非复制算法；每场验证请求数量、请求参数原样或 no-op 提示。第三方可执行上面的永久命令复现。新入口已登记 AGENTS.md 快速命令与依赖 RFC §7.5，不改变依赖 pin。
  • tests/test_user_edit_change_set.py 的五个 audit_v1/real_writer/bad_audit 测试把“错误对象整条 == invalid/[]/None”与“原始 DB 不变”作为判据，已纳入现有 unittest discovery。
  • 合法 writer 的三类真实事件直接喂给 reader，防止过严校验误伤合法历史文本；未来版本必须先定义 reader 分支与坏样本，再变更 writer。
  • 对前端提交优化的验收同时量测网络和业务副作用；对审计兼容同时量测完整记录、坏记录与原始持久化值，不以单个 Toast 或绿测数量代替契约。
