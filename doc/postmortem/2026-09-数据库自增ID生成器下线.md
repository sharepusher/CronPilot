# 数据库自增 ID 生成器下线复盘

日期：2026-09-20 · 关联提交：`7063ff7` · 状态：已实施，待 MySQL 环境复验

## 1. Bug 定位

`cron_infos`、`job_log`、`job_log_events` 和 ExecutionTracer 仍依赖进程内 `next_id()`。多 worker 下该生成器无法提供数据库级唯一性，且事件写入绕过 ORM 时会自行分配主键。

## 2. 根因

设计和模型把应用层默认值误当成数据库自增；SQLite 的 `BIGINT PRIMARY KEY` 又不具备 rowid 自增语义。Core INSERT 路径因此显式注入生成器 ID，绕过了数据库约束。

## 3. 测试漏洞

原有测试覆盖生成器自身的进程内序列，却没有覆盖多 worker、数据库真实自增、旧 SQLite 事件表结构、Core INSERT 省略主键和重复结构切换。

## 4. 修复

- 三张模型移除 `next_id`，改用数据库自增与 SQLite 类型变体。
- ExecutionTracer 构造字段白名单，完全省略 `id`。
- 旧 SQLite 事件表执行值不变的 schema 重建；MySQL 三张表统一为 `BIGINT AUTO_INCREMENT`。
- 迁移重复执行幂等，历史行不重编号。

## 5. 防护测试

`tests/test_id_autoincrement.py` 覆盖 ORM 三表自增、旧 BIGINT 事件表重建、历史 ID 保持和新 ID 为最大值加一；专项、导入和迁移测试共 25 项通过；路由冒烟 86/86 通过。

## 6. 同类排查

已搜索 `app/` 与 `datas/` 生产 Python 代码，除生成器文件自身外不再存在 `next_id` 调用或导入；迁移脚本同时补齐事件表 MySQL 自增分支。

## 7. 预防方案

新增可验证门禁：`rg -n "from datas\\.utils\\.id_generator|next_id\\(" app datas --glob '*.py'` 必须无输出（生成器文件自身除外）；`tests/test_id_autoincrement.py` 固定验证“省略主键才触发数据库分配”和迁移幂等。落地位置：生产提交前 CI 与 `tests/` 回归套件。

## 验收限制

本地已执行重启脚本，但当前沙盒禁止本地监听，live curl 返回 `Operation not permitted`；需在可监听环境完成 POST 登录和 MySQL DDL 复验后再标记发布完成。
