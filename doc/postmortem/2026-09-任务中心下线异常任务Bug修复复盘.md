# 2026-09 任务中心下线异常任务 Bug 修复复盘

**日期**：2026-09-09　**关联设计**：任务中心需要关注项目排除下线任务设计

## 1. Bug 定位

Dashboard “需要关注的任务”面板由 `app/main/views.py::cron_list()` 调用 `CronRepository.top_failing()` 获取。该查询会把 `JobHealth.health_status='failing'` 的下线任务一并返回。

## 2. 根因

`top_failing()` 只表达了“健康状态为持续失败”，没有表达“任务仍处于有效生命周期”；健康聚合记录会被保留，因此 `CronInfos.status=-1` 的历史异常任务仍满足查询条件。

## 3. 测试漏洞

既有测试覆盖了持续失败筛选和逾期检测排除下线任务，但没有在“需要关注面板”的真实渲染路径中同时构造“下线 + failing 健康记录”这一组合状态，导致查询条件缺失未被发现。

## 4. 修复

在 `app/repositories/cron_repository.py::top_failing()` 增加 `CronInfos.status != -1` 条件；不删除健康记录，不改变下线任务的历史查询能力。该条件与同文件统计、连续失败计数和今日成功率的既有生命周期口径保持一致。

## 5. 防护测试

| 验证 | 结果 |
| --- | --- |
| `tests.test_job_health.TestCronListHealthFilters` | 3/3 通过，面板正向展示运行中异常任务、反向排除下线异常任务 |
| 健康/逾期相关测试 | 24/24 通过 |
| `ruff check app/` | All checks passed |
| `python scripts/smoke_routes.py --check` | 86/86 路由通过 |
| SQLite EXPLAIN QUERY PLAN | Join 仍为健康表扫描 + 两侧主键查找 + 既有排序，无新增查询步骤 |

## 6. 同类排查

已核对 `metrics()`、`count_consecutive_failing()`、`today_success_rate()` 和 `compute_overdue_map()`：这些路径已排除下线任务；`top_recent_ok()` 不属于本次“需要关注”面板消费点，未改变其既有口径。

## 7. 预防方案

在 Dashboard Repository 测试夹具中固定保留一个“已下线 + 历史 failing 健康记录”的边界样本，并要求面板渲染断言直接检查异常面板片段。落地位置：`tests/test_job_health.py::TestCronListHealthFilters.test_attention_panel_excludes_retired_failing_task`；复现命令：`.venv-py311/bin/python -m unittest tests.test_job_health.TestCronListHealthFilters -v`。后续新增 Dashboard 提醒查询时，评审清单必须逐项确认生命周期状态过滤与健康状态过滤是否同时存在。
