执行记录状态显示精简设计

状态：待确认 · 2026-08-31 rev.2 · 修订 执行记录结果列细分展示设计（2026-08-27 已确认）

1. 问题

列表「结果」列：在「失败」/「异常」后追加 · 4xx / · 5xx / · 关键词 / · 连接 / · URL拦截 子标签。 但「返回内容」列已展示 HTTP 状态码与响应摘要，fail / error 主标签（不同颜色+不同文案）已完成语义分类，子标签是冗余叠加。视觉上破坏了状态标签的简洁性。

详情页「失败原因」板块：混杂原始枚举码（http_4xx）、英文 label（Target:、Timeout:）、健康计数，而这些信息已分布在「请求」「元数据」板块中，是重复且排版混乱的堆叠。同时 meta 行显示的是原始枚举码而非可读文案。

2. 根因

2026-08-27 「结果列细分」设计的核心目标是：区分筛选按钮「仅失败」与「仅异常」对应的不同状态。该目标已通过拆分 fail / error 为独立分支（红色「失败」vs 橙色「异常」）实现。子标签当初用于进一步细分原因，但其承载的信息与「返回内容」列完全重叠（HTTP 码可见），实际沦为多余注脚。

详情页「失败原因」板块是早期将多处上下文信息聚合为「诊断摘要」的尝试。各信息源（URL、超时阈值、健康计数）已有专属板块后，聚合板块变为纯冗余，且因未做国际化/格式统一导致中英混排、原始枚举码裸露。

4. 方案

方案 A（推荐）：双处精简

A1 — 列表结果列：移除子标签

保留 fail / error / timeout 各自独立分支（颜色+文案区分已足够），仅移除 .el-log-sub span：

status当前显示精简后颜色/样式
success● 成功● 成功绿色，不变
fail (http_4xx)× 失败 · 4xx× 失败红色，不变
fail (http_5xx)× 失败 · 5xx× 失败红色，不变
fail (keyword)× 失败 · 关键词× 失败红色，不变
error (connection)× 异常 · 连接× 异常橙色，不变
error (blocked_url)× 异常 · URL拦截× 异常橙色，不变
timeout⏱ 超时⏱ 超时紫色，不变

A2 — 详情页：移除冗余板块，改善 fail_reason 可读性

移除整个 ri-section danger「失败原因」板块：

原板块内容已有展示位置处理
原始 fail_reason 枚举码ri-meta 行移除重复；meta 改为可读文案（见下）
Target: 请求 URL「请求」节移除
Timeout: 超时阈值「元数据」节移除
连续失败计数 / 时间戳无专属位置移除（健康数据由 job_health 体系覆盖）

ri-meta 行 fail_reason 枚举码 → 可读文案映射：

备选方案 B：仅清理详情页，保留列表子标签

若认为子标签对快速扫描有价值，可仅处理 A2，不动列表。不推荐：子标签携带的信息已在「返回内容」列可见，且视觉上破坏状态标签的简洁性。

7. 验收

  1. bash scripts/cronpilot.sh restart --daemon
  2. 访问执行记录列表：
    • 切换「仅失败」→ 结果列显示「× 失败」，无 · 4xx / · 关键词 子标签
    • 切换「仅异常」→ 结果列显示「× 异常」，无 · 连接 / · URL拦截 子标签
    • 切换「仅超时」→ 结果列显示「⏱ 超时」，样式与精简前一致（回归确认）
    • 「返回内容」列仍正常展示 HTTP 码或响应摘要，未受影响
  3. 访问任意失败/异常执行详情页：
    • 页面无「失败原因」红色板块
    • meta 行「失败原因」显示可读中文（如 HTTP 4xx、连接失败）而非原始枚举码
    • 「请求」「元数据」板块内容不变
  4. python scripts/smoke_routes.py --check 通过
  5. python scripts/check_dead_css.py --check 通过（确认 .el-log-sub 已清理、无新增死代码）

8. 风险

  • 子标签移除后，列表层面无法一眼区分 4xx / 5xx / 关键词；但该信息已在「返回内容」列和详情页可见，可接受。
  • fail_reason 为空的旧记录：枚举映射 fallback 到原始值，不影响展示。
  • 无后端变更、无数据迁移。回滚仅需恢复两处模板改动 + 一条 CSS 规则恢复。
  • 「失败原因」板块中的连续失败计数 / 时间戳（health.consecutive_failures / last_fail_at / last_success_at）：该信息属于任务级别健康趋势（非单次执行诊断），语义上更适合放在任务详情页（task_detail_v2）的 job_health 板块中展示。本次移除后如需补回，应作为任务详情页健康面板的独立优化跟进，不在本批次范围内。
