执行侧观测 sent 状态判定 · 复盘

日期：2026-09-18 · 状态：已修复并验证（F2）

关联评估：执行侧观测近期提交专业 Review 评估

问题：Presenter 的 actual_request_sent 只接受 sent 与 response_received，但运行时没有可靠地产生中间 sent 状态。F1 新增的 sent_no_response 因此无法进入“请求已发起”语义；模板分支也可能把状态覆盖成“已发送并收到响应”。
结果：sent_no_response 与未来兼容的 sent 均被识别为请求已发起；只有明确收到响应时才显示“已发送并收到响应”。本批次不伪造无法由同步 HTTP 客户端可靠观测的中间发送事件。

1. Bug 定位

问题位于 app/services/run_inspector_presenter.py 的 actual_request_sent 判定和 app/templates/redesign/run_inspector.html 的传输状态分支。

2. 根因

状态枚举预留了 sent，但当前同步 requests.get/post 调用在返回前没有可移植的“字节已发出”钩子；异常终态由 exception_failure_info 直接落为 connect_failed 或 sent_no_response。Presenter 仍沿用旧的两值白名单，导致模型状态与展示判定契约脱节。行为层根因是“请求调用已发起”和“已收到响应”没有在 Presenter 与模板中使用同一套状态优先级。

3. 测试漏洞

已有测试只断言成功记录的 response_received，没有断言 sent_no_response 在 Admin 视角下的请求已发起语义，也没有覆盖模板分支优先级。因此即使 Presenter 返回 false 或模板错误显示成功，测试仍可能通过。

4. 修复

  • Presenter 将 sent_no_response 纳入 actual_request_sent，并保留 sent 兼容。
  • Run Inspector 模板先判断 response_received / response_received 状态；仅收到响应时显示“已发送并收到响应”，sent/sent_no_response 显示“已发起，未收到响应”。
  • 连接失败仍优先显示“连接未建立”；Viewer/Operator 的 URL 与响应权限语义不变。

5. 防护测试

  • tests/test_run_inspector_presenter.py::test_transport_state_labels_distinguish_connect_and_read_timeout：连接失败为 false，读取超时为 true。
  • tests/test_run_inspector_presenter.py::test_sent_state_is_treated_as_request_started：兼容状态 sent 为 true。
  • .venv-py311/bin/python -m unittest tests.test_run_inspector_presenter tests.test_execution_observability_contract tests.test_execution_tracer -v（25 条通过）
  • .venv-py311/bin/python scripts/check_ui_contract.py --check、.venv-py311/bin/ruff check app/、.venv-py311/bin/python scripts/smoke_routes.py --check（86/86）

6. 同类排查

已检索 actual_request_sent、transport_state 及 Run Inspector 模板的所有引用。成功响应、连接失败、已发起未响应、历史状态均有明确分支；未发现 Viewer/Operator 绕过角色裁剪或把无响应显示成成功响应的路径。F3（http_status_label 未被模板使用）与 F6（外层 fatal 阶段默认值）仍保持独立待办。

7. 预防方案

将“是否已发起请求”和“是否已收到响应”作为两个独立断言固定在 Presenter 测试矩阵中，并要求模板分支顺序先处理响应已收到，再处理已发起未响应，最后处理连接失败/准备阶段。新增状态时必须同步更新 run_inspector_presenter.py、run_inspector.html 与 tests/test_run_inspector_presenter.py；第三方可用 §5 命令复现。
