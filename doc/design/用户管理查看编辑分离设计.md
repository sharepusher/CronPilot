# 用户管理 — 查看/编辑分离设计

**日期**：2026-08-26 · **状态**：待确认

## 一、问题

当前用户列表的操作列直接提供「编辑」入口，点击即进入表单编辑模式。当管理员只想查看用户信息（角色、组、状态等）时，被迫进入编辑界面，有误操作风险；且缺乏「只看不改」的友好路径。

## 二、方案

### 2.1 交互流程

用户列表
├── [活跃用户] 操作列：👁查看 | 🔑重置密码 | 🔄重置Token | ⊘停用
│ └── 查看 → 用户详情页（只读）
│ └── [编辑] 按钮 → 编辑表单（当前 users\_edit）
│
├── [停用用户] 操作列：👁查看（现有行为不变）
│ └── 查看 → 用户详情页（只读，无编辑按钮）
│
└── [自己] 操作列：🔑修改密码（现有行为不变）

### 2.2 详情页（view\_mode）变更

| 位置 | 当前 | 优化后 |
| --- | --- | --- |
| 标题 | 「查看用户信息」 | 「用户详情 — {username}」 |
| 状态行 | 硬编码「已停用」 | 根据 `user.is_active` 动态显示 |
| 操作区 | 只有「← 返回」 | 活跃用户：「编辑」+「返回」；停用用户：只有「返回」 |

## 三、范围

| 文件 | 变更 |
| --- | --- |
| `app/templates/redesign/_users_rows.html` | 活跃用户操作列：「编辑」图标改为「查看」图标，链接到 `users_view` |
| `app/templates/redesign/user_form.html` | view\_mode 区域：① 状态动态化 ② 活跃用户显示「编辑」按钮 |
| `app/rbac/views.py` | `users_view()` 去掉仅限停用的限制（docstring 说 "Read-only view for deactivated users" 需更新） |

**不做**：不改路由 URL（`/users/view` 已存在）；不改 v1 模板；不新增路由。

## 四、详细代码设计

### 4.1 \_users\_rows.html 操作列变更

```
Before:
  <a class="um-icon-btn" href="{{ url_for('rbac.users_edit', id=item.id) }}" data-tooltip="编辑用户">
    <svg .../> (pencil icon)
  </a>

After:
  <a class="um-icon-btn" href="{{ url_for('rbac.users_view') }}?id={{ item.id }}" data-tooltip="查看详情">
    <svg .../> (eye icon)
  </a>
```

### 4.2 user\_form.html view\_mode 修改

```
Before (状态行):
  <span class="u-badge u-inactive">已停用</span>

After:
  {% if user.is_active %}
  <span class="u-badge u-active">启用</span>
  {% else %}
  <span class="u-badge u-inactive">已停用</span>
  {% endif %}

Before (操作区):
  <a class="btn-c btn-line" href="{{ url_for('rbac.users_list') }}">← 返回</a>

After:
  {% if user.is_active and not view_mode_readonly %}
  <a class="btn-c btn-accent" href="{{ url_for('rbac.users_edit', id=user.id) }}">编辑</a>
  {% endif %}
  <a class="btn-c btn-line" href="{{ url_for('rbac.users_list') }}">← 返回用户管理</a>
```

## 五、分批

单批完成（3 文件，各改 ~5 行）

## 六、验收

1. restart 后打开 `/rbac/users`
2. 活跃用户行：操作列第一个图标为「查看详情」（eye icon）
3. 点击 → 进入用户详情页（只读）
4. 详情页状态显示「启用」（绿色）
5. 详情页底部有「编辑」+ 「返回」两个按钮
6. 点击「编辑」→ 正常进入编辑表单
7. 停用用户行：操作列仍为「查看信息」（行为不变）
8. 停用用户详情页：无「编辑」按钮，只有「返回」

## 七、风险

- 管理员多一次点击才能编辑 — 可接受（防误操作的收益 > 额外一次点击的成本）
- 原「编辑」快捷方式消失 — 用户需适应，必要时可在详情页添加键盘快捷键 `E` 进入编辑
