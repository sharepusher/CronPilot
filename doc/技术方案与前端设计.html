1.1 定位与价值

CronPilot（CronPilot管理） 是一套基于 Python Flask + APScheduler 的轻量级分布式定时任务调度平台。它将传统 Linux Crontab 的能力产品化：通过 Web 可视化界面或 REST API 统一管理定时任务，在触发时刻向业务系统发起 HTTP GET 回调，并记录执行日志、异常告警。

典型场景：每月还款提醒、每日凌晨数据清理、周期性健康检查、异步长任务的执行进度回传等。

4. 数据模型设计

系统采用双库分离：cron_db_url 存储 APScheduler JobStore（apscheduler_jobs 表）及可选共用；cron_job_log_db_url 存储业务表 cron_infos、job_log、job_log_items。

4.1 ER 关系

cron_infos (1) ──────< (N) job_log │ │ log_id (UUID) ▼ job_log_items (N)

5. 调度引擎设计

5.1 任务生命周期

创建/编辑 ──► scheduler.add_job("cron_{id}", cron_do, trigger=cron|date) │ ┌──────────┼──────────┐ ▼ ▼ ▼ 运行中(1) 已停止(0) 已结束(-1) │ │ │ resume_job pause_job remove_job (date 到期) │ │ │ └──────────┴──────────┘ │ cron_do 触发 ▼ requests.get(req_url, params={log_id, sign}) ▼ 写入 job_log + 错误关键词检测 ──► 多渠道通知

5.2 触发器映射规则

模式条件APScheduler trigger
一次性run_date 非空date，run_date=...
周期填写 day/day_of_week/hour/minute/second 至少一项cron，各字段透传
体验版is_dev=1强制清空 second

5.3 集群与高可用

文件锁（进程级）

CuBackgroundScheduler._process_jobs() 使用 portalocker 对 scheduler.lock 加非阻塞排他锁。同一机器多 worker 仅一个进程拉取到期任务。

Redis 锁（节点级）

@single_task() 装饰器在 is_single=0 时，以 task:{func}:{cron_id} 为 key，TTL 120s，保证集群中同一任务同一时刻只执行一次。

5.4 内置维护任务（config.py JOBS）

Job ID周期功能
cron_check每 30 分钟校验 apscheduler_jobs 与 cron_infos 一致性，缺失则 status=-1
cron_del_job_log每 8 小时按配置条数清理 job_log
cron_check_db_sleep每 15 秒SELECT 1 探活，失败则告警

5.5 任务执行时序（cron_do）

1查询 CronInfos，校验 req_url
2生成 UUID 作为 cronpilot_log_id
3解析 URL 已有参数，计算 cronpilot_sign（MD5，参数 ASCII 排序 + api_key）
4GET 请求，User-Agent: CronPilot，超时 120s
5响应体检测 error_keyword（逗号分隔，不区分大小写）→ 触发 wechat_info_err
6写入 JobLog（content、take_time、log_id）

6. API 接口规范

统一响应格式（datas/utils/json.py）：{ "errcode": 0|1, "errmsg": "...", "data": ... }

6.1 POST/GET /api/cron — 添加或更新任务

参数必填说明
access_token配置后必填与 conf.ini api_access_token 一致
task_name是唯一键；存在则更新，不存在则创建
req_url是http(s) 回调地址
run_date二选一有值则 date 模式
day, day_of_week, hour, minute, second二选一Cron 模式字段
task_keyword是备注/说明（LIFECYCLE-2；trim 非空）
 
curl -X POST "http://host/api/cron" \
  -d "access_token=abcdabcd" \
  -d "task_name=daily_cleanup" \
  -d "task_keyword=夜间清理·运维" \
  -d "hour=2" -d "minute=0" \
  -d "req_url=https://api.example.com/cron/cleanup"

6.2 /api/cron/status — 启停任务

参数说明
task_name任务名称
status0=关闭，1=开启；不传则 toggle

6.2b /api/cron/retire — 下线任务（不可逆）

参数必填说明
task_name是任务名称
reason是下线原因（LIFECYCLE-2 · 1～500 字；当前实现尚未强制，设计已确认）
access_token配置后必填与 conf.ini 一致

写 status=-1 及 retire_reason / retired_at（LIFECYCLE-2；无 retired_by）。详见 生命周期设计。

6.3 /api/cron/add_log — 上传执行明细

业务系统在收到 cronpilot_log_id 后，长任务执行过程中可多次调用，将进度写入 job_log_items。

curl -X POST "http://host/api/cron/add_log" \
  -d "access_token=abcdabcd" \
  -d "cronpilot_log_id=uuid-from-callback" \
  -d "content=步骤3/5 数据处理完成"

6.4 回调签名算法

  1. 收集回调 URL 已有 query 参数 + cronpilot_log_id
  2. 按参数名 ASCII 升序排列
  3. 拼接为 key1=val1&&key2=val2&&...&&api_key={api_key}
  4. 对拼接串做 MD5 → cronpilot_sign

前端参考：app/static/js/signs.js、md5.js

7. 安全与鉴权

机制实现风险与建议
Web 登录Session is_login + 单密码 conf.ini login_pwd无用户名、无 bcrypt；建议生产改用哈希存储 + HTTPS
API Tokenaccess_token 可选校验明文配置；建议环境变量注入
回调签名api_key + MD5业务方验签防伪造；api_key 为空则不签名
SQL部分 raw SQL 字符串拼接（delete）存在注入风险，建议改为 ORM 参数化
体验模式is_dev=1 时登录页显示明文密码仅用于演示环境

12. 专业评估与改进建议

12.1 优势

  • 功能闭环完整：配置 → 调度 → 回调 → 日志 → 告警 → API 集成
  • Cron 表达式校验详尽，与 APScheduler 语义对齐
  • 集群场景考虑周全（双锁机制 + JobStore 持久化）
  • 部署门槛低，Docker 开箱即用

12.2 技术债与风险

  • 安全 单密码 Session、SQL 拼接；Flask 1.1 / SA 1.4 仍待 Tier 3/4 代际升级；gunicorn 22 + gevent 23（RFC-2.1/2.2），路线见 依赖升级 RFC
  • 代码 views.py 校验逻辑 Web/API 大量重复，维护成本高
  • 前端 Jumbotron 每页重复、无组件化、响应式弱
  • 架构 多 worker 各启 Scheduler，依赖锁而非单 leader 选举
