任务编辑基线工具语义漂移修复

2026-11-03 · 用户确认设计后实施 · 专项验证通过

设计及最新验收：术语门禁与任务编辑基线工具修复设计。本次仅修复工程工具及文档；完整发布结论以设计末节为准。

1. Bug 定位

scripts/verify_cron_edit_baseline.py 未创建关联组，先被当前关系完整性检查拒绝；旧断言仍把无变更时的关系重建、日志及调度写视为预期。补组数据不能解决语义失效。

2. 根因

历史缺陷实验与长期验收共用默认入口，服务契约演进时没有同步该入口，也没有版本化历史预期。人工阅读旧成功记录无法证明今天的命令仍可运行。

3. 测试漏洞

原单元测试覆盖服务，但没有运行这个独立工具，未检查场景集合完整性；因此 fixture 和断言同时过期。仅验证输出 OK 会遗漏断言被删除或故障注入未命中的情况。

4. 修复

旧脚本按原字节归档并记录 SHA256。默认入口改为六项 current_contract：无变化、无关合并、同字段冲突、调度失败、审计失败、暂停注册。完整创建组/用户/关联/标签，使用真实签名 T0 与保存服务、内存 SQLite 和独立全局暂停调度器。观测实际业务/关系 DML、提交、审计、revision、Job 和故障命中次数；finally 清理。CLI 对异常、遗漏场景或断言失败非零退出。

5. 防护测试

tests/test_cron_edit_baseline.py 六项通过：实际子进程六场景、额外提交、冲突后部分写入、错误恢复暂停任务、缺场景、未知场景。三类真实行为变异均被断言捕获。新工具实际输出 CRON_EDIT_BASELINE: OK cases=6 mode=current_contract；相关两项工具与编辑回归共 73 项通过。

6. 同类排查

核对 M1 与无变化设计中的旧命令/旧观测并追加历史说明；当前入口与归档实验明确分离。直接 update_cron 只验证自身返回契约，Web 冲突经过真实签名快照服务；内存顺序场景不替代跨连接权限竞态验证。未改变 app/ 服务契约。

7. 预防方案

新增命令级子进程测试及完整场景集合检查，落点 tests/test_cron_edit_baseline.py 和脚本 main；进入既有 unittest discover。第三方运行下方命令即可复验，删除一个场景或加入额外提交会使测试失败。历史脚本在 evidence/ 中仅作实验快照，不再作为发布验收入口。

可执行验收

.venv-py311/bin/python scripts/verify_cron_edit_baseline.py
.venv-py311/bin/python -m unittest tests.test_cron_edit_baseline -v
