## 2. P0-1：CpConfirm 参数名修复

### 2.1 根因

`redesign-confirm.js` 的 `CpConfirm.show()` API 使用 `body` 属性读取对话框正文（第 31 行：`var body = opts.body || ''`），但 `task_detail.html` 在 2 处调用中传入了 `message`（行 153、186），该属性被静默忽略。

### 2.2 方案

| 文件 | 行号 | 修改前 | 修改后 |
| --- | --- | --- | --- |
| `app/templates/redesign/task_detail.html` | 153 | `message: '确认立即触发该任务？',` | `body: '确认立即触发该任务？',` |
| `app/templates/redesign/task_detail.html` | 186 | `message: '确认' + action + '该任务？',` | `body: '确认' + action + '该任务？',` |

### 2.3 范围

仅修改 `task_detail.html`，2 处字符串替换。不影响其他 6 处正确的 `CpConfirm.show()` 调用。

### 2.4 验收

1. 访问任务详情页 → 点击「立即执行」→ 确认对话框正文显示「确认立即触发该任务？」
2. 点击「暂停」→ 确认对话框正文显示「确认暂停该任务？」
3. `grep -n "message:" app/templates/redesign/task_detail.html` 无 CpConfirm 相关匹配

### 2.5 风险

极低 纯文本替换，不影响逻辑。

## 3. P0-2：开放重定向修复

### 3.1 根因

登录成功后 `redirect(next_url)` 未校验 `next_url` 是否为站内 URL。攻击者可构造 `?next=https://evil.com` 实现钓鱼跳转。涉及文件：

- `app/rbac/views.py:243` — `redirect(next_url)`
- `app/main/views.py:1201-1202` — `check_pass` 路由透传 `next`
- `app/rbac/decorators.py:17-18` — 装饰器拼入 `next`（此处来源安全，但其他入口不安全）

### 3.2 方案

新增 `app/rbac/safe_redirect.py` 工具函数：

```
from urllib.parse import urlparse

def safe_next_url(next_url, default='/cron_list'):
    """仅允许相对路径或同 Host 的 next URL，拒绝外部跳转。"""
    if not next_url:
        return default
    parsed = urlparse(next_url)
    # 拒绝含 scheme 或 netloc 的 URL（如 https://evil.com）
    # 同时拒绝协议相对 URL（如 //evil.com）
    if parsed.scheme or parsed.netloc or next_url.startswith('//'):
        return default
    return next_url
```

在所有 `redirect(next_url)` 调用点使用 `safe_next_url()` 包装：

| 文件 | 修改前 | 修改后 |
| --- | --- | --- |
| `app/rbac/views.py:243` | `return redirect(next_url)` | `return redirect(safe_next_url(next_url))` |
| `app/rbac/views.py:193` | `next_url = request.values.get('next', '/cron_list')` | `next_url = safe_next_url(request.values.get('next', ''))` |
| `app/main/views.py:1201-1202` | `next_url = request.args.get('next', '')` | `next_url = safe_next_url(request.args.get('next', ''))` |

### 3.3 范围

- 新增：`app/rbac/safe_redirect.py`（~15 行）
- 修改：`app/rbac/views.py`（2 处）、`app/main/views.py`（1 处）
- 新增测试：`tests/test_safe_redirect.py`
- **不做**：不修改 `decorators.py`（其 `next_url` 来自 `request.full_path`，一定是相对路径，无风险）

### 3.4 验收

1. 单测：`safe_next_url('https://evil.com')` → `/cron_list`
2. 单测：`safe_next_url('//evil.com')` → `/cron_list`
3. 单测：`safe_next_url('/rbac/users')` → `/rbac/users`（保留）
4. 单测：`safe_next_url('')` → `/cron_list`
5. 浏览器：登录成功后 `?next=https://evil.com` → 跳转到 `/cron_list`，而非外部站点
6. 浏览器：正常 `?next=/rbac/users` → 登录后跳转到 `/rbac/users`（功能不受影响）

### 3.5 风险

低 仅影响包含外部 URL 的 `next` 参数（正常使用不会出现）。极端情况：如果有内部 URL 含 `//` 开头（理论上不应该），会被错误拦截。

## 4. P0-3：异常文本泄露修复

### 4.1 根因

`app/main/views.py:901` 的 `cron_add` 在 `except Exception` 中将 `str(e)` 直接返回给前端，可能泄露数据库引擎/表名/内网 IP/文件路径等敏感信息。

### 4.2 方案

| 修改前 | 修改后 |
| --- | --- |
| ``` except Exception as e:     trace_info = traceback.format_exc()     wechat_info_err(str(e), trace_info)     return web_api_return(code=1, msg=str(e)) ``` | ``` except Exception as e:     trace_info = traceback.format_exc()     wechat_info_err(str(e), trace_info)     current_app.logger.error('cron_add exception: %s\n%s', e, trace_info)     return web_api_return(code=1, msg='服务器内部错误，请稍后重试') ``` |

### 4.3 范围

- 修改：`app/main/views.py`（1 处，第 901 行）
- 新增：一行 `current_app.logger.error` 确保异常信息不丢失
- **不做**：不修改 `crons.py` 中的 `str(e)`（用于服务端日志/微信推送，不返回前端）

### 4.4 验收

1. 提交重复任务名触发 IntegrityError → 前端收到「服务器内部错误，请稍后重试」，**不显示**数据库细节
2. 服务端日志（`datas/logs/error.log.*`）记录完整异常栈
3. 微信告警仍正常推送

### 4.5 风险

低 用户不再看到具体错误原因（如"任务名已存在"），改为通用提示。运维可从日志中获取详情。未来可通过 `add_cron_web` 的业务校验层（而非 catch-all）返回友好的业务错误信息。

## 5. P0-4：Escape 键守卫选择器修复

### 5.1 根因

`task_detail.html:237` 和 `task_form.html:339` 使用 `.cp-confirm-overlay` 检查对话框是否打开，但实际 class 为 `.cp-modal-overlay`。此外 `[style*="flex"]` 属性选择器不可靠（样式可能来自 CSS 而非 inline style）。

### 5.2 方案

| 文件 | 修改前 | 修改后 |
| --- | --- | --- |
| `task_detail.html:237` | `!document.querySelector('.cp-confirm-overlay[style*="flex"]')` | `!document.querySelector('.cp-modal-overlay')` |
| `task_form.html:339` | `!document.querySelector('.cp-confirm-overlay[style*="flex"]')` | `!document.querySelector('.cp-modal-overlay')` |

**为什么去掉 `[style*="flex"]`**：`.cp-modal-overlay` 元素在创建时直接 `appendChild` 到 `document.body`，关闭时 `removeChild` 移除。因此只需检查该元素**是否存在于 DOM 中**即可，无需检查 display 状态。

### 5.3 范围

- 修改：`task_detail.html`（1 处）、`task_form.html`（1 处）
- **不做**：不修改 `redesign-confirm.js`（行为正确）

### 5.4 验收

1. 任务详情页：点击「立即执行」→ 对话框弹出 → 按 Escape → 对话框关闭，**页面不跳转**
2. 任务详情页：无对话框时按 Escape → 正常跳回任务列表
3. 任务编辑页：同上，Escape 关闭对话框而非 `history.back()`
4. `grep "cp-confirm-overlay" app/templates/redesign/` — 无匹配

### 5.5 风险

极低 纯选择器字符串修正。
