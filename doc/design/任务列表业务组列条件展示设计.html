任务列表业务组列条件展示设计

状态：待确认 · 2026-08-27 · Redesign Dashboard

1. 问题

Redesign Dashboard 的任务列表始终展示「业务组」列（COL 6）和组筛选下拉。对于仅属于单个业务组的用户（Operator / Viewer），该列每行显示相同的组名，信息熵为零，是纯视觉噪音。组筛选下拉也仅有 1 个选项 + "全部"，无实际筛选价值。

2. 根因

模板未根据用户可见组数量条件渲染，始终输出 7 列表格和组筛选控件。

3. 方案

后端计算 show_group_column = len(scope_groups) > 1，模板通过该标志条件展示：

  • show_group_column = True：展示业务组列 + 组筛选下拉（当前行为）
  • show_group_column = False：隐藏业务组列（表格变 6 列），隐藏组筛选下拉

角色scope_groupsshow_group_column列数

备选方案对比

方案描述结论
A. 条件隐藏列（推荐）模板 if 控制整列显隐实现简单、彻底消除噪音
B. 内联 badge组名挂在任务名下方单组仍有重复噪音
C. 列折叠保留列但最小宽度仍占空间、实现更复杂
D. 用户偏好持久化列可见性设置过度设计

4. 范围

文件变更
app/main/views.pycron_list 中计算 show_group_column，传给全页和 AJAX partial 两条渲染路径
app/templates/redesign/dashboard.html<th class="hfc-group"> 和组筛选下拉包裹 {% if show_group_column %}
app/templates/redesign/_dashboard_rows.htmlCOL 6 <td> 包裹 {% if show_group_column %}

不做：v1 cron_list.html 没有独立业务组列，无需改动。

5. 分批

单批完成（改动量小，3 个文件 ≈ 10 行条件模板 + 1 行 view 变量）。

6. 验收

  1. bash scripts/cronpilot.sh restart --daemon
  2. 单组用户登录 → Dashboard 表格为 6 列，无「业务组」列头，无组筛选下拉
  3. 多组用户或 Admin 登录 → Dashboard 表格为 7 列，有「业务组」列，有组筛选下拉
  4. AJAX 翻页/筛选后列数不变
  5. python scripts/smoke_routes.py --check 通过

7. 风险

  • 用户被加入第 2 个组后列突然出现 — 低频操作且符合预期，可接受
  • AJAX partial 渲染需同步传入 show_group_column — 已在范围中明确覆盖
