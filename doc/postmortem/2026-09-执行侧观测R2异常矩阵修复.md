# 执行侧观测 R2 异常矩阵修复复盘

日期：2026-09-18 · 状态：已修复并验证

## 1. Bug 定位

`exception_failure_info()` 将 `ConnectionError`、`SSLError` 和 `TooManyRedirects` 一律写为 `connect_failed`。Run Inspector 因而会在请求已进入客户端、远端可能已参与时显示“连接未建立”。

## 2. 根因

实现按 Requests 的宽泛异常基类归类，忽略了异常子类和 `TooManyRedirects.response` 所携带的响应边界证据；分类逻辑把“连接类异常”错误等同于“连接尚未建立”。

## 3. 测试漏洞

原测试只断言裸 `ConnectionError` 为连接失败，未覆盖 ProxyError、SSLError、远端断连语义，以及带/不带 response 的 TooManyRedirects 分支。

## 4. 修复

仅 `ConnectTimeout` 与 `ProxyError` 使用 `connect_failed`；宽泛 `ConnectionError` 和 `SSLError` 保守使用 `sent_no_response`。TooManyRedirects 有 response 时记录为 `remote_response/response_received`，并持久化其 HTTP 状态；无 response 时记录为 `sent_no_response`。新增 `redirect_limit` 失败原因标签。

## 5. 防护测试

新增异常矩阵断言，覆盖 ProxyError、ConnectionError、SSLError、带 response 的 TooManyRedirects 与无 response 的 TooManyRedirects；并运行 Presenter、观测契约和静态质量检查。

```
.venv-py311/bin/python -m unittest tests.test_job_log_outcome tests.test_run_inspector_presenter tests.test_execution_observability_contract -v
.venv-py311/bin/ruff check app/
.venv-py311/bin/python scripts/check_ui_contract.py --check
```

## 6. 同类排查

已核对 cron 请求异常写入路径：分类值同时写入 JobLog 与 `http.error`/`http.timeout` 事件；当分类确认响应已收到时，`response_received` 和 `http_status` 同步写入，避免 DTO 与存储字段相互矛盾。HTTP 业务 4xx/5xx 判定和历史 transport\_state 兼容未改动。

## 7. 预防方案

在 `tests/test_job_log_outcome.py` 固化异常矩阵：每次新增 Requests 异常分支，必须同时断言 `failure_stage`、`fail_reason`、`transport_state`，并对可带 response 的异常覆盖带/不带 response 两条路径。该测试由全量 unittest discover 执行，可直接阻断重新把宽泛异常写成 `connect_failed` 的回归。
