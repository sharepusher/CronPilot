B-13 API Auth 暴力破解限流

状态：已交付
关联：API 安全与质量全面评估 §3.1 B-13
日期：2026-08-28

1. 问题

/api/auth/token 端点接受用户名+密码换取 API Token，但无任何频率限制。 攻击者可无限速发送暴力破解请求，尝试猜解合法用户密码。

Web 登录（/rbac/login）已在 OPT-P0-13 中接入 LoginLimiter（IP 50次/15分 + 用户名 50次/30分）， 但 API 端点完全未接入同一限流器。

2. 根因

OPT-P0-13 实施 Web 登录限流时，API auth 端点尚未创建（或未纳入同批次）， 后续新增 api_auth_token 时未检查是否需要对等接入限流。

3. 方案

在 api_auth_token() 函数体内复用现有 LoginLimiter 三步模式（与 Web 登录完全对称）：

  1. 入口检查：在校验凭据之前调用 check_login_limit(client_ip, username)， 被锁时返回 429 Too Many Requests（含 Retry-After header）
  2. 失败记录：凭据校验失败时调用 record_login_failure(client_ip, username)
  3. 成功清除：凭据校验成功时调用 record_login_success(client_ip, username)

设计决策：API 和 Web 共享同一个进程内 LoginLimiter 实例。 攻击者在 API 端点的失败计数会同步影响 Web 登录（反之亦然）， 这是期望行为——同一凭据无论从哪个入口尝试都应累计。

4. 范围

文件变更
app/api/views.pyapi_auth_token() 新增 3 处 limiter 调用
tests/test_api_scope_s6.py新增 TestApiAuthLimiter 测试类

不做：不修改 LoginLimiter 本身；不引入 Redis 后端；不新增 API 专用阈值。

5. 分批

单批交付（修改 1 文件 + 测试 1 文件），可独立验收。

6. 验收

  1. python -m unittest tests.test_api_scope_s6.TestApiAuthLimiter -v 通过
  2. bash scripts/cronpilot.sh test 全量通过
  3. python scripts/smoke_routes.py --check 通过
  4. 手动 curl 验证：连续发送错误密码请求 → 达到阈值后返回 429

7. 风险

  • 误锁合法用户：阈值 50 次/15分钟，正常使用不会触发；且成功登录后自动清除计数
  • 多 worker 不共享：与 Web 登录限流的已知限制相同，进程内有效
  • API/Web 互锁：共享计数器意味着 API 暴破也会锁 Web 登录；这是期望的安全行为
