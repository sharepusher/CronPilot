# 个人资料页补充个人信息设计

已确认 2026-08-26

## 1. 问题

当前 `/rbac/profile` 页面仅展示可编辑字段（花名、邮箱、岗位类型）和两个只读身份字段（账号、角色），缺少用户关心的**所属业务组**信息。同时页面一打开即为编辑状态，不符合「查看 > 修改」的低频编辑场景最佳实践。

## 2. 根因

个人资料页（Y1 feature）实现时仅聚焦于"自助修改"场景，未将只读元信息纳入设计范围，也未区分查看与编辑两种用户意图。

## 3. 方案

### 3.1 新增字段

| 字段 | 数据来源 | 显示格式 | 缺失兜底 |
| --- | --- | --- | --- |
| 所属业务组 | `get_user_group_ids(user.id)` → 查 `ResourceGroup.name` | 逗号分隔组名（如「研发组, 运维组」） | `未分配` |

**不展示**创建时间和最近登录时间（这些信息对自助用户价值低，保留在管理端用户列表页）。

### 3.2 交互模式：查看优先

页面默认以**查看模式**呈现所有信息（含只读 + 可编辑字段），点击「编辑」按钮后切换为编辑模式。

| 模式 | 行为 |
| --- | --- |
| **查看模式**（默认） | 所有字段以纯文本展示；右上角显示「编辑」按钮；无表单提交能力 |
| **编辑模式**（点击编辑后） | 可编辑字段变为 input/select；显示「保存」和「取消」按钮；取消恢复为查看模式 |

### 3.3 视觉设计

- 复用已有 `.pw-card` 容器
- 查看模式下每行：`.pw-label` + `<span class="pf-value">`（纯文本值）
- 编辑模式下复用当前表单结构
- 通过 JS 切换 `.pf-view-mode` / `.pf-edit-mode` 类控制显隐
- 「所属业务组」行始终为只读（查看和编辑模式均为文本展示）

### 3.4 决策记录

- **不采用时间字段**：创建时间和最近登录对自助用户价值低，保留在管理端
- **不采用直接编辑**：个人资料修改频率低，查看优先防误操作、符合行业惯例

## 4. 范围

### 改动文件

| 文件 | 改动内容 |
| --- | --- |
| `app/rbac/views.py` | `edit_profile()` 增加模板上下文：`user_groups_display`（组名逗号字符串） |
| `app/templates/redesign/user_profile.html` | 重构为查看/编辑双模式；新增「所属业务组」只读行 |
| `app/static/css/redesign-pages.css` | 新增 `.pf-value` 文本样式（1-2 行） |

### 明确不做

- 不修改 `complete_profile.html`（首次补全页保持现状）
- 不展示创建时间/最近登录时间
- 不修改数据模型
- 不新增 CSS 文件（写入 `redesign-pages.css`）

## 5. 分批

单批完成（改动量小，3 个文件）。

## 6. 验收

1. `bash scripts/cronpilot.sh restart --daemon`
2. 以任意已登录用户访问 `http://127.0.0.1:5001/rbac/profile`
3. 默认为**查看模式**：所有字段以纯文本展示，含「所属业务组」（或「未分配」）
4. 点击「编辑」按钮后切换为编辑模式：花名/邮箱/岗位变为可编辑 input
5. 编辑模式下保存功能正常（AJAX 提交，成功后回到查看模式）
6. 点击「取消」回到查看模式，字段值未变
7. 所属业务组在两种模式下均为只读文本

## 7. 风险

- 低风险：主要是前端交互重构，后端仅增加一个只读上下文变量
- JS 切换逻辑简单（显隐两组 DOM），无复杂状态管理
