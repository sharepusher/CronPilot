# 评估交付格式与测试状态漂移复盘

**日期**：2026-09-11　**类型**：文档质量与交付流程复盘

## 1. Bug 定位

对近期提交的 P1/P2 深度评估最初以仓库外 Canvas 交付，未形成仓库内 HTML+Markdown 文档，也未登记 `doc/index.html`/`doc/index.md`。同时 `doc/design/测试Session补齐auth-version修复设计.html` 与索引标为“已交付”，但定向测试仍可复现 3 个失败与 2 个错误。

## 2. 根因

审查工作流把“分析结果呈现”误当作可使用非文档产物的临时输出，未把仓库规定的 HTML+Markdown+索引注册当作总结/评估的完成条件。已有 P1 设计文档的状态未与最新回归执行结果重新核对，造成“历史交付标记”覆盖“当前可验证状态”。

## 3. 测试漏洞

现有 `check_doc_completeness.py` 只校验仓库内 HTML 是否被索引引用，无法发现仓库外评估产物；也不校验设计文档“已交付”状态与相关测试当前结果的一致性。人工审查没有在引用“已交付”状态前重跑其定向验收命令。

## 4. 修复

删除仓库外 Canvas，新增本复盘与 `doc/design/近期提交P1-P2问题深度评估与修复设计-2026-09.html`，生成对应 Markdown，并登记总索引和复盘索引。将原 P1 设计与总索引状态改为“待修复”，明确当前失败证据。

## 5. 防护测试

运行 `python scripts/html_docs_to_markdown.py --check` 验证 HTML/Markdown 同步；运行 `python scripts/check_doc_completeness.py --check` 与 `python -m unittest tests.test_check_doc_completeness -v` 验证新增文档和复盘均已登记。P1 状态的事实依据由 `tests.test_job_log_detail_integration` 与 `tests.test_cron_run_now` 的定向测试输出提供。

## 6. 同类排查

本轮检查发现总索引已有 HTML/MD 双链机制，并确认新文档按此机制登记；外部 Canvas 已删除。没有修改用户已有的其他未提交文档内容。

## 7. 预防方案

在 `AGENTS.md` 新增“审查、总结、评估”交付约束：凡需持久化或引用仓库事实，必须落 `doc/` HTML 源文档及生成 Markdown，并在 `doc/index.html`/`doc/index.md` 注册；不得以 Canvas、聊天或仓库外文件替代。每次标注“已交付/已完成”前，必须在文档写入对应最新验收命令及结果。第三方可通过上述两条文档门禁和定向测试命令复现检查。
