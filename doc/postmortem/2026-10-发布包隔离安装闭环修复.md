# 发布包隔离安装闭环修复复盘

日期：2026-10-14 · 范围：4.1.0 自定义公开安装包 H5 · 状态：已修复并通过仓库外黄金路径

## 1. Bug 定位

1. 全新虚拟环境安装 `requirements-core.txt` 时解析失败：`croniter==6.0.0` 要求 `pytz>2021.1`，仓库仍固定 `pytz==2020.1`。
2. 第一版发布白名单遗漏运行时 `/docs/` 必需的 `doc/index.html` 与 `doc/deps/依赖升级RFC.html`，服务可启动但三个文档冒烟端点返回 404。
3. 纳入 `doc/index.html` 后，独立链接闭包校验发现索引仍保留 13 个已删除旧截图路径/目录链接。

## 2. 根因

- 既有开发虚拟环境保留了历史上已安装的冲突组合，日常测试没有重新执行现代 pip 的全新依赖求解，掩盖了锁文件不可安装事实。
- 白名单初版把文档只当发布说明，未逆向读取 `app/docs/views.py` 与 `scripts/smoke_http.sh` 确认文档也是运行时 HTTP 面。
- 图片迁移只覆盖 `<img src>` 与 Markdown 图片语法，没有覆盖索引中作为普通 `<a href>` 的图片快捷入口。

## 3. 测试漏洞

- 本地 `verify_install_flow.sh` 默认复用已有 venv，不能证明 requirements 可从零解析。
- 发布包在此次 H5 之前没有仓库外解压、安装、双重启和 HTTP 冒烟门禁。
- 图片专项门禁负责真实图片属性，不负责普通文档链接；只有将包内文档纳入独立链接闭包后才暴露旧快捷入口。

## 4. 修复

- 将 `requirements.txt` 与 `requirements-core.txt` 的 pytz 同步固定为 `2026.1.post1`，满足 croniter 6.0.0 下界并保持 Python 3.8–3.11 兼容。
- 白名单最小补入 `doc/index.html/.md` 与依赖 RFC 双格式；未放宽到整个 `doc/`，历史截图仍排除。
- 删除索引中的旧截图路径快捷入口，改为指向内容寻址 manifest、治理设计和复盘。
- tag workflow 固定执行图片门禁、双构建比较、独立包校验、仓库外安装/启动黄金路径；全部通过后创建或恢复草稿 Release、上传三项资产，最后才发布。已发布的同名 Release 拒绝覆盖。

## 5. 防护测试

- 全新临时 venv 成功安装 `requirements-core.txt`；`tests.test_requirements_timezone_contract`、cron 展示和下次执行共 16 项通过。
- 当前完整工作树临时 Git commit 双构建：274 文件、629,528 字节，SHA-256 均为 `546de32ac946bed8d18b933318db83c72ef04626c61358e3b324f01ca65d866b`。
- 独立包校验通过；仓库外黄金路径的 home、docs、docs index、docs RFC、登录页、登录 POST、API、任务列表、404 与隔离数据库全部通过。

## 6. 同类排查

检查 package manifest 中全部精确项与目录前缀、运行时脚本引用、包内 HTML/Markdown 本地链接以及禁止文件后，未发现其他缺失运行项、截图哈希、测试基线、数据库、日志、PID、密钥或本地配置。两份 requirements 的 pytz pin 已对齐。

## 7. 预防方案

1. **依赖契约：**`tests/test_requirements_timezone_contract.py` 固定检查两份 pin 一致且高于 croniter 6 明确拒绝的版本区间；`install-full.yml` 继续覆盖 Python 3.8–3.11 全新安装。
2. **运行面逆向：**`release/package-manifest.txt` 的运行时文档项以 `app/docs/views.py` 和 `scripts/smoke_http.sh` 为依据；修改任一文件时必须重跑包黄金路径。
3. **链接闭包：**`scripts/check_release_asset.py` 独立解析包内文档本地链接，构建器只能将仓库中存在但未入包的目标确定性改写为固定 ref URL。
4. **正式发布：**`.github/workflows/release-asset.yml` 只从 tag Git 对象构建，禁止工作树和未跟踪文件进入；正式 4.1.0 必须重复当前全部验收。
