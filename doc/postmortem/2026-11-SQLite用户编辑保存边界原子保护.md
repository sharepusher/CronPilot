# SQLite 用户编辑保存边界原子保护修复复盘

日期：2026-11-02 · 状态：**RBAC用户编辑缺口已修复并通过专项验收；任务子项和全量既有失败保留。** 用户已授权评估批准设计并实施，包含临时文件集成例外。未commit或发布。

[设计及分批评估](../design/SQLite用户编辑保存边界原子保护设计-2026-11-02.html) · [完整验收](../qa/SQLite用户编辑原子保护验收-2026-11-02.html)。

## 1. Bug定位

update\_user\_management在SQLite上使用只在其他后端生效的FOR UPDATE，读取当前actor/target后到提交前允许独立连接写入。已复现管理员被降权后旧请求仍保存、同字段新值被旧请求覆盖。既有MySQL锁释放和串行页面绿色结果没有覆盖该SQLite交错。新预览工厂接入docs蓝图时遗漏BASEDIR配置，首次文档访问500，已补齐并重启验证。

## 2. 根因

把ORM逻辑事务与后端物理保护视作同一保证，设计与验证没有分别校准驱动读事务、SQLite方言和MySQL行锁。代码有事务和三方比较，但前置读取未保护到写入完成。行为层选择了容易观察的顺序结果，遗漏读取与写入之间的独立提交。

## 3. 测试漏洞

内存单连接与串行HTTP可以验证业务结果，不能证明文件写者排他；旧同步注入诊断适合复现缺口，修复后会让持锁方等待竞争方而卡住。若只将observed改成false或只看到数据库忙，就可能把错误测试当成修复成功。入口rollback及清理失败也缺少明确的错误边界。新预览只核对了docs蓝图符号，未在初次装配时核对路由的配置依赖，缺少实际文档请求预检。

## 4. 修复

- 新增sqlite\_write\_boundary，取得同一Session/模型bind的SQLite即时写事务后才重读授权和当前数据；MySQL保持原锁流程。
- busy\_timeout临时0仅控制获取保护，随后立即恢复；恢复失败失效连接，不污染池；不自动重试业务。
- 入口rollback移入受控异常边界，终态rollback失败记录原异常并尽力invalidate，不覆盖原阶段或假报成功；commit后异常仍未知。
- 服务开始即拒绝待提交ORM工作；明确不能据new/dirty/deleted为空证明无原生SQL待写，顶层调用契约与路由零DML守卫继续保留。
- 仅生产helper与用户服务有本批代码变更；函数外内容对照实施前副本一致，未顺手重构任务或其他用户写入口。

## 6. 同类排查

核对用户编辑唯一应用调用方、停用入口和组服务的事务归属；不宣称其他写服务都获得完整保护。任务保存按当前接口重新诊断，两模式仍可复现actor撤权后旧任务保存，已作为范围外开放项留证。旧锁释放及七状态回归继续通过，不以本次修复推翻原有有效结论。

验证工具自身也需隔离全局调度资源：既有冒烟初次沿用全局JobStore报错的尝试不算有效验收；隔离配置、关闭执行后重跑通过。复制历史截图导致临时空间不足后，仅清理本轮创建的副本并改最小源码清单。原环境未重建，源码与历史证据未删除。

## 7. 预防方案

1. **可验证的原子边界：**tests/test\_user\_edit\_sqlite\_boundary.py固化保护先于授权读、同Session连接、参数恢复、异常失效和MySQL不发SQLite SQL等否定路径；命令`python -m unittest tests.test_user_edit_sqlite_boundary -q`必须通过。
2. **真竞争与反向校准：**scripts/verify\_user\_edit\_sqlite\_boundary.py对DELETE/WAL强制无保护/持保护/释放对照、固定业务及两服务浏览器矩阵；缺阶段、超时、未命中、物理路径不符、缺结果一律失败，全部临时文件清理后才输出passed。第三方用新空输出目录重跑验证。
3. **预览文档装配：**preview\_user\_edit\_sqlite\_boundary.py在发布本机登录信息、启动端口前，用真实test\_client请求/docs/index.html，非200或异常立即拒绝启动；交付再curl核验每份HTML/Markdown。该新增可执行预检覆盖缺BASEDIR等路由装配错误，不能只检查配置字符串。
4. **内容基线与发布边界：**每次验收记录代码范围指纹；工作区HEAD不替代未提交内容。全量失败与剩余任务问题必须独立列出，不允许用专项成功覆盖，证据schema明确scope=rbac\_user\_edit\_only。新增/改测试工厂仍需核验业务库和全局JobStore，不能仅凭内存业务URI推定所有资源隔离。
