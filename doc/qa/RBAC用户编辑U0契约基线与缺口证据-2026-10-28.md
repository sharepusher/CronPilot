# RBAC 用户编辑 U0 契约基线与缺口证据

## 1. U0 范围与方法

- 一次性 harness：`/private/tmp/cronpilot_u0_user_edit_harness.py`，使用 `create_app('testing')` 间接构建的测试应用和内存 SQLite，不导入 `manage`。
- fixture：全局 admin、启用/停用目标、一个业务组、用户组关系和审计表。
- 业务观测：返回结果、DML 次数、commit 次数、审计增量、缓存失效次数和最终数据库事实。
- 本批只诊断与冻结测试规格；不新增故意失败的仓库测试，不修改服务、路由、模板或 JavaScript。

## 2. 当前缺口的运行证据

| 场景 | 实测结果 | 目标契约 | 判定 |
| --- | --- | --- | --- |
| 全字段原样提交 | 返回成功；2 次 commit；1 次 DML（成功审计 INSERT）；1 条审计；缓存失效 1 次；源码在差异判断前已构造 `FOR UPDATE`。 | `NO_CHANGE`；0 行锁、0 DML、0 写 commit、0 审计、0 缓存副作用。 | **缺口稳定复现** |
| 非空邮箱提交为空 | 返回成功；邮箱仍为 `old@example.invalid`；新增 1 条审计；2 次 commit；缓存失效 1 次。 | 缺少确认/理由时零写入；有效确认后存 SQL `NULL`，理由与 before/after 同事务审计。 | **意图被静默丢弃且误记成功** |
| 路由校验后 actor 在数据库降为 viewer | 服务没有 `actor_user_id` 参数；直接调用仍返回成功并把目标花名改为 `changed-with-stale-actor`。 | 写边界锁定并复核数据库当前 actor、角色与 Scope；无权时零业务变化。 | **服务边界授权缺失** |
| 停用目标直接调用服务 | 目标保持停用，但资料仍被改为 `changed-while-disabled` 并返回成功。 | 停用目标 GET/POST 均不允许编辑；固定去只读详情。 | **路由策略未在写边界闭合** |
| 业务成功后审计丢失 | 模拟审计写入无结果时，目标花名已持久化为 `business-without-audit`，新增审计 0，服务仍返回成功。 | 业务与成功审计同一事务；任一失败全部回滚。 | **双事务缺口稳定复现** |

## 3. 冻结的签名快照契约

使用 `URLSafeSerializer(secret_key, salt='rbac-user-edit-snapshot-v1')` 的运行验证结果为：roundtrip 通过、篡改拒绝、禁止字段未出现。

| 项目 | 冻结值 |
| --- | --- |
| 精确键集合 | `actor_user_id`、`email`、`group_ids`、`job_title`、`nickname`、`role`、`schema_version`、`target_user_id` |
| 固定版本 | `schema_version == 1` |
| 组格式 | 去重、升序整数数组；全局 admin 持久化事实为零关系行，快照规范值使用空数组，表单 marker 仍为 `__ALL__`。 |
| 拒绝条件 | 签名无效、版本未知、任一键缺失/多余、类型错误、actor/target 与当前请求不匹配。 |
| 禁止进入载荷 | 密码、密码哈希、API Token、Token 过期时间、auth\_version、Session、CSRF、状态原因及其他未回显字段。 |

## 4. 冻结的规范化与差异规则

| 字段/单元 | 规范化 | 意图比较 |
| --- | --- | --- |
| email | 字段必须存在；trim；空值为 `None`；非空包含 `@` 且不超过 128。 | 原非空→请求空必须确认标志和 1–500 字 trim 后理由。 |
| nickname | trim；空为 `None`；最长 64。 | 独立资料字段。 |
| job\_title | 必填；标准枚举或 `other:` + 1–20 字；禁止静默截断。 | 独立资料字段。 |
| role + group\_ids | 角色必须为现有三角色；组去重升序；`__ALL__` 只允许合规全局 admin。 | 作为一个耦合授权单元三方比较，禁止混合两个时点。 |
| is\_active | 编辑端点不接收。 | 只读展示；停用走专用流程。 |

## 5. 冻结的结果与响应契约

| 结果 | 终态 | Ajax | 原生 POST |
| --- | --- | --- | --- |
| `UPDATED` | 是 | `errcode=0`，跳用户列表。 | 303/302 PRG 到用户列表。 |
| `NO_CHANGE` | 是 | `errcode=0`、`data.outcome=no_change`、无 URL，Toast 后留页。 | PRG 回编辑页，固定提示。 |
| `ALREADY_APPLIED` | 是 | `errcode=0`、`data.outcome=already_applied`、无 URL。 | PRG 回编辑页，固定提示。 |
| `CONFLICT` | 是 | `errcode=1`、`data.outcome=conflict`，要求刷新。 | PRG 回编辑 GET，重新读取数据库。 |
| `FAILED` | 是 | `errcode=1`；字段错误可带固定 field key。 | PRG 或安全回显，不重复提交。 |
| `COMMIT_UNKNOWN` | 是 | `errcode=1`、`data.outcome=commit_unknown`，禁止自动重试。 | PRG 回编辑 GET，固定警示。 |
| `CONFIRM_REQUIRED` | 否 | `errcode=1`、`data.outcome=confirm_required`；页面收集理由后由管理员再次明确提交。 | 安全回编辑页；不得通过 URL 携带理由。 |

## 6. U1/U2 永久测试规格

正式测试文件固定为 `tests/test_user_edit_change_set.py`，必须使用内存 SQLite，不导入 `manage`。U1 先落地纯函数与写前拒绝用例，U2 再落地真实事务和 MySQL 锁用例。

- 快照：roundtrip、篡改、未知版本、缺/多键、错误类型、actor/target 不匹配、禁止字段零出现。
- no-op：全字段相同、组顺序变化、重复组、全局 admin `__ALL__`，均断言锁/DML/commit/审计/Token/缓存为 0。
- 邮箱：取消不 POST；缺确认、空/超长理由零写入；有效理由 trim；原值冲突不覆盖；当前已为空为 `ALREADY_APPLIED`。
- 三方比较：资料字段独立；授权单元耦合；任一冲突整体拒绝，不部分保存。
- 副作用：资料-only 不 bump/不重签/不失效；角色或组有效变化只 bump、重签、失效一次。
- 审计：仅 `UPDATED` 产生；changes 键精确等于五字段白名单与有效差异交集；理由只在邮箱清空；凭据值零出现。
- 故障注入：审计 add/flush 失败整体回滚；commit 抛错分类 `COMMIT_UNKNOWN`；授权尝试后 best-effort 缓存失效。
- 锁：SQLite 验证调用边界；真 MySQL 双连接验证 `CONFLICT`/`ALREADY_APPLIED`/锁后失败均立即释放。
