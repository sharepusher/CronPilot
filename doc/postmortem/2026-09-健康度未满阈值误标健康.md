# 健康度未满阈值误标「健康」复盘

**日期**：2026-09-16 · **类型**：UX / 健康模型 · 设计
[方案 A](../design/健康度未满阈值误标健康修复设计-2026-09.html)

## 1. Bug 定位

任务 `testgoogle`：`job_log.status=error`，
`job_health.consecutive_failures=1`，
`health_status=ok` → Dashboard 健康列渲染「健康」。
写路径：`app/services/job_health_service.py` 失败分支
`consecutive < N → HEALTH_OK`。

## 2. 根因

「持续异常」阈值（≥N）与「可否称健康」共用 `ok/failing`。
未满 N 的失败被故意写入 `ok`，模板把 `ok` 一律显示为「健康」。
行为层：产品把「尚未进入持续异常」误表达成「健康」。

## 3. 测试漏洞

`test_three_fails_marks_failing_when_n_is_3` 曾断言
「第 1 次失败 → `HEALTH_OK`」，把错误语义锁进回归门禁；
无「单次失败不得标健康」否定用例；无模板层断言「有失败」文案。

## 4. 修复

- 写路径：失败且 <N → `unknown`（非 ok）
- 列表 / 详情：`consecutive_failures > 0` → badge「有失败」（含历史 ok 兜底）
- `ensure_business_tables._correct_subthreshold_health_ok` 校正存量

## 5. 防护测试

```
.venv-py311/bin/python -m unittest \
  tests.test_job_health.TestUpdateJobHealth.test_single_fail_is_not_healthy \
  tests.test_job_health.TestUpdateJobHealth.test_three_fails_marks_failing_when_n_is_3 \
  tests.test_ensure_business_tables.TestCorrectSubthresholdHealthOk -v
```

期望：1 次失败 → unknown；3 次 → failing；历史 ok+failures>0 → unknown。

## 6. 同类排查

| 位置 | 结论 |
| --- | --- |
| Dashboard 健康列 | 已改「有失败」分支 |
| 任务详情健康卡 | 原 failing/else→健康，已对齐三态 |
| 持续异常统计 | 仍仅 failing / ≥3，未改口径 |
| OPT-P1-18 待验证 | 未实施；文案勿与「有失败」混淆 |

## 7. 预防方案

在 `job_health_service` 模块文档与设计中固定：
**ok ≡ 连续失败为 0**；未满阈值失败必须 unknown。
单测 `test_single_fail_is_not_healthy` 永久锁定。
启动校正落在 `scripts/ensure_business_tables.py`。

```
grep -n 'HEALTH_UNKNOWN if row.consecutive_failures' app/services/job_health_service.py
grep -n '有失败' app/templates/redesign/_dashboard_rows.html
```
