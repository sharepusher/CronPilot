复盘：迁移脚本清零有效时间戳（2026-08）

影响：P0 — 数据破坏。Dashboard "今日失败"等时间相关统计全部归零，用户无法查看任何时间维度的执行记录统计。

1. Bug 定位

文件：scripts/ensure_business_tables.py，函数 _convert_column_data()，第 706-713 行（修复前）。

清理 SQL：

UPDATE job_log SET create_time = 0
WHERE create_time = ''
   OR (create_time IS NOT NULL AND typeof(create_time) = 'text')

该语句在每次服务重启时执行（ensure_business_tables.sh → _ensure_bigint_timestamps()），将所有 typeof() = 'text' 的 create_time 值清零——包括有效的纯数字文本（如 '17877473677'）。

2. 根因

层问题
SQLite 物理模式job_log.create_time 列类型仍为 VARCHAR(25)（SQLite 不做 ALTER COLUMN TYPE），SQLAlchemy Mapped[int] + BigInteger 写入的整数在存储层是 text affinity
typeof() 判断SQLite 的 typeof() 返回的是值的存储类型而非列声明类型。VARCHAR 列中写入的整数 17877473677 的 typeof 为 'text'
清理条件过宽原条件 typeof(col) = 'text' 覆盖了所有文本值，未区分「合法数字文本」和「需要清零的非法文本」
_column_needs_migration 误触发采样条件只看 typeof = text，不检查值是否为日期格式，导致纯数字文本也触发迁移流程
每次重启执行迁移脚本在 cronpilot.sh start 中无条件调用，每次重启均执行上述清零

行为层根因：时间戳迁移设计时未考虑"列已切换到 BigInteger 写入但物理类型仍为 VARCHAR"的过渡态。开发者假设 typeof='text' 等价于"未迁移的旧日期字符串"，但在 SQLite 的 VARCHAR 列中，即使写入整数也会被存为 text。

3. 测试漏洞

  • 现有 tests/test_timestamp_utils.py 仅测试 times.py 的工具函数，不测试迁移脚本逻辑
  • 无集成测试模拟"写入 BIGINT 时间戳 → 重启 → 检查值是否保留"的全流程
  • 迁移脚本开发时仅在"全部是旧日期字符串"的库上测试，从未在"已有 BIGINT 值"的库上回归

4. 修复

修改 1：_column_needs_migration() — 仅当列中存在日期格式文本时才触发迁移（LIKE '____-__-__%'）：

row = db.session.execute(text(
    "SELECT %s FROM %s WHERE %s IS NOT NULL "
    "AND %s != '' AND %s != '0' AND typeof(%s) = 'text' "
    "AND %s LIKE '____-__-__%%' LIMIT 1"
    % (col, table, col, col, col, col, col)
)).fetchone()
return row is not None

修改 2：_convert_column_data() 清理条件 — 仅清零空字符串和无法解析为数字的文本：

cleanup_sql = (
    "UPDATE %s SET %s = 0 WHERE %s = '' "
    "OR (%s IS NOT NULL AND typeof(%s) = 'text' "
    "AND CAST(%s AS INTEGER) = 0 AND %s != '0')"
    % (table, col, col, col, col, col, col)
)

逻辑：CAST('17877473677' AS INTEGER) = 17877473677（非零，保留）；CAST('abc' AS INTEGER) = 0（清零）；空字符串直接清零。

5. 防护测试

文件：tests/test_timestamp_utils.py，类 TestMigrationCleanupPreservesNumericText（3 条用例）：

  • test_numeric_text_not_zeroed_by_cleanup_condition：模拟 SQLite VARCHAR 列中存有效数字和无效文本，验证清理后数字保留、无效文本归零
  • test_needs_migration_ignores_numeric_text：验证纯数字文本不触发迁移检测
  • test_needs_migration_detects_date_text：验证日期格式文本正确触发迁移检测

运行命令：python3 -m unittest tests.test_timestamp_utils.TestMigrationCleanupPreservesNumericText -v

7. 预防方案

#措施落地位置验证命令
1 防护测试：3 条用例覆盖清理逻辑和迁移检测逻辑 tests/test_timestamp_utils.py::TestMigrationCleanupPreservesNumericText python3 -m unittest tests.test_timestamp_utils.TestMigrationCleanupPreservesNumericText -v
2 迁移脚本自身判断改为仅日期格式触发，纯数字不触发 scripts/ensure_business_tables.py::_column_needs_migration() 重启后日志输出 "OK: 时间戳列已是 BIGINT，无需迁移"
3 清理条件收窄：仅 CAST 为 0 的非空文本才清零 scripts/ensure_business_tables.py::_convert_column_data() 连续两次 restart 后 sqlite3 datas/job_log.sqlite "SELECT count(*) FROM job_log WHERE create_time != 0" 值不减
