# 认证页品牌标识与产品描述设计

**状态**：待确认  |  **日期**：2026-08-28  |  **关联**：OPT-P1-16 Redesign

## 1. 问题

**P1. 认证页 Logo 与管理端不一致** — 4 个认证页面使用 9px 蓝色方点（`.auth-logo-dot`）作为品牌标识，而管理端侧边栏使用自定义 SVG 括号+时钟图标。品牌识别断裂：用户从登录页进入主界面后看到完全不同的 Logo。

**P2. 缺少产品定位描述** — 认证页只显示 "CronPilot" 品牌名，首次访问的用户无法快速了解产品定位。行业最佳实践（Supabase、Railway、PlanetScale）均在认证页展示产品定位 tagline。

## 2. 根因

**直接原因**：认证页面独立于 `_base.html`（自带 `<!DOCTYPE>`，不继承管理端 Shell），Logo 区域在初始设计时使用了简化的方点占位符（`.auth-logo-dot`：9px 蓝色圆角方块）。产品描述在 Redesign 中未纳入认证页设计范围。

**系统性根因**：

- **设计资产碎片化** — 认证页与管理端的品牌标识（Logo SVG、tagline）缺乏统一的 Design Token 管理。管理端侧边栏在 Redesign 中更新了 SVG 图标，但认证页未被纳入同一设计变更的范围，导致两个入口的品牌表达产生分叉。
- **独立模板的 Review 盲区** — 不继承 `_base.html` 的独立页面（login/register/forgot\_password/complete\_profile）不在管理端 UI Review 的常规视野内，容易在全局视觉迭代中被遗漏。
- **Redesign 范围定义粒度** — Redesign 阶段按"功能模块"（Shell、Dashboard、RBAC 等）划分范围，而非按"用户旅程"（认证→首页→功能页）划分。认证页作为用户旅程的第一触点，反而被归为"边缘页面"而延后处理。

### 3b. 同领域调度类产品对标

| 产品 | Logo 形式 | 品牌布局 | Tagline |
| --- | --- | --- | --- |
| **Apache Airflow** | 风车图标 | 居中堆叠（图标 → 名称） | "Airflow™"（无功能描述，依赖品牌知名度） |
| **Dagster** | 几何 Logo | 居中堆叠 | "The data orchestration platform" |

**领域补充洞察**：调度/编排类工具中，Dagster 和 Rundeck 均在认证页附带 tagline 辅助产品认知。Apache Airflow 虽未加 tagline，但依赖其在数据工程领域的高知名度——*这恰好佐证了前述规律：知名度不足时 tagline 不可省略*。

### 3c. 反面案例：缺少 tagline 的负面效果

**Jenkins** 登录页仅展示 Logo + "Jenkins" 文字，无任何产品定位描述。新用户（尤其非 DevOps 背景的项目经理）首次访问时常反馈"不确定这个系统是做什么的"。相比之下，同期的 GitLab（"The DevSecOps Platform"）和 CircleCI（"Continuous Integration and Delivery"）通过 tagline 在认证页建立了即时认知。

**洞察**：品牌知名度较高的产品（Linear、Vercel、Airflow）倾向居中堆叠布局且可省略 tagline；B2B/基础设施产品（Supabase、Railway、PlanetScale、Dagster）普遍附带产品定位 tagline。CronPilot 作为内部工具类产品，品牌认知度有限，应采用 tagline 帮助首次用户建立认知。

## 4. 三种布局方案对比

### 方案 A：居中堆叠品牌（Linear/Vercel 风格）

品牌图标以 48px 圆角方块承载，居中显示。品牌名和 tagline 居中排列。整体庄重、对称、有仪式感。

### 方案 B：左对齐品牌 + 独立 tagline（Railway/PlanetScale 风格）

品牌图标与名称内联左对齐，tagline 作为独立行。保持信息层次的同时更紧凑。

### 方案 C：品牌色带 + 表单分区（企业级风格）

卡片顶部为品牌主色渐变条，白色字体展示品牌信息。表单在下方白色区域。视觉层次最强，企业感最重。

| 评分维度 | 权重 | A. 居中堆叠 | B. 左对齐 | C. 品牌色带 |
| --- | --- | --- | --- | --- |
| **品牌冲击力** | 25% | 5 居中 + 大图标 | 4 紧凑但专业 | 5 色带醒目 |
| **信息层次** | 20% | 5 品牌→tagline→操作 | 4 品牌+tagline→操作 | 5 分区最清晰 |
| **空间利用** | 20% | 3 品牌区占 ~90px | 5 最紧凑 ~50px | 4 色带占 ~60px |
| **移动端适配** | 15% | 5 居中天然响应式 | 5 左对齐天然响应 | 4 色带渐变需适配 |
| **暗色主题兼容** | 10% | 5 currentColor + CSS 变量，零额外代码 | 5 currentColor + CSS 变量，零额外代码 | 3 渐变色硬编码，暗色需额外维护一组值（见 Demo E） |
| **迁移成本** | 10% | 4 重构 Logo 区 | 5 最小改动 | 3 新增色带结构 |
| **加权总分** | | **4.55 ★** | **4.60 ★** | **4.10** |

**评分说明**：A（4.55）与 B（4.60）仅差 0.05，处于统计噪声范围。当定量评分接近时，决策权转向定性判断：A 的居中堆叠在视觉焦点引导和品牌仪式感上优于 B 的紧凑布局——对于管理平台的"第一印象页面"（认证页），仪式感权重应高于空间效率。最终推荐 A。

## 7. 推荐方案

### 推荐：方案 A（居中堆叠）+ T5 tagline

**核心理由**：

1. **仪式感与庄重** — 居中布局是 Linear、Vercel、Supabase 等一线 SaaS 的标准，传达"专业管理平台"定位
2. **品牌识别强** — 48px 图标容器（淡蓝渐变背景 + 品牌 SVG）在页面中占据视觉焦点，比 9px 方点提升数倍辨识度
3. **层次分明** — 品牌区（图标+名称+tagline） → 操作区（标题+副标题+表单）天然分层，无信息混杂
4. **暗色主题兼容好** — 图标容器背景色可用 CSS 变量适配

**与方案 B 差异**：B 更紧凑（适合长表单如注册页），但品牌冲击力弱于 A。建议登录/忘记密码用 A，注册/补全资料如空间紧张也可用 A（卡片宽度足够）。

**与方案 C 差异**：C 企业感最强但暗色主题需维护渐变色双套，且色带在移动端小屏幕上压缩表单空间。

## 8. 范围

**改动范围**：

- `login.html` — 替换 Logo 为居中堆叠品牌区 + tagline
- `register.html` — 同上
- `forgot_password.html` — 同上
- `complete_profile.html` — 同上
- `redesign-auth.css` — 新增 `.auth-brand`（容器）、`.auth-brand-icon`（图标方块）、`.auth-brand-name`（名称）、`.auth-tagline`（tagline）样式；调整 `.auth-logo` 的 margin

**CSS class 变更明细**：

| 操作 | 选择器 | 属性 |
| --- | --- | --- |
| 新增 | `.auth-brand` | `text-align: center; margin-bottom: 28px;` |
| 新增 | `.auth-brand-icon` | `display: flex; align-items: center; justify-content: center; width: 48px; height: 48px; border-radius: 12px; background: var(--cp-signal-bg); border: 1px solid var(--cp-signal-border, var(--cp-border)); margin: 0 auto 10px;` |
| 新增 | `.auth-brand-icon svg` | `width: 28px; height: 28px;` |
| 新增 | `.auth-brand-name` | `font-size: 18px; font-weight: 700; color: var(--cp-text); letter-spacing: -0.01em;` |
| 新增 | `.auth-tagline` | `font-size: 12px; color: var(--cp-text-faint); margin-top: 4px; letter-spacing: 0.03em;` |
| 删除 | `.auth-logo`（整个块） | 替换为 `.auth-brand` |
| 删除 | `.auth-logo-dot` | 不再使用 |

**SVG Accessibility 规格**（WCAG 2.1 合规）：

| 属性 | 值 | 说明 |
| --- | --- | --- |
| `role="img"` | 加在 `<svg>` 元素上 | 向辅助技术声明这是图片而非可交互元素 |
| `aria-label="CronPilot"` | 加在 `<svg>` 元素上 | 屏幕阅读器读出品牌名（与旁边 `.auth-brand-name` 文本重复时，也可改为 `aria-hidden="true"` 避免双重朗读） |

**设计决策**：由于 `.auth-brand-name` 已以文本展示 "CronPilot"，SVG 采用 `aria-hidden="true"` 方案更佳，避免屏幕阅读器重复朗读。若未来 Logo 独立展示（无文字名称伴随），则需切换为 `role="img" aria-label="CronPilot Logo"`。

**HTML 变更**：

| 变更类型 | 旧值 | 新值 |
| --- | --- | --- |
| 替换 Logo 区域 | `<div class="auth-logo"><span class="auth-logo-dot">...CronPilot</div>` | `<div class="auth-brand">...SVG + CronPilot + tagline</div>` |

**模板 Include 架构（已实施）**：

品牌标识 SVG 路径是品牌的原子知识（不可分割），须保持全局唯一来源。通过 Jinja2 `{% include %}` 实现三层去重架构：

```
_brand_paths.html        ← 唯一来源：3 个 SVG 路径（品牌标识原子知识）
    ↑ include                     ↑ include
_brand_block.html        _sidebar.html
(auth 品牌区：             (管理端侧边栏：
 48px icon + name +        20px icon + name
 tagline)                  无 tagline)
    ↑ include
login / register / forgot_password / complete_profile
```

| 文件 | 职责 | 说明 |
| --- | --- | --- |
| `_brand_paths.html` | SVG 路径数据 | 3 个 `<path>`/`<polyline>` 元素，被所有品牌 SVG 消费者引用 |
| `_brand_block.html` | 认证页品牌区 | 48px 图标容器 + 品牌名 + tagline + `aria-hidden` |
| `_sidebar.html` | 管理端侧边栏 | 20px 图标 + 品牌名（无 tagline）+ `aria-hidden` |

**设计决策**：不在 auth 和 sidebar 之间共享整个品牌块（`_brand_block.html`），因为两者外层语义不同（`<div>` 纯展示 vs `<a>` 可点击导航）、尺寸不同（48px vs 20px）、伴随内容不同（有/无 tagline）。仅共享 SVG 路径数据——这是真正的品牌原子知识，改变路径 = 改变 Logo = 必须全局同步。

**明确不做**：

- 不改变 `auth-title` / `auth-subtitle` 内容
- 不改变表单结构、JS、交互逻辑
- 不涉及 v1 模板、`_base.html`
- 不改变卡片宽度或整体布局

## 9. 分批

改动量小（共 5 个文件、约 30 行），采用**渐进式单批**策略：

1. **CSS 基础**：在 `redesign-auth.css` 中新增 `.auth-brand*` 和 `.auth-tagline` 样式，删除旧 `.auth-logo` / `.auth-logo-dot`
2. **先验证 login.html**：替换 `login.html` 的 Logo 区域 → `restart` → `curl` 验证品牌区渲染正确（`auth-brand-icon` 存在、`auth-logo-dot` 不存在、tagline 文案正确）
3. **批量替换**：确认 login 正常后，依次替换 `register.html`、`forgot_password.html`、`complete_profile.html`
4. **全量验收**：`restart` → 浏览器访问 4 个页面，运行 CI 门禁

**渐进理由**：先在最常用的 login 页面验证 CSS + HTML 结构正确性，避免 4 个模板同时修改后出现问题时定位困难。由于 4 个模板的 Logo 替换内容完全相同，login 验证通过后批量替换风险极低。

## 11. 风险

- **低风险**：仅替换 Logo HTML + 新增 CSS class，不改表单逻辑或 JS
- **视觉**：居中品牌区增加约 90px 高度，380px 宽度的卡片仍远低于视口高度
- **回退**：Git revert 单 commit

### CSS 变量降级策略

品牌区样式依赖以下 CSS 变量，任一缺失时的降级行为：

| 变量 | 用途 | 降级行为 |
| --- | --- | --- |
| `--cp-signal-bg` | 图标容器背景 | 若缺失则渲染为透明背景，品牌图标仍可见 |
| `--cp-signal-border` | 图标容器边框 | CSS 中已写 `var(--cp-signal-border, var(--cp-border))`，自动回退到通用边框色 |
| `--cp-text` | 品牌名颜色 | 若缺失则继承 `body { color }` |
| `--cp-text-faint` | tagline 颜色 | 若缺失则继承 `body { color }`（视觉层次损失但内容可读） |
| `--cp-signal` | SVG 时钟指针色 | 若缺失则 stroke 不渲染（指针不可见但括号图标仍完整） |

**设计意图**：`.auth-brand-icon` 的 `border` 属性使用双层 fallback（`var(--cp-signal-border, var(--cp-border))`）是有意为之——`--cp-signal-border` 是语义化的品牌边框色，`--cp-border` 是通用边框色。当主题文件只定义通用变量而未定义品牌变量时，仍能保持视觉一致性。
