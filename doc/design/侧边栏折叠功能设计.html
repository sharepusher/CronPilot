设计文档：侧边栏折叠功能

分类：功能增强
日期：2026-08-24
关联：OPT-P1-16（Redesign Phase 1）
状态：待确认

1. 问题

当前 Redesign 侧边栏固定占据 192px 宽度，无法折叠或隐藏。在小屏幕（1280px 以下）或需要更大内容区域的场景下，侧边栏占比过高。

代码层面已有折叠基础设施：

  • CSS：.cp-shell.collapsed 将侧边栏从 192px 缩为 56px，隐藏文字标签和分组标题（redesign-layout.css L425-447）
  • JS：window.CpShell.toggleSidebar() 函数可切换折叠状态，通过 cp_sidebar_collapsed cookie 持久化（redesign-shell.js L16-21）
  • 缺失：没有任何可见的 UI 控件来触发折叠。JS 注释写着"Mobile hamburger button will be added in later phases"。

2. 根因

Redesign Phase 1 实现时，侧边栏折叠的 CSS/JS 基础设施已就绪，但触发 UI 被推迟到后续阶段。Mockup 中也未包含折叠按钮设计。

3. 方案

3.1 折叠按钮位置 — "分界线按钮"方案

按钮放置在侧边栏与内容区的分界线上（半嵌入侧边栏右边缘），垂直方向固定在页面高度的 1/5 处（即 top: 20%）。此方案是 VS Code、Linear、Figma、Notion 等主流产品的标准做法，具有以下优势：

  • 高可发现性：用户自然会沿分界线探索交互
  • 零侵入：不占用侧边栏内部空间，也不影响内容区域
  • 位置可预测：无论滚动状态如何，按钮始终在同一位置
设计决策：选择 20%（1/5 处）而非顶部或底部的原因 — ① 避开顶部 Brand 区域（约 60px），防止视觉拥挤；② 视觉重心在阅读区上部三分之一，与用户视线自然交汇；③ 参考 VS Code 的折叠按钮位于侧边栏中上部。

3.2 按钮规格

属性值说明
位置侧边栏右边缘，top: 20%（1/5 处），半圆外露按钮中心点在分界线上，右半部分伸入内容区域
定位方式position: absolute，相对于 .cp-sidebarright: -12px（按钮直径的一半外露）

3.3 可见性策略

折叠按钮始终可见（opacity: 1），确保首次访问的用户也能发现折叠功能。按钮尺寸小（24px 圆形），视觉上不会造成干扰。

设计决策变更：初始方案为"默认隐藏、hover 渐显"，但用户反馈指出——如果按钮不展示，首次访问的用户无法发现折叠功能。因此改为始终可见。

3.4 交互行为

交互行为
点击折叠按钮调用已有 CpShell.toggleSidebar()，侧边栏 192px ↔ 56px 切换
状态持久化通过 cp_sidebar_collapsed cookie 记忆（已有实现）
过渡动画.cp-shell { transition: grid-template-columns 0.2s ease }
折叠后图标 tooltip鼠标悬停在折叠的导航图标上时，显示原始文字标签（如"任务中心"）；使用 title 属性原生 tooltip
页面加载服务端根据 cookie 渲染 collapsed class，避免闪烁（见 3.5）

3.5 初始化（服务端渲染 · 防闪烁）

在 _base.html 中根据 cookie 在服务端渲染时即决定初始 class，避免"先展开再折叠"的视觉闪动：

<div class="cp-shell{% if request.cookies.get('cp_sidebar_collapsed') == '1' %} collapsed{% endif %}">

4. 范围

涉及文件（3 个）

  • app/templates/redesign/_sidebar.html — 在侧边栏末尾添加折叠按钮 HTML（含 SVG 图标 + title 属性）
  • app/static/css/redesign-layout.css — 添加折叠按钮定位样式（.cp-collapse-btn）+ .cp-shell transition 动画 + hover 显隐 + 折叠后导航 title tooltip 样式
  • app/templates/redesign/_base.html — .cp-shell 行添加 Jinja2 条件判断 cookie，服务端渲染折叠初始状态

不涉及（无需修改）

  • redesign-shell.js — toggleSidebar() 和 cookie 逻辑已就绪，无需改动
  • console-theme.css — 现有令牌足够，无需新增变量

明确不做

  • 移动端 hamburger 菜单（已有独立的 @media (max-width: 768px) 响应式设计，作用域不同）
  • 键盘快捷键折叠（可在后续阶段添加，如 Cmd+[）
  • 拖拽调整侧边栏宽度
  • 折叠后导航 flyout 子菜单（当前使用原生 title tooltip，后续可升级为自定义 flyout）

5. 分批

单批次实施，涉及 3 个文件，总变更量约 30-40 行，均为新增。

7. 风险

风险影响缓解
折叠状态下导航仅图标，用户需要学习低原生 title tooltip 提供文字提示；折叠是主动操作，用户有预期
按钮圆形外露 12px 进入内容区无内容区域有 padding，12px 不会遮挡内容；hover 才显示进一步降低干扰
CSS position: absolute 的 z-index 冲突低按钮 z-index: 10 低于模态框（100+），不影响弹窗
折叠后表格宽度变化低内容区使用 1fr 自适应，表格已有 overflow-x，无需额外处理
