**不要**把筛选 chip「全部」改为「在营」；
**不要**改默认列表过滤。

**相对 rev.2–4（方案 D）的变更：**
取消「活跃/暂停」替代总数、取消 chip「在营」、取消默认列表排除下线。
文案对齐现有 chip：用「运行中 / 已暂停」，不用「活跃 / 暂停」。

## 1. 问题

- 顶栏 `stat-line` 仅显示 `metrics.total`（「N 个任务」），看不到运行中与已暂停各多少。
- 数据层已有 `metrics.running` 与 `status_counts.paused`，模板未展示。

## 2. 根因

```
# dashboard.html stat-line 只拼 total + 异常/逾期/今日失败
# metrics.running / status_counts.paused 已算好，未进入 stat-line
# AJAX 刷新 statLine.innerHTML 同样只写 total
```

## 3. 方案

### 3.1 推荐方案 E（仅顶栏追加）

> 目标形态：  
> `16 个任务 · 运行中 3 · 已暂停 1 · 2 持续异常 · 0 逾期 · …`

- **全部任务数**：仍用 `metrics.total`（Scope 内含已下线，语义不变）。
- **运行中**：`status = 1` ⇔ `metrics.running` / chip「运行中」。
- **已暂停**：`status = 0` ⇔ `status_counts.paused` / chip「已暂停」。
- **不做**：不改 chip 文案；不改默认列表 where；顶栏不展示「已下线」计数；不加 Stats 卡片；分列默认纯展示（不加点击跳转，若加链接须另批确认）。

2. **AJAX**：`statLine.innerHTML` 与 stats payload 同步带上 running / paused。
3. **数值口径**：与现网 stats 一致，按 Scope 统计，不随列表 status 筛选收缩。

| 批次 | 内容 | 验收 |
| --- | --- | --- |

## 6. 验收

1. 构造运行 2 / 暂停 1 / 下线 5：顶栏为「**8** 个任务 · 运行中 **2** · 已暂停 **1** · …」
2. chip 仍为「全部」，默认列表仍含下线（若库中有）
3. AJAX 刷新后 stat-line 仍为「总数 + 运行中 + 已暂停」结构

## 7. 风险

- 总数仍含下线，可能继续「虚高」——本轮接受；若以后要排除下线须另开设计。
- stat-line 变长：窄屏换行，沿用现有 `stat-line` 样式即可。
- 回滚：恢复原 innerHTML / 模板一行即可。
