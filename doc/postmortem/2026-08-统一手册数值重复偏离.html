复盘：统一执行手册 v1 数值重复导致 15 处不一致

日期：2026-08-11
关联：OPT-P1-16-MANUAL
严重级别：中（文档不可信，未影响运行代码）
发现方式：用户要求全面审计手册与 Mockup 一致性时发现

1. Bug 定位

doc/design/UI重设计-统一执行手册.html v1 的 Part 2（全局设计规格）和 Part 3（逐批次执行计划 + 逐页规格）中包含了从 Mockup CSS 和视觉规格书抄写的精确数值（色值、字号、间距、圆角等），其中 15 处与源文档不一致。

典型偏差示例：

位置手册 v1 写的值Mockup/源文档实际值
字体族凭记忆添加了不存在的 fallback-apple-system, BlinkMacSystemFont, sans-serif
Sidebar 宽度混淆不同文档来源的值Mockup CSS 第 156 行
个别色值写为近似值精确值来自 Mockup :root 块

2. 根因

Agent 在创建统一手册时采用了「读取源文档 → 用自然语言总结 → 综合写入新文档」的工作流。在「综合写入」步骤中，Agent 依赖的是对源文档的记忆/印象而非机械逐行复制。具体行为层原因：

  • 任务理解偏差：将"整合文档"理解为"总结重述"而非"精确引用"
  • 上下文切换 hallucination：token context 中同时存在多个源文档，在切换间产生了值的混淆
  • 缺少回验步骤：写入后没有立即 Read 新文档并逐行对比源文档的数值差异
  • 已有 Design QA 门禁未覆盖此场景：门禁 #8 是面向"代码实现 vs Mockup"的，不覆盖"文档 vs 文档"的一致性

3. 测试漏洞

本应拦截此问题的测试：不存在。

  • html_docs_to_markdown.py --check 只检查格式转换一致性，不检查内容准确性
  • Design QA 门禁 (#8) 面向代码实现，不覆盖文档间一致性
  • 没有任何自动化工具验证"文档 A 中引用文档 B 的数值是否与 B 一致"

4. 修复

将统一手册从 v1（含冗余数值）重构为 v2（纯索引+架构模式）：

  • Part 2：移除全部色彩/字体/间距/圆角/阴影/布局的精确数值表 → 替换为指向源文档行号的索引表
  • Part 3：移除全部逐页详情 → 替换为批次总览表 + 统一执行规程 + 架构决策备忘
  • Part 5/6：移除重复的动画参数和 ARIA 对比度数值 → 改为指向逐页规格书附录的索引
  • 结果：~900 行 → 470 行；手册中不存在任何可从源文档查到的精确值

5. 防护测试

结构性防护：本次采用「消除重复」策略而非「修正重复中的错误值」。统一手册 v2 中不存在任何可从源文档查到的精确数值，因此不可能再出现「手册值 ≠ 源值」的问题。这是架构层面的防护。
