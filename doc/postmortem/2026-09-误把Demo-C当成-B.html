误把 Demo §C（Run Inspector）当成 §B 复盘

日期：2026-09-17 · 类型：沟通 / 设计交付

1. Bug 定位

用户指出「和原方案 UI 不一致」，并给出 任务执行链路可观测性-页面对比Demo.html。 Agent 连续多轮按 §B 任务详情最近执行（状态机语义）改 R3-C； 用户纠正：要对齐的是 §C Run Inspector 执行详情。

2. 根因

行为层：当时在推进 R3-C（任务详情），默认把「页面对比 Demo」映射到同批次的 §B， 未先问清「不一致」指向 Demo 的哪一节，也未对照用户打开的是详情页还是任务详情卡片。 父 Demo 含 A/B/C 三节，缺「用户反馈 → Demo 节号」确认步骤。

3. 测试漏洞

设计确认流程无「用户指出的 Demo 锚点 / 节号」必填项； 自检只验子设计是否含 page-compare，不验是否对准用户所说的那一节。

4. 修复

  • 新建 doc/design/R2-D-RunInspector对齐页面对比Demo-C设计-2026-09.html：页面对比原文照录 Demo §C。
  • R3-C 标为暂停（非本轮用户所指）。
  • 确认前不改 app/。

6. 同类排查

项结论
R3-C / Demo §B另题；本轮暂停，不与 §C 混改
R2 已实施稿曾写明偏离 §C；正是本轮要对齐的对象

7. 预防方案

在 cronpilot-project.mdc / AGENTS.md「子设计锚定父 Demo」补强： 用户给出含多节的页面对比 Demo 时，确认开干前必须写明节号（如 §C）， 子设计文首与 #page-compare 标题须含该节号；禁止默认取「与本批 OPT 同名」的节。 

# 用户点名 Demo 文件后，设计稿必须出现节号
grep -nE 'Demo §[ABC]|§C|§B' doc/design/本设计.html
