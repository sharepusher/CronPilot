图标规范化与替换设计

状态：已完成  |  日期：2026-08-27  |  关联：OPT-P1-16 Redesign

1. 问题

P1. 密码可见性切换图标不够精致 — 登录、注册、修改密码页共 7 处 Eye/Eye-Off 图标在 14px 下线条偏粗、斜线贴边杂乱。
P2. 「查看详情」与密码切换共用 Eye 图标 — 语义冲突，违反 WCAG 3.2.4 一致性标识。
P3. 密码重置 (Key) 与 API Token 入口 (Key) 语义混淆 — 同一 Key 图标代表两种不同操作。
P4. 停用/启用用户「查看」图标不一致 — 同一操作使用不同图标（Eye vs User）。

2. 必要性分析

P1 · 密码 Eye 精细化：必要性 中 — 视觉渲染问题，非语义问题。原因是当前 Feather Icons stroke-width=2 在 14px 下偏粗。
P2 · 查看详情 Eye → 别的图标：必要性 高 — Eye 在行业中强绑定「密码可见性切换」（GitHub/GitLab/AWS/Vercel 均不用 Eye 表示"查看详情"），违反 WCAG 3.2.4。
P3 · API Token Key → 别的图标：必要性 高 — Key 已被「重置密码」占用，侧边栏相邻两项（Lock/Key）14px 下难区分。
P4 · 停用状态查看图标统一：必要性 中 — 一致性问题，随 P2 一并修复。

3. 图标库方案对比

CronPilot 技术约束：Flask + Jinja2 模板、无 JS 构建步骤、inline SVG 方式（复制 path）、深色/浅色主题 currentColor。

3.3 各方案详细分析

A. Lucide（Feather 社区版）

优势：与当前 Feather 图标最接近，迁移成本最低（仅替换 path data）。1,500+ 图标，活跃维护，shadcn/ui 默认。

劣势：stroke-width: 2 在 14px 下与当前 Feather 问题相同——线条偏粗，这正是用户反馈的核心痛点。换 Lucide 不解决"不够专业"的根本问题。

结论：迁移轻松但视觉改善有限。仅做语义修正（P2/P3）时可选。

B. Heroicons（Tailwind 官方）

优势：stroke-width: 1.5 是关键差异化——比 Feather/Lucide/Tabler 的 2px 细 25%，14px 渲染下线条更精致、留白更充分。由 Tailwind Labs 设计团队维护，每个图标经过严格像素对齐。同 viewBox (24×24)、同渲染方式 (stroke + currentColor)，迁移仅需替换 path data。

劣势：仅 292 个图标，是最小的集合。但 CronPilot 当前只使用约 20 个不同图标，292 完全覆盖（含 eye, eye-slash, lock-closed, key, document-text, command-line, arrow-path, no-symbol, users, shield-check 等）。

结论：直接解决"14px 下不够专业"的核心问题。292 图标对管理面板充足。

C. Phosphor（多权重设计系统）

优势：6 种权重（thin/light/regular/bold/fill/duotone），视觉层次最丰富。5,400+ 图标数量最多。设计系统级品质。

劣势：viewBox 为 256×256、使用 fill path 而非 stroke——与 CronPilot 现有 viewBox="0 0 24 24" stroke="currentColor" 体系完全不同。迁移需重写所有 SVG 容器属性。fill path 在 14px 下与 stroke 的视觉风格差异大，可能与现有页面元素不协调。

结论：品质最高但迁移成本最大，且 fill 风格与现有 stroke 体系冲突。适合全新项目，不适合渐进替换。

D. Tabler（管理面板专用）

优势：5,000+ 图标专为管理面板设计，覆盖度最高。与 Lucide 同源 (24×24 viewBox, stroke-width:2)，迁移简单。

劣势：与 Lucide 同样的 stroke-width: 2 问题。Tabler 的 Eye 图标使用 r="2"（比 Lucide r=3 更小），但整体线条粗细一致。不解决核心视觉问题。

结论：图标最多但视觉改善与 Lucide 相当。

5. 推荐方案

推荐：B. Heroicons Outline

核心理由：

  1. stroke-width: 1.5 是关键差异 — 比 Feather/Lucide/Tabler 的 2px 细 25%，这直接解决了用户反馈"图标不够专业"的核心问题。在 14px 渲染尺寸下，1.5px 的线条更精致、留白更充分、整体更现代
  2. 迁移成本低 — 同样是 24×24 viewBox + stroke + currentColor 体系，只需替换 SVG path data，不改 CSS 或 JS
  3. 292 图标完全够用 — CronPilot 管理面板当前使用约 20 个不同图标，Heroicons 292 个图标全覆盖（eye, eye-slash, lock-closed, key, document-text, command-line, arrow-path, no-symbol, users, shield-check, pencil-square, clipboard, tag, cog 等）
  4. 专业团队维护 — Tailwind Labs 设计团队维护，每个图标经过严格的像素对齐和视觉测试
  5. 行业标杆 — GitHub, Vercel, Linear 等产品的图标精致度与 Heroicons 同级

与 Lucide 对比的关键决策点：

如果核心诉求是"不够专业/精致"→ Heroicons（stroke 更细）
如果核心诉求是"语义混乱"→ Lucide 也能解决（仅换图标类型）
如果核心诉求是"最小改动"→ Lucide（path 最接近现有）

6. 范围（按推荐方案 Heroicons）

改动范围：替换 6 个模板文件中的 SVG path data
  • login.html — Eye/Eye-Slash 替换（2 组）
  • register.html — Eye/Eye-Slash 替换（2 组）
  • change_password.html — Eye/Eye-Slash 替换（3 组）
  • _users_rows.html — 查看 Eye→DocumentText（2处）、Token 重置→ArrowPath（1处）
  • _sidebar.html — API Token Key→CommandLine（1处）
  • _topbar.html — API Token Key→CommandLine（1处）
同步变更：所有已替换的图标统一调整 stroke-width 为 1.5 明确不做：
  • 不全量替换全站图标（侧边栏导航、Dashboard 等暂保留现有 Feather，后续统一迁移）
  • 不变更 CSS 类名、布局结构、交互行为
  • 不涉及 v1 模板

B2① 用户管理操作列「查看」为文件图标 ② 「Token 重置」为双向旋转箭头 ③ tooltip 正确
B3① 侧边栏 API Token 为终端窗口图标 ② 与相邻的 Lock（修改密码）视觉明确区分

9. 风险

  • 低风险：仅替换 SVG path 和 stroke-width，不改 class/事件/布局
  • 视觉一致性：本轮仅替换 6 个文件中的问题图标，侧边栏导航等其他图标暂保留 Feather (stroke:2)。两种粗细在同一页面中需要在验收时评估是否突兀，如有需要可在后续统一迁移全站图标
  • 回退：Git revert 单 commit 即可还原
