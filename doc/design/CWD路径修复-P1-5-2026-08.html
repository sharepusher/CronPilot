1. 问题

configs.py 第 22 行 cp.read('conf.ini', encoding='utf-8') 使用 CWD 相对路径读取配置文件。ConfigParser.read() 在文件不存在时静默返回空列表（不报错），导致所有配置项变为空字符串或默认值。如果进程的工作目录不是项目根目录，配置将完全失效。

2. 根因

上游 xiaoniu_cron 原始代码使用相对路径。启动脚本（start_local_full.sh、run_production.sh）都会 cd 到项目根目录后再启动 Python，因此问题从未在正常部署中暴露。

同文件第 7 行已定义 _proj_root = os.path.dirname(os.path.abspath(__file__)) 并用于 SQLite URL 解析，但 conf.ini 读取未使用此变量——属于"修了一半"的历史遗留。

3. 方案

# configs.py 第 22 行
# 修复前
cp.read('conf.ini', encoding='utf-8')

# 修复后
cp.read(os.path.join(_proj_root, 'conf.ini'), encoding='utf-8')

4. 范围

文件改动
configs.py第 22 行，'conf.ini' → os.path.join(_proj_root, 'conf.ini')

不做的事：不改变 configs() 的接口或返回结构；不修改其他文件中对 configs() 的调用方式。

5. 分批

单行修改，单步交付。

7. 风险

风险等级说明
回归风险极低_proj_root 就是 configs.py 所在目录（= 项目根），与现有启动脚本 cd 到项目根后的行为完全等价
部署兼容无Docker 和裸机部署均将项目完整复制，conf.ini 始终与 configs.py 同目录
