# RBAC 用户编辑 U3 交互与审计展示验收

日期：2026-10-29 · 状态：**通过** · 范围：`/rbac/users/edit` 与访问审计中的 `user:update` JSON v1

**结论：**U3 已完成，U0–U3 设计闭环全部落地。正常浏览器路径在请求前阻止 no-op；邮箱清空必须经表单型确认并填写理由；各写入 outcome 不再误刷新或误报成功；审计详情只展示经过严格解析的五字段白名单，损坏和未来结构安全降级。

## 1. 实施内容

- 公共 Ajax 提交增加可取消的 `cp:form-before-ajax-submit` 和 opt-in `cp:form-outcome`，只对显式 outcome 留页，不改变其他表单默认跳转。
- 编辑页用与服务端一致的五字段规范化比较原始快照；无变化直接提示且不发 POST。
- 仅“原邮箱非空 → 请求邮箱为空”打开 `CpModal`；理由 trim 后必须为 1–500 字，取消和空理由均不提交；确认字段动态写入前移除同名旧节点。
- 无 JavaScript 的原生 POST 回退保留表单输入、确认标志和理由输入区；NO\_CHANGE、ALREADY\_APPLIED、CONFLICT、COMMIT\_UNKNOWN 经 PRG 返回稳定提示。
- 访问审计严格解析 JSON v1；只渲染 email、nickname、job\_title、role、group\_ids 的 before/after 和邮箱清空理由；不使用 `|safe`。

## 3. 专业评估

**准确性：A。**浏览器比较值与后端规范化字段一致，前端只优化交互，最终安全仍由 U1/U2 服务端契约保证；审计解析器不把数据库 JSON 当可信 HTML。

**专业性：A。**公共 Ajax 扩展采用 opt-in 事件而不是页面特判；输入型确认使用 `CpModal`；原生 POST、无 JavaScript、损坏历史数据均有降级路径。

**合理性：A。**所有比较和 JSON 解析规模均为固定五字段，性能开销可忽略；no-op 减少网络与数据库入口，审计展示不增加查询。

## 4. 交付边界

本验收只声明 `/rbac/users/edit` 的 U0–U3 完成。密码、Token、停用、审批和其他编辑入口继续使用各自既有流程；凭据操作仍记录事件，但凭据值永不进入 detail。
